# 数据读写：动态 CRUD、批量操作与关系事务

状态：Ontology 设计阶段，尚未编码。本文针对对象保存方式给出候选建议，接口、操作类型、批量范围及事务协议尚未冻结。本文统一维护 Data 的实例读写入口、CRUD、批量写入及对象/关系组合提交；DataSet 查询规则独立维护在[数据查询目录](数据查询/README.md)的 [DataSet 文档](数据查询/DataSet.md)，字段与模型规则引用 [Schema](模块/Schema.md)，关系语义引用 [Link](模块/Link.md)，不重复定义。

## 1. 每个 Schema 具备能力，服务共用实现

建议 Schema 生效且物理映射就绪后，Data 按当前定义动态提供可用的实例读写能力。对使用者而言，每个 Schema 都有自己的单条/批量操作契约；后端使用统一路由、类型校验、查询编译和事务设施，不为每个 Schema 生成、编译及部署一套 Controller、Service 或 ORM 类型。用户按中文业务名称选择定义和字段，解析后由内部路由及执行计划按 Schema/字段/实例/Link 稳定 ID 定位。

实例写入与 Schema 草稿保存、模型生效分别处理：创建一台设备不修改设备 Schema，不创建定义 version，也不执行 DDL。新增 Schema 所需的建表和索引仍走模型迁移，普通实例写入只使用已就绪映射。

Metadata 提供当前字段和定义，Data 的候选能力描述返回当前调用者可用的 create/read/patch/delete/query/batch 等能力、限额及不可用原因。它结合生效状态、具体类型、权限、物理源和适配器认证派生；能力发现不能替代每次实际执行的校验。db_2_schema、视图、抽象类或维护中的模型不默认拥有全部 CRUD；反向源是否允许写入需单独授权和验证。客户端可根据描述生成表单、OpenAPI 或 SDK 辅助方法，服务运行不依赖重新生成客户端或服务代码。

## 2. 建议的单条与批量入口

以下为候选 HTTP 形式，schemaId 和 entityId 都是内部 ID，路径不是已实现的服务契约。

| 需求 | 候选入口 | 说明 |
| --- | --- | --- |
| 创建实例 | POST /data/schemas/{schemaId}/instances | 创建一个对象，返回实际具体 Schema ID、实例 ID 及并发凭证 |
| 读取实例 | GET /data/schemas/{schemaId}/instances/{entityId} | 按具体类型和稳定 ID 定位，可选择合法投影 |
| 部分更新 | PATCH /data/schemas/{schemaId}/instances/{entityId} | 只修改显式提交的字段，使用自动并发凭证 |
| 删除实例 | DELETE /data/schemas/{schemaId}/instances/{entityId} | 检查当前关系、组合生命周期及计算依赖，不直接物理删行绕过约束 |
| 查询/批量读取 | POST /data/schemas/{schemaId}/instances/query | 明确的 ID 集合或受控过滤、投影、排序和分页；不能只取第一页就称全部 |
| 同 Schema 批量写入 | POST /data/schemas/{schemaId}/instances/batch | 显式 create、patch 或 delete，复用单条规则，声明事务模式 |
| 对象与关系组合提交 | POST /data/mutations | 有界命令集合，在可覆盖的同一本地事务中提交；约束见第 6 节 |

基本读写以统一 Data 能力提供，业务参数、权限或流程更复杂时使用 [Action](模块/Action.md)。可在具体 Schema 的业务权限策略中限制直接 CRUD，要求特定修改通过 Action；Action 最终写 Data 仍受相同约束，不获得绕过校验的权限。

## 3. 数据查询入口与职责

对象按 ID 读取和 query 入口仍由统一 Data 服务提供；DataSet 的筛选、字段投影、关系导航、多跳执行、聚合、结果分页及预览统一见[数据查询 / DataSet](数据查询/DataSet.md)。查询文档集中于[数据查询目录](数据查询/README.md)，本文件只维护实例读写入口、保存语义、批量写入、对象/关系事务及导入，不重复维护查询协议。

用户也可通过 [OntologySQL](数据查询/OntologySQL.md) 文本入口表达查询，建议编译为同一 QuerySpec；文本入口初期只读，保存仍使用本文的明确写入契约，不从 SELECT 结果或 SQL 文本自动推断更新。

查询结果的修改不会自动保存到数据库；保存仍须显式调用本文的单条/批量 CRUD 或受控关系事务。查询与写入共用当前定义、可信租户和权限校验，但读取结果不授予写入权限。

## 4. 单条保存的明确语义

建议明确区分 create、patch、delete，不将一个通用 save 自动解释为“有 ID 则覆盖、无 ID 则创建”，也不把更新不存在的对象自动变成创建。首批候选不默认开放 PUT 整体覆盖；若后续需要须明确缺失字段的清除语义。upsert 另行作为显式能力，必须指定可靠的业务唯一键并证明并发及分表唯一性，不用先查后写模拟。

候选内部规范写入以 values 的稳定 field ID 为键。表单和 SDK 面向用户使用“设备编码”“设备名称”等中文业务名称，按当前 Schema 的属性 name 解析、绑定后转换为同一契约；不按任意本地化标签猜字段，规则见[组织与隔离](组织与隔离.md)。最终外部编码待确认，以下 ID 正文表示内部保存契约。创建时 ID 由服务端分配，或按已授权源映射取得；tenant_id、系统 ID、计算属性及只读字段不能由普通 values 覆盖。

以下为向设备 Schema 创建对象的候选正文；假设两个字段 ID 分别对应字符串类型的设备编码（已声明唯一约束）和设备名称。接口使用上表的创建路径，schemaId 为设备 Schema 的 ID。

```json
{
  "values": {
    "2d1f0bfa-e317-4cc2-82c3-32410b2c9601": "PUMP-001",
    "6b49c61b-1754-41d2-9d53-2385f72f9602": "输送泵"
  },
  "idempotencyKey": "72cba1f3-4029-4e6e-9f67-281ff7b185c1"
}
```

PATCH 中未提交的字段保持原值，显式 null 只有在字段可空时成立，未知字段、只读字段和非法类型明确拒绝；业务 JSON 字段中的嵌套对象仍是字段值，不被猜成需要级联保存的关联实体。创建时应用默认值，创建与更新均执行当前 Enum/单位/范围等校验；stored_sync 在同事务内维护，virtual 不落值，详细规则统一引用 Schema。

更新、删除建议默认使用自动生成的 ETag/If-Match 或等价条件写凭证，拒绝覆盖别人已提交的修改；该凭证不是业务 version，也不提供按凭证读取旧对象的接口。没有可靠并发校验的外部源不伪造凭证，不能认证的受保护写入明确不可用。创建和重复提交使用租户及调用上下文内的幂等键，相同键同一意图返回原操作结果，不重复创建；同键不同意图拒绝，保留期及响应编码待定。

## 5. 批量操作复用同一套规则

同 Schema 批量写入建议一个入口，operation 指定 create、patch 或 delete；读取用 query 的 ID 集合或过滤。它是批处理执行模式，不维护第二套业务校验。服务端一次解析当前定义及权限结构，批量校验、分表路由、定位和参数绑定，再使用适配器支持的批量 SQL 或有限批次执行，不逐对象调用单条 HTTP 接口。

以下为候选批量创建正文，field ID 与上一示例相同。clientKey 用于逐项对应结果，是本次请求标识，不替代实例 ID。

```json
{
  "operation": "create",
  "atomic": true,
  "items": [
    {
      "clientKey": "pump-1",
      "values": {
        "2d1f0bfa-e317-4cc2-82c3-32410b2c9601": "PUMP-001",
        "6b49c61b-1754-41d2-9d53-2385f72f9602": "输送泵"
      }
    },
    {
      "clientKey": "pump-2",
      "values": {
        "2d1f0bfa-e317-4cc2-82c3-32410b2c9601": "PUMP-002",
        "6b49c61b-1754-41d2-9d53-2385f72f9602": "冷却泵"
      }
    }
  ],
  "idempotencyKey": "71a7259f-b1ec-4eeb-981f-78026c8202c2"
}
```

上述单条和批量正文是相互独立的创建示例；若先创建了 PUMP-001，再提交包含该唯一编码的批量请求，应按真实唯一约束拒绝相应冲突，不能当作覆盖保存。

| 批量规则 | 候选约定 |
| --- | --- |
| 默认事务 | atomic=true；在可覆盖的本地事务内全部成功或全部回滚，不能认证则拒绝，不自动降级成逐条提交 |
| 部分成功 | 可作为后续显式 atomic=false 能力，每项独立事务并返回结果；不能用于同一完整链、组合转移或相互依赖操作，也不能与原子批量共用模糊的成功状态 |
| 更新/删除目标 | 每项携带实例 ID 及所需并发凭证，首批只接受明确 ID，不开放无界按条件批量改删；同批重复修改同一实例须拒绝或另用有明确依赖的事务命令 |
| 返回结果 | 按 clientKey 对应实际实例 ID、状态及错误；原子批量失败时没有任何一项被标为已提交，计算值、关系影响及 outbox 同样回滚 |
| 限额 | 限制对象数、字节数、字段/依赖扇出、分表数、SQL 参数及事务耗时；具体值经后端认证和压测确定，超限不偷偷拆成多次提交 |
| 定义与幂等 | 同一批次用一致的当前定义及映射；提交前仍检查生效协调状态。整批请求具有幂等语义，不能仅以数组序号去重 |

## 6. 对象和 Link 一起保存

仅保存设备属性用实例 CRUD；连接设备与产线、维护前后顺序用关系用例。需要“新建设备并放到产线末尾”时，建议通过有界 mutations 或等价事务命令，一次提交对象创建和受控序列插入，失败一起回滚。成员及单链规则以 [Link 的保存示例](模块/Link.md) 为准，不能先提交新成员再逐条补边。

候选事务命令可包含实例创建/修改/删除、普通关系增删和受控的序列/组合命令。请求内的 operation key 可临时引用同请求新建实例，Data 预分配实际 ID 并解析依赖，校验最终图后保存；临时引用只在本次命令内有效，持久事实仍保存真实 Schema/实例 ID。拒绝模糊循环创建依赖，不能靠嵌套 JSON 自动决定要创建、覆盖或删除哪些对象。

事务只覆盖 Data 已认证的同一本地存储及会话，物理分表也须满足其事务/全局约束条件。跨 Schema 不等于跨数据库：同一可覆盖事务中的多个 Schema 可组合提交，不同数据源/数据库或外部设备控制不自动获得原子性。具体组合没有能力证明时明确拒绝；跨源业务通过任务、幂等及明确补偿另行设计。Metadata 定义替换和 Execution 状态也不加入一个假定的分布式事务。

普通关系 CRUD 同样须维护当前所有引用约束；受控序列/组合命令绑定同一 Data 事务会话，不在事务里再调用多个远程 CRUD 后声称它们原子。可验证的数据写入、stored_sync、定位/唯一登记、边事实和所属 outbox 按同一本地契约提交。并发图约束、全范围编辑权限、幂等及预算沿用 Link；通用实例/关系入口不能绕过受控命令的最终约束。

审批、启停、校准、派工等业务动作用 Action 表达。Action 的多次远程调用不天然原子；需要本地原子数据效果时，应明确调用一次 Data 事务命令；外部副作用按 [执行与调度](执行与调度.md) 声明幂等、核对和补偿。

## 7. 统一执行与大规模导入

单条、批量、事务命令及 Action 最终写入共用 Data 的领域校验和存储契约：可信租户与权限 → 当前 Schema/Link/Enum 及就绪映射 → 类型/单位/只读字段/依赖校验 → 受控事务中的并发及真实约束 → 数据、同步计算、定位/关系、outbox 提交。纯预检查不代替提交时校验，直接 SQL 和批量路径也不能绕过此流程。

大规模导入建议独立任务入口，先校验格式和映射，再按受控分块执行并保存进度、逐项错误及幂等信息；任务状态遵循执行设施契约。分块导入明确可能部分完成，不把整文件描述为一个数据库事务；每块执行同一批量规则，暂停、重试、取消及错误修正行为需可追踪。

导入使用的目标字段和映射发生变化时，不能让后续分块继续使用旧规则。首批候选采用受影响任务暂停，结合 [定义生效与迁移](发布与迁移.md) 处理已提交数据，并按当前定义重校验未处理内容后恢复；不兼容变更仍须排空受影响运行操作。性能测量比较批量 SQL、循环写入及单条基线，但不牺牲原子性、权限、计算或事件正确性。

## 8. 验收与待定事项

以下为候选范围的未来验收；当前仅验证文档和示例。

| 编号 | 要求 | 验收方法 |
| --- | --- | --- |
| DATA-01 | Schema 生效后动态获得已认证的单条/批量契约 | 新增及修改 Schema 无需新增服务代码或重启生成 CRUD；改名不变调用 ID，抽象/只读/维护中及未授权能力不暴露为可写 |
| DATA-02 | 单条创建、PATCH、删除语义及并发幂等明确 | 区分缺失/null/只读/未知字段；更新不存在不创建，拒绝覆盖派生值；重复请求不重复创建，旧凭证不能覆盖新修改；删除维护关系及依赖 |
| DATA-03 | 批量复用单条规则并按声明事务提交 | 唯一冲突、计算失败及跨表回滚可核对；原子失败无已提交项或残留事件；逐项结果可对应，重复目标/超限拒绝，不能认证的原子范围不降级 |
| DATA-05 | 对象与关系事务保持最终图及本地原子性 | 新建设备并加入完整序列一并提交，注入失败无孤立新对象或半链；临时引用持久化为实际 ID，反向无重复事实；跨源和未知事务能力明确拒绝 |
| DATA-06 | 大规模导入可分块追踪和恢复 | 中断重放不重复写，已提交块与失败项可核对；取消不假报整文件回滚，定义变化暂停重校验，不使用旧映射继续写 |
| DATA-07 | 所有写入口遵循当前态、业务权限及能力边界 | CRUD、批量、mutations、Action 和直接 SQL 使用相同约束；Action 不能绕过禁止的修改，外部源无可靠校验不伪造并发保证；不兼容定义切换遵守暂停/排空 |

查询相关 DATA-04、DATA-08～DATA-12 统一在 [DataSet](数据查询/DataSet.md) 定义。
