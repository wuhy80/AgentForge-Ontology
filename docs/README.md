# 项目文档

按模块和公共主题组织，每个主题只维护一份说明，将功能、业务规则、数据结构、接口、实现取舍和验收放在一起。适用于单人开发，也便于把一个模块的上下文提供给模型。

当前仓库已有首批Metadata、Data、公共协议、MySQL存储及中文前端工作台，并已补齐本地账号密码、用户/用户组/角色管理、权限策略草稿/模拟/生效及管理审计；另有 [Link](模块/Link.md#当前关系数据库实现2026-11-07) 的物理映射与同库单跳查询，以及[OntologySQL](数据查询/OntologySQL.md#首批实际协议2026-11-07)单Schema文本、参数、补全及SQL/可视化工作台。当前交付范围及验证结果统一见[项目总览](项目总览.md#当前实现与验证2026-11-06)，启动、测试及实际协议入口见[开发指南](开发指南.md)。尚无性能验收结果；下文的完整设计示例与候选扩展不代表均已实现。

Schema、Enum、Link、Action、Function 统一只维护当前生效定义，引用仅保存稳定 ID，不设置业务 version。草稿、生效、迁移及执行期间的一致性规则集中见 [定义生效与数据库迁移](发布与迁移.md)。

新增能力先修改所属模块文档，在同一处说明做什么、怎样实现及怎样验收；公共机制只引用对应专题。重要取舍及理由写在所属文档，暂不为每次修改另建流程文档。

权限设计、引擎调研、选型依据和验证资料统一存放在 `权限/`，公共权限机制只在[权限设计](权限/权限设计.md)维护，各模块通过引用说明执行边界。

建议各模块包含：用途与边界、数据结构/示例、业务规则、接口与实现、变更生效和依赖、验收与待定事项。内容简单时可以合并章节，避免为套模板扩写。

OntologySQL 的文本语法、编译及补全协议验收 OSQL-01～OSQL-09 唯一维护在 [OntologySQL](数据查询/OntologySQL.md)；DataSet 继续负责各入口共用的查询语义和执行规则，不重复维护另一套查询引擎。

SQL/可视化交互、使用指导、编辑状态和体验验收的 VQE-01～VQE-11 唯一维护在[可视化查询编辑器](数据查询/可视化查询编辑器.md)；查询、权限和文本语义继续引用各自来源，编辑器不重复维护执行规则。

保留已有 CORE、SEM、PUB、RUN、TRG、MOD、SCALE、PERF、DOC 检查编号，并用 DB 编号追踪数据库适配、ORG 编号追踪组织、中文命名与隔离、SCHEMA 编号追踪类型继承、建模方向、分表、计算属性、索引及预览、LINK 编号追踪关系语义、自动反向关系、双向查询及子类型端点、DATA 编号追踪 DataSet 中文编写/查询/多跳、实例 CRUD、批量、对象/关系事务及导入。查询相关 DATA-04、DATA-08～DATA-12 在独立的 [DataSet](数据查询/DataSet.md) 文档定义，其余 DATA 编号在[数据读写](数据读写.md)定义，每条只保留一个来源。新增 AUTH-01～AUTH-14 仅在[权限设计](权限/权限设计.md)定义，追踪行列、调用、执行身份、管理与撤权候选。编号不是第二套说明；开发和测试直接引用相关模块章节即可。候选性能数值只在性能与容量文档维护。
