## 组织约定

```text
docs/
  README.md
  需求文档/                 # 需要什么、约束是什么、怎样验收
  设计文档/                 # 怎样实现、方案取舍和接口设计
  术语表.md                 # 公共工程术语
  industrial-agent-ontology-plan.md
```

元数据与发布、数据与查询、执行与调度已建立设计草案，后续在各自文档中细化接口与流程，并补充部署与容量、工程与发布设计。发生关键选型时，再在 `设计文档/决策记录/` 增加短文，记录背景、备选方案、结论和代价。实际开展验证后，再建立 `测试与验收/` 保存报告；有部署步骤时再建立 `运维文档/`。

功能需求使用 `CORE-*`（建模与查询）、`PUB-*`（发布与迁移）、`RUN-*`（执行）、`TRG-*`（触发）编号；工程需求使用 `MOD-*`、`SCALE-*`、`PERF-*`、`DOC-*` 编号。设计和验收报告引用这些编号。修改需求时同步调整受影响的设计与验收条件，避免同一条指标在多份文档分别维护。

当前明确的项目目标见需求总览；细化条款是满足这些目标的草案，具体技术方案及性能数值以文档标注的状态为准。基础业务语义在对应需求文档维护，实现方式及选型在对应设计文档维护。相同主题发生冲突时，以需求文档中的目标和范围为准；设计草案不能自行扩大需求。工业规划中的模块化单体、数据库选型、性能数值和排期不构成当前基础引擎的承诺。
