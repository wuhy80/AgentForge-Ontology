# 数据与查询设计

状态：设计草案，数据库与存储模型尚未选定。对应 [CORE-01～05](../需求文档/本体建模与查询需求.md)、[MOD-04/05](../需求文档/模块化与演进需求.md) 和 [PERF-01～05](../需求文档/性能与容量需求.md)。

## 1. 数据所有权与类型映射

Metadata 管理 Schema、Enum 和 Link 定义；Data 管理实例、关系、查询编译及数据库适配。请求固定发布版本并读取相应定义，不在逐条记录或逐跳查询中重复回源 Metadata。具体服务边界见 [总体架构设计](总体架构设计.md)。

建议先定义数据库无关的逻辑类型，再由适配器映射为物理类型。

| 类型组 | 建议逻辑类型 | 设计要点 |
| --- | --- | --- |
| 文本 | string、text | 长度、字符集和排序规则 |
| 整数 | int16、int32、int64 | 范围及有无符号能力差异 |
| 数值 | float32、float64、decimal | 精确值使用 decimal，定义精度与小数位 |
| 布尔 | boolean | 区分 false、null 和字段缺失 |
| 时间 | date、time、datetime、timestamp | 时区、精度和时间点语义 |
| 标识与二进制 | uuid、binary | 数据库支持程度与编码 |
| 结构化值 | json | 校验方式及可查询范围 |
| 约束值 | enum 引用 | 值的稳定标识及变更兼容性 |

每个适配器声明原生支持、转换支持或不支持，数据库版本也是能力判断的一部分。数组、空间及专有类型通过能力声明扩展。HTTP/JSON 的 int64、decimal、时间、二进制编码仍需在接口契约中确定，并验证往返无损；不能依赖客户端默认数字或日期解析保持精度。

Enum 建议存储稳定值编码，显示名称独立维护，是否采用原生 ENUM 需结合迁移能力评估。Schema 的物理映射候选为独立业务表、统一实例表或混合存储；尚未选定，不能假设每次定义变更都执行 DDL。结构与数据变更流程见 [元数据与发布设计](元数据与发布设计.md)。

## 2. 关系事实与查询

建议用一份关系定义和一个权威关系事实表示关联。反向查询从目标端访问同一事实，不默认复制一条需要独立维护的反向关系；可按读访问建立两端索引。关系存储遵循端点、基数、重复边及删除规则，具体约束方式依物理模型确定。

Data 负责将固定版本的 Link 路径、方向和逐层过滤编译成受控执行计划，定义去重、分页和结果形式。优先过滤和投影，使用批量读取或数据库关联，避免逐实体调用形成 N+1 请求。执行计划有跳数、扫描量、分支、结果数和时间预算，超预算返回明确错误。

| 主要查询形态 | 优先评估方案 |
| --- | --- |
| 双向关联、固定少量跳数、选择性较强的过滤 | 关系表、双向访问索引、JOIN 或 EXISTS |
| 高频跨源关系、重复出现的复杂路径 | 应用层批量关联、集中关系索引、物化或预计算 |
| 不定长路径、可达性、最短路径、图算法 | 图数据库或专门图计算能力，先确认是否在范围内 |

需要关系查询语义不意味着必须采用图数据库。关系数据库性能取决于数据量、分支度、索引、过滤位置、统计信息和执行计划；图数据库也受路径膨胀影响。固定路径或少于四跳不能证明某种引擎性能最优。

## 3. 数据库候选与限制

首期采用一种关系数据库是合理候选，具体产品尚未确定。如部署必须支持 MySQL 或达梦，需要验证明确版本的类型、事务、索引、查询与 DDL 能力。

- MySQL 5.7 缺少递归 CTE，但可执行固定层级 JOIN 或 EXISTS；兼容某种固定路径查询不等于支持不定长遍历。
- 跨数据源路径通常需要应用层批量关联或集中关系索引，不能假设一条 SQL 可以完成跨源访问。
- EdgeDB（现名 Gel）是基于 PostgreSQL 的对象关系数据库，不能简化为 ORM 封装，其 Link 语义也不是遍历性能最优的证明。
- Neo4j 是属性图数据库，ArangoDB 是多模型数据库，Apache AGE 是 PostgreSQL 图扩展，应按能力和实际负载分别评估。

图库可作为特定负载的存储方案或后续加速层。引入前必须评估同步延迟、索引重建、权限过滤及故障回退成本，并确定权威数据来源。缓存、物化、读副本和图索引的引入均需要实测依据。

## 4. 验证与待定事项

首先验证字段精度、非空、Enum 约束和正反向多对多查询正确性，再按 [性能与容量需求](../需求文档/性能与容量需求.md) 测量普通/热点关系、不同过滤选择性和多跳路径。报告扫描量、执行计划、连接等待、锁和 IO，不能仅报告平均延迟。

详细设计仍需确定物理存储模型、第一种数据库及版本、类型映射表、查询协议、身份隔离、索引规则、固定/不定长路径范围、每层去重与分页语义、跨源能力以及默认查询预算。本文保留候选方案，尚未给出最终表结构或 SQL 编译接口。
