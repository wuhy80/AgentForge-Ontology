# DataSet：数据查询、关系导航与多跳执行

状态：Ontology 设计阶段，尚未编码。数据查询文档集中放在本目录，本文为 DataSet 查询规则的唯一主要说明；查询抽象、HTTP/SDK 协议、开放范围及数据库能力仍为候选，尚无实测性能结果。本文维护查询构造、筛选/投影、关系导航、多跳计划、结果模式、分页、预览及查询验收；实例写入见[数据读写](../数据读写.md)，字段/单位规则见 [Schema](../模块/Schema.md)，关系语义见 [Link](../模块/Link.md)，测量方法见[性能与容量](../性能与容量.md)。

## 1. DataSet 的定位

如果 DataSet 指“一个可以继续筛选、关联、投影和统计的逻辑数据集合”，建议采用这种使用方式。DataSet 保存查询意图，构造时不读取全部实例；调用 execute 或请求下一页时，由 Data 按当前定义、权限和映射编译并执行。这里不采用将整库表装进客户端内存、离线修改后统一回写的默认语义。

| 概念 | 候选职责 |
| --- | --- |
| Schema | 定义对象有哪些字段、类型、约束和物理映射；不是某次查询结果 |
| DataSet | 面向使用者的查询对象，可从一个 Schema 或一个带类型的实例起点构造，继续组合查询条件；普通临时查询无需保存或分配业务 ID |
| QuerySpec | DataSet 对应的结构化查询描述，包含稳定 Schema/字段/Link ID、参数、方向、结果模式及分页等；SDK 和 HTTP 共用同一语义 |
| ResultSet | 一次实际执行返回的有界数据页、字段描述和翻页信息；对象投影、边、路径和聚合结果有明确区别 |

SDK 可提供链式写法，界面可提供可视化配置，HTTP 提交结构化 JSON；它们最终使用同一套查询编译及权限规则。DataSet 是新增的查询使用方式候选，不自动增加第六类必建的 Ontology 定义，不要求先保存一个 DataSet 才能查询对象。

从 Schema 构造时默认查询精确类型；显式 includeSubtypes 才扩展到合法具体子类型，沿用 Schema 的类型、权限及全局结果规则，不因统一 DataSet 自动查询全部继承族。

## 2. 可以怎样查询

| 形态 | 候选能力与例子 |
| --- | --- |
| 按 ID | 读取一台设备，或用明确的 ID 集合批量读取；结果按实际 Schema/实例 ID 对应，不把返回数组位置当作身份 |
| 条件筛选 | 类型化等值、比较、范围、集合、空值及经认证的文本操作，支持 AND/OR/NOT；例如额定电压大于 220 V 的设备 |
| 字段投影和排序 | 只返回编码、名称和需要的计算属性，按合法字段排序并稳定分页；字段访问权限同时约束筛选和排序 |
| 关联筛选 | 通过 Link 的 out/in 判断是否存在满足条件的关联对象；例如筛选属于产线 L1 的设备，默认每个设备只返回一次 |
| 关系导航 | 从具体产线沿成员 Link 的 out 查设备；从设备沿直接后继 Link 的 in 查上一台，携带产线上下文；多跳复用逐层方向和过滤 |
| 关联展开 | 在设备结果中附带其所属产线等授权字段；多值展开须有每个父对象的数量及分页上限，不默认递归展开全部关系 |
| 分组与聚合 | 按合法字段分组，执行经类型/单位校验的 count、countDistinct、sum、avg、min、max 等；例如按设备状态统计数量，不默认求所有数值字段之和 |

关系定义、方向、上下文、整线设备及前驱的请求示例统一引用 [Link 的查询示例](../模块/Link.md)。DataSet 的关系导航沿用其 start/path 结构或编译成等价受控计划，不另造一套相反的方向含义；out/in 本身不保证产线顺序。完整序列读取、祖先/后代和任意长度遍历仍须单独认证，不能因有 DataSet 就开放无限遍历。

关联筛选与关联展开分别声明：前者默认按“存在匹配”判断根对象，不能因一台设备有三个匹配工单而返回三台设备；后者保留根对象一行并附带有界子结果。若确需明细行展开，必须显式选择扁平结果并区分对象、边或路径身份，不能在实体结果中悄悄改变行数。count 也要区分设备数、关系数和展开行数，聚合先在授权的完整逻辑集合上计算，再对聚合结果排序分页；多跳及 N:M 不得无意重复累计数值。按多值关系分组时，须显式说明实体是否在每个匹配组各计一次，不推断互斥分组。

过滤表达式按字段类型解析参数，明确 null/缺失与否定条件的语义；非法操作符、未知字段和无权限的筛选/排序/聚合明确拒绝。单位归一化和计算属性过滤遵循 Schema；不同后端未认证的比较、文本检索或聚合不伪装成等价能力。全文、向量、GIS、任意 SQL 和任意 Function 执行不因通用查询而默认开放。

## 3. 单 Schema 查询示例

以下是候选请求正文，用于 `POST /data/schemas/{schemaId}/instances/query`；schemaId 为设备 Schema 的稳定 ID。字段 ID 与[对象保存示例](../数据读写.md)相同，分别表示设备编码和名称。本例查询编码以 PUMP- 开头的设备；page.limit=50 仅为示意，实际限额经认证确定。

```json
{
  "where": {
    "op": "startsWith",
    "fieldId": "2d1f0bfa-e317-4cc2-82c3-32410b2c9601",
    "value": "PUMP-"
  },
  "select": [
    {"fieldId": "2d1f0bfa-e317-4cc2-82c3-32410b2c9601"},
    {"fieldId": "6b49c61b-1754-41d2-9d53-2385f72f9602"}
  ],
  "orderBy": [
    {"fieldId": "2d1f0bfa-e317-4cc2-82c3-32410b2c9601", "direction": "asc"}
  ],
  "page": {"limit": 50},
  "includeMetadata": "fields"
}
```

startsWith 按已认证的字符比较及字面前缀语义执行，参数中的通配字符不能被当成 SQL 模式注入；是否利用索引以实际执行计划为准。上例也可以由下列 SDK 风格伪代码表达；所有大写常量保存稳定内部 ID，方法名仅用于说明候选使用方式，并非已有 SDK。

```text
DataSet.fromSchema(EQUIPMENT_SCHEMA_ID)
  .where(startsWith(EQUIPMENT_CODE_FIELD_ID, "PUMP-"))
  .select([EQUIPMENT_CODE_FIELD_ID, EQUIPMENT_NAME_FIELD_ID])
  .orderBy(EQUIPMENT_CODE_FIELD_ID, "asc")
  .page({limit: 50})
  .execute()
```

where、select 等构造操作只形成新查询描述，execute 才发起执行；继续从已有 DataSet 构造派生查询不应偷偷改动原查询。后续页使用服务端返回的游标和同一条件，不以当前页数组继续筛选后冒充全局查询。DataSet 查询结果只读，需要保存时仍显式使用单条/批量 CRUD 或受控关系事务，不提供含糊的“将当前 DataSet 全部回写”。

## 4. 多个 Link 怎样连续查询

多跳查询一次提交完整的路径及每层约束，由 Data 编译。以下候选示例表示“查询某工单使用的设备所参与产线上的设备”，复用 Link 文档中的工单使用设备与产线成员 ID：工单 → 使用设备 out → 设备 → 产线成员 in → 产线 → 产线成员 out → 设备。成员关系可能多对多，结果选择终点实体并按实际身份去重，不表示产线的工艺顺序。

```json
{
  "start": {
    "schemaRef": {"id": "f5e1bc42-9e6b-4e43-8dc3-230b53da2a83"},
    "entityId": "97e56d83-b843-4efa-aaf1-19909ebd2891"
  },
  "path": [
    {
      "linkRef": {"id": "d0a3bbd7-c351-4e78-bbb6-7ec48736c386"},
      "direction": "out"
    },
    {
      "linkRef": {"id": "23dbd0a1-c628-4ca0-a504-64504c088332"},
      "direction": "in"
    },
    {
      "linkRef": {"id": "23dbd0a1-c628-4ca0-a504-64504c088332"},
      "direction": "out"
    }
  ],
  "return": "entities",
  "page": {"limit": 50}
}
```

关系查询的最终 HTTP 路由仍待冻结，以上沿用 Link 的候选请求结构。多跳可在每层声明端点/关系过滤、上下文和合法投影，受类型连接及权限检查；返回终点实体、边或完整路径须明确，不能把分页后的某层中间结果当作完整输入再继续查询。

| 执行位置 | 候选执行方式与边界 |
| --- | --- |
| 同一数据库、可关联的受管表 | 优先将固定路径编译为 JOIN、EXISTS 或半连接等受控 SQL，减少网络往返；由结果模式及经验证的实际计划选择，不要求每个 Link 都单独发请求 |
| 同库分表或继承展开 | 每层按可信映射裁剪成员、使用可覆盖的 SQL 或有界批量计划，并保持全局身份/去重/分页；不能把多表查询当成单表等价成本 |
| 跨数据源且已认证组合 | 有界分阶段批量取键和关联，按源/成员分组、去重并限制参数和中间结果；不能逐对象远程调用，也不能假定单 SQL 或统一读取快照 |
| 未认证跨源或不定长遍历 | 明确拒绝或作为后续任务能力设计，不自动递归、广播所有源或返回不完整成功 |

优化可在不改变路径、每层条件、上下文、权限及结果模式的前提下选择有选择性的驱动集合和 JOIN 顺序；不能为提速忽略中间约束或提前截断候选。Link 正反访问索引由 Link 文档维护，实体筛选/排序字段的索引由 Schema 维护；DataSet 不产生另一套可独立编辑的反向事实或索引定义。

性能取决于实际扫描/匹配边数、中间结果、排序/聚合及网络等成本，不能仅按 Link 数量判断。查询须受路径深度、中间候选/匹配行数、成员数、响应字节、内存及耗时预算约束；page.limit 只限制最终页大小，不能保证只处理相同数量的中间行。超过预算应拒绝或明确失败；若后续支持部分结果，须单独声明完成状态及恢复协议，不能冒充完整成功。性能工作负载、扇出示例及度量方法统一见 [性能与容量](../性能与容量.md) 第 9 节，当前没有实测延迟或吞吐。

## 5. 结果、执行及复用

候选结果至少区分实际结果模式、数据页和 page.nextCursor/hasMore；对象结果保留稳定实例身份，跨类型时逐行保留具体 Schema ID，聚合结果不伪装成可更新的实例。字段类型、标签、Enum 及单位描述按 [Schema 的自描述结果](../模块/Schema.md) 返回并与实际输出匹配；编码可沿用其中的 data/fields 候选，不在这里重复冻结另一套响应格式。总数建议按需计算，明确为当前权限和筛选下、分页前的精确匹配数；未计算不能用本页长度或估算值冒充精确总数。数据页与精确总数若承诺对应同一状态，须使用经认证的一致快照，否则说明差异或拒绝该组合。

执行顺序建议为：验证可信租户及当前查询权限 → 解析当前 Schema/Link/字段/单位和参数 → 校验查询结构及预算 → 选择成员、索引和 SQL/批量关联计划 → 在声明的读取一致性内执行 → 返回有界结果和游标。过滤、聚合及必要计算先于分页；纯展示计算可按 Schema 规则在正确分页后执行。多值展开可批量读取，不能每行再发一次远程请求。

分表对使用者保持一个逻辑集合，裁剪、全局排序/聚合及稳定决胜键复用 Schema 规则；单次查询的多条 SQL 不天然共享快照。默认每次新执行按当前已提交数据及已声明的数据源读取一致性返回，不提供历史定义 version，也不将 DataSet 视为自动更新的实时订阅。游标绑定当前定义/映射、权限、条件和排序等上下文，相关内容改变时失效；跨请求数据增删的可见性按分页契约声明，不因有游标就保证整个翻页过程持有历史快照。

频繁复用的查询可后续增加“保存查询/DataSet 模板”：保存参数声明、查询描述和展示配置，引用稳定 ID，每次执行重新检查当前定义、权限及参数。它保存的是规则，不默认保存结果副本，也不让定义或权限变更后继续使用旧规则；预览应显示失效依赖。是否将模板持久化、如何组织命名及授权、是否需要发布草稿仍待用户确认，不直接套用五类定义的分类名称登记。缓存、物化结果和定时报表另外声明刷新及新鲜度契约，不与临时 DataSet 混为一体。

## 6. 查询预览与范围

建议提供只读查询预览，返回字段/单位检查、关系路径、预计访问成员、执行预算及可用的厂商 SQL/EXPLAIN 计划；无可用估计时明确未知。预览受相同权限限制，不默认执行 EXPLAIN ANALYZE、读取业务样例或运行全量 COUNT；读取样例须独立授权并限制行数和耗时。它与 Schema 的结构/DDL 预览分别处理。实际执行仍重新校验当前状态，预览不保证以后任意数据规模都能快速执行。

首批候选先覆盖按 ID/集合读取、类型化筛选、投影、排序分页、现有固定路径和关系存在性筛选；经后端认证再开放有限关联展开及基本聚合。持久模板、物化、实时订阅、无界遍历及大规模跨源分析另行确认。接口字段名、操作符清单、结果模式和游标编码尚未冻结。

## 7. 验收与待定事项

以下为候选范围的未来验收，当前只检查文档与示例。为保留已有引用，查询相关 DATA 编号迁入本文并保持原编号；写入、事务和导入的 DATA 编号继续由[数据读写](../数据读写.md)维护，每条仅定义一次。

| 编号 | 要求 | 验收方法 |
| --- | --- | --- |
| DATA-04 | 批量读取和查询遵循逻辑全集及权限 | ID 集合按类型/租户定位，分页、字段投影、排序及计算正确，不逐对象发 HTTP；全部与当前页明确区分，越权字段/实例不泄露 |
| DATA-08 | DataSet 延迟执行且共用类型化查询契约 | SDK/JSON 相同描述得到同语义结果，构造条件不读取全集，派生查询不改变原对象；ID 引用不因改名失效，非法操作符/类型及越权字段拒绝；修改结果不能隐式回写 |
| DATA-09 | 关系筛选、展开及聚合的计数和身份明确 | N:M 筛选不重复根实体，嵌套展开有逐父分页且无 N+1；显式扁平结果区分边/路径；聚合不因 JOIN 重复累计，按多值关系分组语义可核对，前后查询不丢上下文 |
| DATA-10 | 分页、结果描述及预览遵循当前态与读取契约 | 全局排序/聚合/计算筛选先于分页，字段描述匹配输出，精确总数不以当前页代替；同快照声明逐库验证，定义/权限/映射变化使旧游标失效；预览不默认执行 ANALYZE 或业务扫描，超预算明确结束 |
| DATA-11 | 多跳按完整计划执行且限制中间成本 | 同库候选使用受控 SQL/批量计划而非逐实体远程访问；同库/分表/跨源分别验证结果及读取契约，优化不忽略层级过滤、上下文、权限及去重；小结果页遇高扇出仍有扫描/内存/时间上限，超限不返回完整成功 |

待定：DataSet/QuerySpec 的最终协议、操作符及查询结果模式、关联展开/聚合首批范围、分页一致性及精确总数成本、查询预览、持久模板需求、多跳预算与三库/跨源能力认证。本文是设计说明，不创建查询源码、SDK 或持久化 DataSet 配置。
