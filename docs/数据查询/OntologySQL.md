# OntologySQL：中文本体查询语言与统一查询计划

状态：用户于2026-11-07确认按工作台方案开发。首批范围为单 Schema 只读文本、类型化参数、授权目录、诊断、补全和格式化，编译到现有 QuerySpec；本节首批语法按确认方案实施，后文 JOIN、聚合及关系文本继续是后续候选。实现与验证结果统一见[项目总览](../项目总览.md#当前实现与验证2026-11-06)。本文只维护文本语法、编译与诊断；页面、引导和补全交互见[查询工作台设计增量](可视化查询编辑器.md#ontologysql-工作台设计增量2026-11-07候选)，公共查询语义和执行边界唯一见 [DataSet](DataSet.md)，名称与身份规则见[组织与隔离](../组织与隔离.md)。

## 1. 方案选择

用户可以直接提交 OntologySQL 文本，客户端无需先构造 DataSet。内部建议采用以下路线，其中 DataSet/QuerySpec 表示延迟执行的查询描述，不是已经读取到内存的数据集。

```mermaid
flowchart LR
    SQL[OntologySQL 中文查询] --> PARSE[解析为语法树]
    PARSE --> BIND[名称和类型绑定]
    BIND --> PLAN[DataSet 共用的 QuerySpec]
    SDK[DataSet SDK / JSON / 可视化查询] --> PLAN
    PLAN --> CHECK[统一权限和能力校验及优化]
    CHECK --> EXEC[数据库 SQL / 受控批量执行]
    EXEC --> RESULT[统一结果与分页]
```

| 路线 | 收益与成本 | 当前建议 |
| --- | --- | --- |
| OntologySQL → DataSet 共用 QuerySpec → 存储计划 | 复用中文名称、类型/单位、Link、权限、计算属性、分表、分页及缓存规则；增加文本解析与语法映射 | 推荐，共用一个逻辑计划和执行引擎 |
| OntologySQL → 独立的物理 SQL 编译器 | 初期可直接处理简单查询；需要再次维护关系、隔离、映射、分表及多后端规则，两个入口容易产生不同结果 | 不单独建设；若最后仍复用同一逻辑计划与优化器，实际上属于上一条路线 |

“编译到 DataSet”是将整条查询降低为同一份结构化逻辑计划，不是把 SQL 翻译成 SDK 代码后执行，也不是每解析一个 JOIN 就发起一次数据库请求。同库适合下推的查询仍可生成一条完整 SQL；分表和跨源执行方式复用 DataSet。OntologySQL 无法表达或 QuerySpec 尚未支持的语义应明确拒绝，不能丢弃条件或将原文透传数据库。

DataSet SDK、JSON、OntologySQL 和可视化配置是不同的编写入口，统一能力以 QuerySpec 可精确表示且后端已认证为前提。不要求各入口立即具备完全相同的表达范围；SQL 新增 JOIN、聚合或表达式前，先明确共享计划中的结果模式、类型及操作语义，不能借 SQL 单独开放另一套执行行为。

[可视化查询编辑器](可视化查询编辑器.md) 直接构造相同的结构化描述，等价 SQL 展示及导入作为候选互通能力。转换只在双方都能无损表示的子集内进行；不能将实体身份去重、嵌套展开或作用域条件简化后宣称等价。无法转换的查询保留原稿或文本模式，具体交互和单一执行来源规则由编辑器文档维护。

## 2. 中文标识符与参数

建议保留熟悉的 SELECT、FROM、WHERE、ORDER BY 等英文关键字，业务 Schema、属性、Link 和输出别名使用中文。关键字大小写不敏感，业务名称的归一和唯一性沿用组织文档，不采用数据库对标识符的默认折叠规则。

| 内容 | 候选规则 |
| --- | --- |
| Schema | `"生产管理"."设备"` 表示业务分类与 Schema；分类不是物理数据库 schema，租户来自可信请求上下文 |
| 属性 | `"设备"."额定电压"` 表示已声明别名上的中文字段；解析到有效 field ID，不使用英文技术键或物理列名猜测 |
| 引号 | 双引号包围一个标识符，内部双引号以两个双引号转义；单引号表示文本值。中文标识符是否允许省略双引号待语法冻结，本文统一使用双引号 |
| 点号与别名 | 点号只分隔语法节点；`"设备.扩展"` 是一个完整名称。别名只在当前查询作用域内有效，重复或歧义须报错 |
| 分类 | 可在可信请求中声明 defaultCategory，确定后允许写 `FROM "设备"`；未限定且不能唯一定位时拒绝，不跨分类取第一项 |
| 参数 | `:最低电压` 等命名参数通过独立 parameters 提供值，按目标类型和规范单位绑定；文本值不通过拼接写入查询 |
| Enum | 中文取值标签按确定字段的 Enum 唯一解析为 code，绑定后使用稳定 code 比较；普通字符串不因此被当成枚举 |
| 实例与上下文 | 以有类型的真实实例身份或显式唯一业务键定位，不将“产线一”等实例显示名当作唯一 ID |

参数只能提供数值、文本、时间、集合或有类型对象引用等声明的值，不能替换 Schema、字段、Link、排序方向或任意 SQL 片段。decimal、日期、空值和计量值使用与 DataSet 相同的类型化编码，不为了 SQL 文本入口丢失精度或单位。

以下示例都是候选 OntologySQL，不能直接作为 MySQL、PostgreSQL 或达梦 SQL 执行。假设“生产管理”中已定义设备、产线、工单及文中字段；设备编码和产线编码分别是对应具体 Schema 内经认证的唯一业务键，额定电压的规范单位为 V。

## 3. 基本查询与编译对应

查询额定电压超过给定阈值的设备，调用时提供最低电压参数，结果列仍使用中文。

```sql
SELECT "设备"."设备编码", "设备"."设备名称"
FROM "生产管理"."设备" AS "设备"
WHERE "设备"."额定电压" > :最低电压
ORDER BY "设备"."设备编码" ASC
LIMIT 50;
```

| OntologySQL 部分 | 降低到共享查询描述 |
| --- | --- |
| FROM 分类.Schema | 当前租户内的 category ID、Schema ID 和精确类型范围 |
| SELECT 中文字段 | 稳定 field ID 投影及中文输出描述，保留源别名映射 |
| WHERE 比较及参数 | 有类型的比较节点、字段 ID、参数声明及规范单位，参数值逐次绑定 |
| ORDER BY | 合法字段排序及结果模式所需的稳定决胜键 |
| LIMIT | 最终结果页上限，仍受服务端限额；不限制数据库或多跳中间扫描量 |

建议首批支持单条只读 SELECT、显式字段投影、参数化比较、AND/OR/NOT、IS NULL/IS NOT NULL、有限 IN 集合、排序和有界分页。经认证后再开放 DISTINCT、固定 Link 导航、受限 EXISTS、聚合及 HAVING；文本比较、LIKE 和算术按类型及后端能力逐项开放。SELECT *、任意子查询、普通任意键 JOIN、UNION、窗口函数、递归 CTE 及不定长遍历不自动进入首批范围。

计算属性可以按中文字段名选择和筛选，实际使用 virtual、stored_sync 或 stored_async 规则仍由 [Schema](../模块/Schema.md) 决定。WHERE 中使用计算值时按完整逻辑集合计算后筛选，不能先 LIMIT 再计算。SQL 中的函数初期仅允许查询引擎明确支持的无副作用操作和聚合，不将同名 Function 定义当作数据库函数或逐行远程调用入口。

### 工作台首批语法候选（2026-11-07）

当前 [QuerySpec](../../contracts/model.go) 能表达单 Schema 实体查询和固定实例起点的 `via`，尚无扁平 JOIN、输出表达式或聚合节点。用户已确认第一阶段实施下表，使相同条件的 SQL 与现有可视化查询可精确对照；实际 HTTP 类型以 [contracts/ontology_sql.go](../../contracts/ontology_sql.go) 为准。本节标题保留设计期锚点，避免已有引用失效。

| 文本形态 | 第一阶段候选规则与对应能力 |
| --- | --- |
| `SELECT` | 仅显式属性列表，按源码顺序绑定为 `select` 中的稳定字段ID；重复投影拒绝。不支持星号、列输出 `AS` 别名、常量列、算术或任意函数表达式，结果沿用原属性描述与实例身份 |
| `FROM` | 一个已生效 Schema；允许 `"分类"."对象"` 或当前分类内的 `"对象"`，可用 `AS "别名"`。Schema 别名仅用于绑定，降低后不新增结果模式；无别名时可用对象名限定属性 |
| 中文名称 | 首批业务标识符统一双引号，字符串使用单引号；引号内同类引号双写转义。补全和模板自动加引号，点号只在引号外分隔；只归一标识符，不改写字面值 |
| `WHERE` | 属性与有类型的字面值/命名参数比较，`= <> != < <= > >=`、括号及 `AND / OR / NOT`，沿用当前运算符和三值逻辑；不接受字段对字段比较 |
| 空值和集合 | `IS NULL / IS NOT NULL`、有限 `IN / NOT IN`。首批集合是括号中的字面值/标量参数列表；不隐式把一个数组参数展开为多个值。`= NULL` 明确报错并提示空值语法 |
| 字面前缀 | `STARTS_WITH(属性, 值或参数)` 精确降低为 `startsWith`，仅用于当前支持的文本类型，`%`、`_` 等仍为普通字符。该内建谓词不是业务 Function 调用；首批不开放任意 `LIKE`、包含检索或全文检索 |
| `ORDER BY` | 至多一个可排序属性及 `ASC / DESC`；未声明时按现有稳定实例ID排序，声明后仍以实例ID决胜。`text / longtext` 不可排序，跨表/跨源属性沿现有主表限制 |
| `LIMIT` | 整数字面量1至100，表示每页条数；省略时建议25并在界面提示。SQL模式不再叠加一份独立页大小配置，不支持 `OFFSET` 或厂商 `LIMIT offset,count` |
| 语句边界 | 仅一条只读查询，可选末尾分号，支持常规行注释及非嵌套块注释。注释/字符串中的分号不能被当作语句分隔符；不接受第二条语句或未消费尾部文本 |

未通过共享引擎认证的字段操作仍拒绝；SQL语法允许比较不表示每个数据类型支持所有比较。显式映射允许已认证的跨来源属性投影，但筛选、排序及权限行条件继续遵守主表边界。计算、Enum、单位表达式不因文本入口自动开放。

首批语法骨架如下；标识符和字符串均由词法器处理转义，注释只作为 token 间空白，不通过正则替换 SQL。关键字大小写不敏感，`OR < AND < NOT` 为从低到高的优先级。

```ebnf
statement  = SELECT field { "," field } FROM source [ AS identifier ]
             [ WHERE expression ] [ ORDER BY field [ ASC | DESC ] ]
             [ LIMIT integer ] [ ";" ] EOF ;
source     = identifier [ "." identifier ] ;
field      = identifier [ "." identifier ] ;
expression = conjunction { OR conjunction } ;
conjunction = negation { AND negation } ;
negation   = NOT negation | "(" expression ")" | predicate ;
predicate  = field comparison scalar
           | field IS [ NOT ] NULL
           | field [ NOT ] IN "(" scalar { "," scalar } ")"
           | STARTS_WITH "(" field "," scalar ")" ;
comparison = "=" | "<>" | "!=" | "<" | "<=" | ">" | ">=" ;
scalar     = string | number | TRUE | FALSE | NULL | parameter ;
```

`identifier` 是双引号标识符，内部双引号双写；`string` 是单引号字符串，内部单引号双写；`parameter` 是冒号加名称。数字保留原始十进制文本后按字段类型校验，不经过浮点数。`NULL` 只在共享引擎允许的位置使用；比较或前缀操作的空值须改写为 `IS NULL` 等明确形态，不能将空值悄悄当空字符串。`IN` 中允许的空值仍按字段可空性及 SQL 三值逻辑处理，不展开数组参数。

可将当前个人知识库生成的第一条指导查询设为：

```sql
SELECT "笔记"."标题", "笔记"."来源相对路径"
FROM "个人知识库"."笔记" AS "笔记"
WHERE "笔记"."来源可用" = TRUE
LIMIT 25;
```

该示例可通过首批文本入口执行，内部仍由 QuerySpec 查询。“标题”和“来源相对路径”实际为 `text`，不能在指导中推荐按标题排序；若用户需要排序，候选列表只提供实际可排序字段。包含完整 Markdown 的属性可显式选择，模板默认不展开长正文。

参数化前缀示例为 `WHERE STARTS_WITH("笔记"."标题", :标题前缀)`，参数面板独立填写字符串，用户无需在参数值中加单引号或 `%`。int64、decimal 的字面数字由服务端保留词法原值并按目标字段编码为十进制字符串；参数控件也保留字符串，不能经过 JavaScript Number。时间沿当前RFC3339及微秒约束，不擅自转成浏览器毫秒值。同名参数多次出现必须具有兼容类型；缺值可完成结构分析并提示待填写，执行必须完整绑定。空字符串、未填写和显式空值分别处理。

### Link 文本查询的分期

第一阶段继续保留结果行“关联数据”入口，实际通过既有 `via` 查询；它支持从一个确定实例正向或反向读取终点实体，不能替代下面的全集 `JOIN LINK` 示例。`via` 的筛选、投影、排序只作用于返回端，并按终点身份去重；它不能保留任意根端投影、根端条件或多条路径产生的重复行。

建议后续第二阶段单独定义“固定起点关系导航”的文本形态，要求有类型起点实例参数、明确方向和终点实体结果，再精确降低为 `via`。该形态的最终拼写待确认，不提前作为 `JOIN LINK` 的简写实现。若要开放本节后续的 `JOIN LINK`、相关 `EXISTS` 或聚合，应先扩展 DataSet 共用计划及结果模式，再同时落实编译、权限和分页；不能只扩展文本解析器。

## 4. Link 导航、多跳与前后关系

建议使用显式 `JOIN LINK` 扩展，区分通过本体关系导航与按任意字段关联。短写使用当前端点上的中文方向入口；完整写法使用分类、Link 主名称和方向，解决入口重名或需要明确方向的情况。以下是候选语法骨架，不是完整语法定义：

```text
JOIN LINK 起点别名.方向入口名 AS 终点别名
  [EDGE AS 边别名] [CONTEXT :上下文参数] [ON 附加条件]

JOIN LINK 起点别名 VIA 分类.Link主名称 DIRECTION OUT或IN AS 终点别名
  [EDGE AS 边别名] [CONTEXT :上下文参数] [ON 附加条件]
```

OUT/IN 是语法中的方向关键字，对应 Link 的正向/反向；不根据“包含”“属于”等动词猜方向。绑定时校验起点实际类型、Link 端点、上下文及权限，终点类型由 Link 推导。方向入口不能唯一解析时要求完整写法。边别名用于引用已声明的中文关系属性，边身份保留在内部行绑定中；基础 INNER 导航先认证，LEFT JOIN LINK 的空值补齐、ON 与 WHERE 区别需在共享计划具备明确语义后开放。BOTH、对称、有效时间和派生关系也分别沿用已认证能力。

### 查询一条产线的设备

```sql
SELECT "设备"."设备编码", "设备"."设备名称"
FROM "生产管理"."产线" AS "产线"
JOIN LINK "产线"."包含设备" AS "设备"
WHERE "产线"."产线编码" = :产线编码
ORDER BY "设备"."设备编码" ASC
LIMIT 50;
```

“包含设备”绑定为“产线设备成员”的正向视图，数据仍来自统一成员事实。此查询按设备编码返回一页成员，不表示产线前后顺序；查询全部成员需沿游标读取完，实际工艺顺序和前驱规则见 [Link](../模块/Link.md)。

### 查询某设备在指定产线的上一台

```sql
SELECT "上一台"."设备编码", "上一台"."设备名称"
FROM "生产管理"."设备" AS "当前设备"
JOIN LINK "当前设备"
  VIA "生产管理"."产线设备直接后继" DIRECTION IN AS "上一台"
  CONTEXT :产线上下文
WHERE "当前设备"."设备编码" = :设备编码
LIMIT 1;
```

产线上下文参数是同租户“产线”的有类型实例引用，绑定和执行时验证实际身份及授权。这里 IN 读取当前设备作为 target 的直接后继边，返回 source，即上一台；唯一约束来自该上下文中已认证的 chain 规则，LIMIT 1 不能替代基数和顺序校验。短写可选择当前设备的“上一台”方向入口；权限隐藏邻居、读取失败与真实首节点的区别沿用 Link，不伪装成相同空结果。

### 连续多个 Link

```sql
SELECT DISTINCT "设备"."设备编码", "设备"."设备名称"
FROM "生产管理"."工单" AS "工单"
JOIN LINK "工单"."使用设备" AS "工单设备"
JOIN LINK "工单设备"."所属产线" AS "产线"
JOIN LINK "产线"."包含设备" AS "设备"
WHERE "工单"."工单编码" = :工单编码
ORDER BY "设备"."设备编码" ASC
LIMIT 50;
```

路径绑定为“工单使用设备 OUT → 产线设备成员 IN → 产线设备成员 OUT”，与 DataSet 多跳示例共用计划；假设本例工单编码也是已校验的唯一键。这里 DISTINCT 去重的是所选字段组合，在本例设备编码唯一且只查具体设备 Schema 的前提下可得到每台设备一次。一般情况下不能把字段值相同当作实体身份相同，也不能把 DISTINCT 当作降低多跳成本的保证。

## 5. 行数、聚合和分页语义

OntologySQL 的普通 SELECT 是行投影，JOIN LINK 默认每个匹配边/路径绑定产生一行，N:M 可能重复根对象或终点对象；不隐式套用 DataSet 关联存在性筛选的实体去重。需要“至少存在一条满足条件的关系”的筛选时，应编译为共享计划的关系存在性节点；候选相关子查询写法为 `EXISTS (SELECT 1 FROM LINK 起点别名.方向入口名 AS 终点别名 WHERE 条件)`，只允许已认证的相关范围，不默认开放任意子查询。

| 语义 | 共享计划必须保留的区别 |
| --- | --- |
| 普通 SELECT 与 JOIN LINK | 显式扁平行结果，保留参与对象、边及路径身份；不能用 EXISTS 替换会影响行数的 JOIN |
| EXISTS | 根对象的关系存在性条件，不因多条匹配关系复制根对象 |
| DISTINCT | 按投影后的值元组去重，遵循 NULL 及类型比较规则，不等于按实体 ID 去重 |
| COUNT(*) / COUNT(字段) | 分别计算输入行和非空字段值数量；COUNT(DISTINCT 字段) 计算不同非空值，不自动表示实体数 |
| GROUP BY / HAVING | 全部授权输入先分组聚合，再筛选聚合结果，最后排序分页；无意展开造成的重复汇总须由显式查询形态解决 |
| NULL 和布尔条件 | 采用 SQL 三值逻辑，WHERE/HAVING 仅保留 TRUE；共享表达式必须明确 NULL、缺失、NOT、IN 及比较语义，不能错误转换成普通二值判断 |

例如按设备状态统计时，可以在聚合开放后采用以下写法，避免先关联多值关系导致 COUNT(*) 计成关系行数。

```sql
SELECT "设备"."设备状态" AS "状态", COUNT(*) AS "设备数量"
FROM "生产管理"."设备" AS "设备"
GROUP BY "设备"."设备状态"
HAVING COUNT(*) >= :最少数量
ORDER BY "设备数量" DESC, "状态" ASC
LIMIT 50;
```

同名输出列要求显式中文别名或明确的来源分组，不能覆盖结果键。聚合结果和扁平行不伪装成可保存的实体；字段、Enum code/中文标签、单位和隐藏身份描述仍沿用 DataSet。类型继承默认精确 Schema，不因写 FROM 自动包含子类；子类型文本语法另行确定。

LIMIT 对应最终页大小；游标建议作为查询请求参数传递，沿用 DataSet 的条件、参数、当前定义/映射及权限绑定，不将底层厂商游标写入 SQL 文本。实体页、扁平路径行和聚合页分别确定稳定排序身份：路径行须考虑参与边的完整绑定，聚合页按分组身份及排序键处理；未认证稳定续页的形态不能承诺游标分页。OFFSET 和无 ORDER BY 的稳定翻页策略待定，不默认开放无界深分页。

## 6. 编译、接口和诊断

### 首批实际协议（2026-11-07）

请求和响应类型见 [ontology_sql.go](../../contracts/ontology_sql.go)、[query_context.go](../../contracts/query_context.go)，路由与共用查询执行见 [Data 服务](../../services/data/README.md)。以下入口使用现有服务端会话及 POST 的同源/CSRF 校验，响应均为 `Cache-Control: no-store`。

| 入口 | 首批协议 |
| --- | --- |
| `GET /data/query/context` | `categoryId/schemaId/search/cursor/limit` 可选过滤；limit默认30、最大50，返回 `models` 和可选 `nextCursor`。模型含分类、Schema稳定ID/中文名及授权字段；字段含类型、可空性、精度、`filterable/sortable`，不含物理映射或业务数据 |
| `POST /data/query/ontology-sql/analyze` | 正文 `text/parameters/defaultCategoryId/requestId`，返回 `requestId/textHash/diagnostics/parameters/fields/ready`；完整可执行时含稳定ID的 `query`。缺参仍返回类型和出现范围，`provided=false/ready=false`，不读取业务行 |
| `POST /data/query/ontology-sql/complete` | 同上并提交从0开始的UTF-16 `cursorOffset`；返回 `items`，每项含 `label/insertText/detail/kind/range`。容忍未完成语法，最多50项；仅使用授权模型与字段，WHERE/ORDER按实际能力过滤 |
| `POST /data/query/ontology-sql/format` | 同一词法/语法前端格式化，返回 `text/diagnostics/requestId/textHash`；字符串、标识符、注释保留，不完整语句不通过删除片段修复 |
| `POST /data/query/ontology-sql` | 正文与analyze相同；检查完整且参数齐全才执行，返回原QueryResult的 `data/fields/hasMore/nextCursor`，附加实际绑定的 `query/requestId/textHash`。后续页携带此query及游标提交既有 `/data/query`，继续重新授权 |

`parameters` 是按名称传递的JSON标量对象；int64/decimal必须使用字符串，boolean使用JSON布尔值，文本/UUID/时间使用字符串，合法位置的空值使用JSON null。省略某个键表示未提供，空字符串是已提供的文本值；不把数组参数展开为IN集合。同名参数的类型、精度及全部使用位置必须兼容，未使用的实参明确拒绝。文本最多64KiB、8192个token、64个命名参数；投影和IN集合最多100项，筛选节点最多100、嵌套最多10层，LIMIT默认25、范围1..100。目录读取另有1000项扫描预算，要求缩小范围后重试。

所有源码范围为UTF-16半开区间 `from/to`；展示用 `line/column` 从1开始，CRLF算一个换行。`textHash` 是输入文本UTF-8的SHA-256，供调用方与requestId一起拒绝旧响应，不是授权或持久计划凭证。语法、字段和类型诊断由analyze返回；不完整或非法文本执行返回422。不可见和不存在的模型统一为 `source_unavailable`，字段统一为 `field_unavailable`，不返回隐藏名称或绑定；身份失效、目录读取或权限服务故障仍使用对应HTTP错误。

目录以当前调用者身份读取Metadata公开目录，叠加 `instance.query` 与 `readFields` 生成，不用服务身份列目录。显式FROM的名称解析随后也检查定义可发现性及当前查询授权。格式化只处理调用者提交的文本，不解析隐藏目录；analyze、context和complete不查询业务表、样例或COUNT。物理目录、gate、实际来源及授权状态在执行时仍按共用执行器重新核验，分析通过不能代替运行时检查。

以下继续描述完整方案；其中计划预览、多跳、聚合、持久缓存等为后续候选，不能从上表接口可用推断为已开放。

建议 Data 服务内部增加文本前端，不新增独立查询服务或执行通道。编译步骤为：完整解析单条语句并保留源码位置 → 按可信租户及作用域绑定名称/ID → 检查类型、单位、参数及操作权限 → 降低为 QuerySpec → 执行统一能力/预算校验及优化 → 生成数据库 SQL 或受控批量计划。SDK/JSON 也通过同一校验器，外部提交的 IR 或已绑定对象同样不被直接信任。

使用真正的词法/语法解析与类型化语法树，不能靠正则替换字段或按分号切分文本。首批有限语法建议使用Go显式词法器与递归下降解析，保留token及源码范围，布尔表达式明确优先级；实现时先冻结EBNF和代表用例，再决定是否复用适合的解析库。评估Unicode、双引号、参数、容错上下文及未来关系扩展，不将MySQL等厂商方言直接当作本体语言。前端仅做高亮和交互，权威语义编译保持一份。后端解析器无新增依赖或生成代码；前端使用独立加载的CodeMirror 6。

查询计划预览仍待后续实现；不返回物理SQL或厂商EXPLAIN，也不自动执行样例扫描。其余首批入口的协议以上表为准，新增上下文不能获得额外业务权限；公共授权规则仍唯一见[权限设计](../权限/权限设计.md)。

建议执行流程为 `读取可信上下文 → 解析 → 绑定Schema/字段 → 类型化参数 → 共用校验器 → 共用执行器`，将当前HTTP入口中的绑定/执行逻辑提取为Data内部可复用函数。SQL接口不通过回环HTTP另调自己，也不读取Metadata私有表。编译/补全不开放底层表、列、凭据或不可见字段；无权与不存在的业务名称采用不泄露目录的统一反馈，可见但能力未支持的语法才具体说明原因。

首批分页建议复用现有结构：执行返回实际已绑定的 `QuerySpec` 作为执行上下文，参数值已按当前类型写入表达式；下一页将这份稳定ID描述及游标提交现有 `POST /data/query`。该描述与其他客户端QuerySpec一样必须重新授权，不是授权令牌，也不创建持久计划。修改文本、参数、默认分类或模式后清除上下文和游标；仅排版变化也可保守要求重新运行。不能每一页重新按中文名称解析到另一个对象。定义/权限/来源变化仍使现有游标失效，依照DataSet当前分页规则重新运行。

诊断与补全候选建议携带 `requestId`、源码摘要、范围、稳定错误码及中文修正说明。范围统一为从0开始、末端不包含的UTF-16文档偏移，供浏览器直接标注；展示行列从1开始。Go内部的UTF-8字节位置在输出前转换，显式覆盖中文、emoji、CRLF和双引号转义。缺少参数、同名参数类型冲突、字段不可用、不可排序、能力未开放及超预算分别定位；旧请求响应不得套用到新文本或新分类。

只读入口初期仅接受一条 SELECT，允许可选末尾分号并要求其后只有合法空白或注释；不允许多语句、DDL、DML、过程调用、文件访问、系统目录或物理表逃逸。表和列仅来自绑定后的受控映射，值仍参数化；即使底层数据库支持某语法，也须先满足本体规则与能力认证。

预览复用 DataSet 的只读边界，不默认执行 EXPLAIN ANALYZE、样例扫描、COUNT 或业务 Function。文本长度、token/AST 节点、嵌套和参数集合均有编译预算，多跳与执行仍有中间结果、成员数、字节和耗时预算；小 LIMIT 不构成廉价查询保证。具体限额和 HTTP 协议待后续验证。

首批工程预算已经在实际协议中冻结；后续多跳、中间结果与响应容量仍须按能力单独验证，不能将有界页大小视为性能承诺。

## 7. 改名、缓存和性能

临时文本每次首次绑定按当前中文名称解析；持久查询若后续开放，应保存原始文本、参数声明、ID 绑定的逻辑计划及源码映射，执行时使用原 ID 并校验当前定义。改名后可从绑定生成当前中文名称的展示或格式化文本，原始文本仅作编辑来源；重新编辑并编译视为显式新绑定，展示绑定变化，不让同名新建自动接管旧依赖。沿用单份当前定义，不引入业务 version；具体保存查询能力仍是候选。

SQL 文本解析和语义绑定可缓存，但绑定及执行计划须按租户、当前名称登记、依赖/映射、权限、能力及查询结构隔离并校验权威当前状态；参数值每次绑定。缓存命中不跳过授权，不能缓存上次参数；名称不在逐行执行阶段重新解析。参数变化影响成员裁剪或执行计划时重新校验，不复用上次参数的分表成员集合。

性能比较以等价 OntologySQL、DataSet SDK/JSON 和人工核对的参数化 SQL 为基线，要求相同行结果、重复/空值、权限、单位、读取一致性和预算。分别测文本解析、中文绑定、逻辑计划编译与数据库执行，并记录冷暖缓存、并发和多跳规模。经共享计划执行可复用同库下推，不能据此宣称文本解析零开销或所有查询只发一条 SQL；测量方法统一维护在[性能与容量](../性能与容量.md)。

## 8. 验收与待定事项

以下覆盖完整目标；首批单Schema子集已有模块及真实MySQL/OPA验证，JOIN、聚合、多跳、缓存与性能继续待验收，具体结果见项目总览。

| 编号 | 要求 | 验收方法 |
| --- | --- | --- |
| OSQL-01 | 文本入口降低为统一查询描述 | 同语义 SQL、SDK、JSON 得到等价 ID 绑定及结果，编译不加载全集或逐 JOIN 发请求；未表示的语义明确拒绝 |
| OSQL-02 | 中文名称、作用域及诊断明确 | 分类同名、别名、引号内点号、转义双引号和 Unicode 可核对；参数不能替换标识符，错误定位到源码且不越权泄露 |
| OSQL-03 | Link 方向、上下文和多跳沿用统一规则 | 成员 OUT、所属产线 IN 和指定产线的上一台与 DataSet 等价；歧义拒绝，关系属性、N:M 和后续 LEFT 语义逐项认证 |
| OSQL-04 | SQL 行数、聚合及空值不被错误简化 | JOIN 重复行、EXISTS 根对象、DISTINCT 值元组、COUNT/NULL、三值逻辑、HAVING 和全局分页有独立可核对结果 |
| OSQL-05 | 只读、参数化及预算在所有入口成立 | 多语句/写语句/物理表访问拒绝，参数和名称不能注入 SQL；复杂文本及小页高扇出受控失败，无物理 SQL 兜底通道 |
| OSQL-06 | 绑定身份、当前态和权限一致 | 改名、同名重建、原文重编译、缓存失效及参数变化不误绑/漏成员；依赖或权限失效明确拒绝，旧绑定不运行历史定义 |
| OSQL-07 | 预览与性能结论有相同语义基线 | 预览不执行业务扫描，三种编写入口复用当前校验；分阶段报告解析/绑定/编译/执行成本，不将文档或单例等价当作三库性能通过 |
| OSQL-08 | 首批文本与现有实体QuerySpec精确等价 | 比较基础SELECT、参数、NULL/集合、精确数值、默认/显式排序与分页；拒绝星号、列别名、字段间比较、JOIN/聚合及尾部多语句，不丢弃未支持片段 |
| OSQL-09 | 查询上下文、补全与源码诊断准确受控 | 不完整语句可补全；候选随分类、别名、字段类型/主表能力及当前权限变化，不泄露隐藏目录或扫描业务值；UTF-16范围覆盖中文/emoji/CRLF，旧响应被拒绝 |

第一阶段单Schema文本、参数、诊断/补全、引导和可视化子集完整转换已按用户确认方案落实；实际验证以项目总览为准。第二阶段待明确固定起点关系文本，后续再扩共享计划的JOIN、EXISTS及聚合。待定：固定起点关系拼写、扁平行/聚合节点、三库能力、持久查询、缓存及性能目标。
