# Enum：枚举定义与演进

状态：模块说明草案，尚未实现。本文统一维护枚举的用途、数据结构、校验、存储建议和验收；示例是候选协议。

## 1. 用途与边界

Enum 表达一组具有稳定业务含义的可选值，供 [Schema](Schema.md) 属性和 [Function](Function.md)、[Action](Action.md) 参数引用。例如设备状态、工单优先级和故障分类。

Metadata 的 enum 模块拥有枚举定义；使用方通过明确版本获取取值及校验规则。实例中的实际状态由 Data 管理。Enum 不承担任务运行状态机或设备状态转换规则，这些行为分别由执行服务或业务操作维护。

## 2. 建议数据结构

| 内容 | 含义 |
| --- | --- |
| id、version | 枚举的稳定标识和定义版本 |
| name、labels、description | 程序名称、多语言显示名称及说明 |
| values[].code | 稳定的业务值编码，建议首期使用字符串 |
| values[].labels、description | 值的多语言名称及解释 |
| values[].deprecated | 是否已废弃；旧数据能否读、新数据能否写需分别定义 |
| values[].order | 可选显示顺序，不能代替业务值编码 |

```json
{
  "id": "device-state",
  "version": "1.0.0",
  "labels": {"zh-CN": "设备状态"},
  "values": [
    {"code": "RUNNING", "labels": {"zh-CN": "运行中"}, "deprecated": false},
    {"code": "STOPPED", "labels": {"zh-CN": "已停止"}, "deprecated": false},
    {"code": "MAINTENANCE", "labels": {"zh-CN": "维护中"}, "deprecated": false}
  ]
}
```

字段或参数通过 `{ "id": "device-state", "version": "1.0.0" }` 形式的枚举引用表达类型；实际值保存 `RUNNING` 等编码。具体引用字段名在协议定稿时统一。

## 3. 校验与兼容性

同一版本内值编码必须唯一。显示名称可以本地化或修改，但业务编码的含义不应随标签变化。空值由引用方的 nullable/required 规则决定，不自动作为一个枚举值。

| 变更 | 建议处理 |
| --- | --- |
| 增加值 | 评估消费者是否穷举全部取值；不能笼统认定所有旧客户端都兼容 |
| 修改显示名称或顺序 | 更新元数据版本，保留业务编码，通常无需重写实例值 |
| 废弃值 | 明确新写入策略，旧版本和历史数据仍能解释该编码 |
| 重命名业务编码 | 作为新增/迁移/废弃处理，不能等同于修改标签 |
| 删除值 | 检查实例、参数、默认值及定义引用，先完成数据处理与兼容迁移 |

已发布定义不可被草稿覆盖。校验按调用或写入指定版本执行，不能用最新 Enum 静默重解释旧值。发布、依赖检查和迁移流程统一见 [发布与迁移](../发布与迁移.md)。

## 4. 接口与存储建议

模块至少提供草稿维护、指定版本读取、取值校验、差异及兼容性检查能力；对外路由尚未确定。Data 和执行服务可按发布版本缓存枚举，批量查询时返回值编码及所需标签信息，无需每个实例再访问 Metadata。

建议逻辑枚举先与数据库实现解耦。首轮实例列保存稳定编码，定义、引用与版本校验由所属模块维护，通过 [统一存储引擎](../存储引擎.md) 访问数据库。编码的比较、大小写及约束须跨库验证；原生数据库 ENUM 作为适配器可选能力。不能因数据库能存字符串就忽略约束，也不能强制每次增加取值都产生 DDL。

## 5. 验收与待定事项

| 编号 | 要求 | 验收方法 |
| --- | --- | --- |
| CORE-03 | Enum 可被字段和调用参数引用，变更兼容性可判断 | 验证非法值拒绝、稳定值与显示名称分离，以及删除使用中取值的处理 |

补充检查：重复编码被拒绝；标签改名不破坏历史数据；旧版本可读取；已废弃值的新写入策略可验证；默认值仍属于有效取值范围。

待定：编码类型与大小写规则、废弃后写入策略、引用索引、客户端未知值处理、原生 ENUM 使用范围及接口格式。
