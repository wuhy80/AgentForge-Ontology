# Enum：枚举定义与演进

状态：模块说明草案，尚未实现。本文统一维护枚举的用途、数据结构、校验、存储建议和验收；示例是候选协议。

## 1. 用途与边界

Enum 表达一组具有稳定业务含义的可选值，供 [Schema](Schema.md) 属性和 [Function](Function.md)、[Action](Action.md) 参数引用。例如设备状态、工单优先级和故障分类。

Metadata 的 enum 模块拥有一份当前生效定义，使用方按稳定 ID 获取当前取值及校验规则，不携带业务 version。实例中的实际状态由 Data 管理。Enum 不承担任务运行状态机或设备状态转换规则，这些行为分别由执行服务或业务操作维护。

租户、分类、分组及中文名称解析规则见 [组织与隔离](../组织与隔离.md)。用户按中文 name 定义和选择 Enum，内部 Schema 与调用参数通过稳定 ID 引用同租户 Enum；values[].code 是业务取值编码，与定义中文名称及定义 ID 分开。以下 JSON 为内部定义示例，不要求用户手填 ID。

## 2. 建议数据结构

| 内容 | 含义 |
| --- | --- |
| id、tenantId、categoryId、groupId | 枚举的稳定标识及组织归属 |
| name、labels、description | 中文主业务名称、可选多语言显示名称及说明；定义选择时按中文主名称解析 |
| values[].code | 稳定的业务值编码，建议首期使用字符串 |
| values[].labels、description | 值的多语言名称及解释 |
| values[].deprecated | 是否已废弃；旧数据能否读、新数据能否写需分别定义 |
| values[].order | 可选显示顺序，不能代替业务值编码 |

```json
{
  "id": "458bdc85-0827-4bdb-9f93-68f5624dcb89",
  "tenantId": "56a79c34-5f02-4836-a809-42a7e3110c21",
  "categoryId": "49346208-cf9c-486b-9982-782ab3f3ea49",
  "groupId": "764cc48e-995e-4edc-b148-6cb8f4eba310",
  "name": "设备状态",
  "labels": {"zh-CN": "设备状态"},
  "values": [
    {"code": "RUNNING", "labels": {"zh-CN": "运行中"}, "deprecated": false},
    {"code": "STOPPED", "labels": {"zh-CN": "已停止"}, "deprecated": false},
    {"code": "MAINTENANCE", "labels": {"zh-CN": "维护中"}, "deprecated": false}
  ]
}
```

字段或参数通过 `{ "id": "458bdc85-0827-4bdb-9f93-68f5624dcb89" }` 形式的枚举引用表达类型；实际值保存 `RUNNING` 等编码。具体引用字段名在协议定稿时统一。

## 3. 校验与兼容性

当前定义内值编码必须唯一。显示名称可以本地化或修改，但业务编码的含义不应随标签变化，也不能删除后复用为另一种含义。空值由引用方的 nullable/required 规则决定，不自动作为一个枚举值。

面向用户可写“设备状态 = 运行中”，编辑器或名称解析层按目标 Enum 的中文标签绑定 `RUNNING`，底层比较和保存仍用稳定 code。按中文标签输入必须唯一匹配，不允许从多个同标签值中取第一项；明确选择时绑定真实 code。中文标签改名不改变已绑定取值，也不能把标签字符串直接写入编码列；labels 的其他语言变化不切换中文查询含义。

| 变更 | 建议处理 |
| --- | --- |
| 增加值 | 评估消费者是否穷举全部取值；不能笼统认定所有旧客户端都兼容 |
| 修改显示名称或顺序 | 更新当前元数据，保留业务编码，通常无需重写实例值 |
| 废弃值 | 当前定义保留编码及含义，明确新写入策略，保证既有数据可读取 |
| 重命名业务编码 | 作为新增/迁移/废弃处理，不能等同于修改标签 |
| 删除值 | 检查实例、参数、默认值及定义引用，先完成数据处理与兼容迁移 |

保存草稿不改变当前定义，生效前检查当前 Schema、参数、默认值、实例及运行任务。新调用和写入按当前 Enum 校验；删除仍被使用的编码必须阻止，直到依赖调整和既有数据迁移完成。不会保存可供调用方选择的旧 Enum，统一流程见 [发布与迁移](../发布与迁移.md)。

## 4. 接口与存储建议

模块至少提供草稿维护、当前定义读取、取值校验、差异及影响检查能力；对外路由尚未确定。Data 和执行服务可按租户、Enum ID 及当前内容摘要缓存，并校验当前状态；批量查询返回值编码及所需标签，无需每个实例再访问 Metadata。

建议逻辑枚举先与数据库实现解耦。首轮实例列保存稳定编码，当前定义、引用与取值校验由所属模块维护，通过 [统一存储引擎](../存储引擎.md) 访问数据库。编码的比较、大小写及约束须跨库验证；原生数据库 ENUM 作为适配器可选能力。不能因数据库能存字符串就忽略约束，也不能强制每次增加取值都产生 DDL。

## 5. 验收与待定事项

| 编号 | 要求 | 验收方法 |
| --- | --- | --- |
| CORE-03 | Enum 可被字段和调用参数引用，变更兼容性可判断 | 验证非法值拒绝、稳定值与显示名称分离，以及删除使用中取值的处理 |

补充检查：重复编码被拒绝；标签改名不破坏既有数据；无旧定义选择接口；已废弃值仍可解释既有数据，其新写入策略可验证；默认值仍属于有效取值范围。

待定：编码类型与大小写规则、废弃后写入策略、引用索引、客户端未知值处理、原生 ENUM 使用范围及接口格式。
