# Action：业务操作与效果

状态：完整设计与首批实现并行维护。Metadata已开放定义维护及`targetSchemaIds`对象关联；2026-11-07先实现绑定Python Function的纯计算调用及Action独立源码，2026-11-08按用户要求接入JavaScript和Go。三语言直接源码与绑定调用已有实现，副作用、业务前置条件和事务仍未实现，分项验证状态见[项目总览](../项目总览.md#当前实现与验证2026-11-06)。

## 1. 用途与边界

Action 表达对目标对象执行的业务操作，例如创建维护工单、更新业务状态或触发外部处理。定义应描述参数、目标、预期效果、权限及执行要求，实际运行状态保存在 Execution。

Action可直接维护Python、JavaScript或Go源码，或调用[Function](Function.md)，对应入口与隔离统一见Function。用户自定义容器、外部服务及异步调用仍为后续方案。Action与Function的区别主要在业务语义，不能仅靠名称判断读写、副作用或重试安全性。

Metadata 的 action 模块维护定义及引用，Data 管理实例/关系，Execution 管理任务和尝试，Worker 执行代码。Action 不能绕过其他服务的接口直接修改其私有表。

租户、分类、分组及中文名称解析规则统一见 [组织与隔离](../组织与隔离.md)。用户按中文 name 维护和选择 Action、目标 Schema 及实现 Function，解析后保存稳定 ID 引用，且必须属于同一租户；输入输出按中文参数名编辑并映射已声明的技术协议键，用户无需填写内部 ID。每个 Action 仅有一份当前生效定义，不设置业务 version。

### 当前对象关联协议（2026-11-07）

对象详情页的“动作信息”按 Action 正文中的 `targetSchemaIds` 筛选关联动作；字段位于 `definition.action`，是可选的稳定 Schema ID 数组，最多32项，不接受空白或重复标识。数组顺序没有业务含义，保存时按稳定 ID 排序。省略或空数组表示未关联对象，不表示适用于全部对象。Function 不支持该字段。

目标须为同租户已经生效的 Schema，可跨分类选择，中文名称仅用于显示；保存草稿及发布都重新校验，发布后将关联纳入当前依赖登记。已有动作允许经草稿及发布修改这份关联，未发布的调整不替换当前态；输入输出、实现引用和副作用等变化仍遵守原有变更边界。对象关联目前用于定义发现，不授予动作调用、实例读取或写入权限，不代表动作执行已实现。工作台只展示当前账号可访问的关联定义。

后文的 `target`、前置条件及效果等仍为执行能力的候选协议，不将上述已实现的对象关联当作完整目标条件或调用语义。

## 2. 建议定义内容

### 直接源码与绑定调用（2026-11-07）

用户确认Action也须具有独立源码编辑区域。当前定义在以下两种实现中选择一种，均要求`sideEffects=none`：

| 实现方式 | 定义与运行边界 |
| --- | --- |
| 直接源码 | 源码保存在`definition.action.runtime`，Action拥有自己的语言、输入、输出、源码、入口和超时，调用时按实际语言执行自己的当前代码；不创建或隐式绑定Function |
| 绑定Function | 使用`functionId`引用同租户已生效Function；双方中文参数名、类型、必填/空值、默认值、精度和约束必须一致，各自保留自己的稳定属性ID |

`runtime`、`functionId`、`artifactRef`互斥，不将配置冲突静默解释为另一种实现。`artifactRef`仍仅可登记，尚不能执行。直接源码模式保存及发布时按共同源码协议校验；绑定模式保存及发布时校验引用类型和签名，调用时重新读取双方当前定义。已生效直接源码Action可经草稿更新语言、源码、入口和超时；已生效且没有函数绑定或产物引用的无副作用Action可补充源码。输入输出签名、副作用及已绑定实现保持锁定；已有绑定Action继续使用原引用，不能通过编辑器改为一份独立源码。源码写法、语法高亮、参数补全、类型映射和运行限制统一见[Function](Function.md#javascript与go扩展2026-11-08已确认)。

首批调用只传入声明参数，`targetSchemaIds`继续用于模型关联发现，不隐式读取或更新目标实例，也不开放目标对象ID、前置条件、业务事务和外部写入。权限统一见[权限设计](../权限/权限设计.md#首批纯计算调用2026-11-07已实现)，同步调用及幂等协议见[执行与调度](../执行与调度.md)。Action名称表达业务意图不意味着其业务效果已实现。

2026-11-08确认的Python调试、参数改名引用提醒及测试样例统一见[Function](Function.md#python调试与草稿试运行2026-11-08已确认)。Action试运行使用其服务端已保存草稿，保持Action自身的定义ID及执行身份；直接源码模式执行该草稿的源码，绑定模式仍读取所绑定Function的当前实现，不复制源码、不隐式运行Function草稿。试运行不发布或替换当前Action，当前态业务调用继续使用已生效实现；草稿调用和结果授权仍引用权限主说明。

### 完整业务操作清单候选

| 内容 | 用途 |
| --- | --- |
| id、tenantId、categoryId、groupId | 稳定标识及组织归属 |
| name、labels、description | 主展示名及业务用途 |
| target | 允许操作的 Schema、对象或业务范围 |
| input、output | 参数、结果及单位/Enum 语义，复用 Schema 描述 |
| preconditions、effects | 业务前置条件、预期数据变化和外部副作用 |
| permissions | 公共策略绑定或调用者/执行身份的能力要求；统一语义见[权限设计](../权限/权限设计.md)，不作为独立允许名单 |
| implementation | Function 稳定 ID 引用，或运行器清单 |
| idempotency、retry、compensation | 去重、可重试条件、部分成功时的处理规则 |

下面用一个外部工单操作演示结构，所有字段为候选协议，具体规则表达式与执行方式尚待设计。

```json
{
  "id": "fc9f0b3b-8b2d-442f-a146-1e3486b0f0b3",
  "tenantId": "56a79c34-5f02-4836-a809-42a7e3110c21",
  "categoryId": "49346208-cf9c-486b-9982-782ab3f3ea49",
  "groupId": "764cc48e-995e-4edc-b148-6cb8f4eba310",
  "name": "创建维护工单",
  "description": "为指定设备创建维护工单",
  "target": {"id": "a10a4ea8-a988-48a6-aec3-d70cc5f4e531"},
  "input": {"reason": {"name": "维护原因", "dataType": "string", "required": true}},
  "output": {"workOrderId": {"name": "工单标识", "dataType": "string"}},
  "effects": [{"kind": "externalWrite", "system": "eam", "operation": "createWorkOrder"}],
  "permissions": ["maintenance-order:create"],
  "implementation": {"kind": "function", "id": "7e61a790-3a5a-4124-9931-15a46eb70b1f"},
  "idempotency": {"required": true},
  "retry": {"requiresIdempotentReceiver": true}
}
```

引用的 Function 必须实际声明并获准执行外部写入，不能将其伪装成无副作用计算。目标对象标识与幂等键属于一次调用的输入/上下文，具体载体由调用协议统一定义。

上例为内部定义结构：reason/workOrderId 是技术适配键，用户填写“维护原因”、读取“工单标识”；中文参数名在对应输入或输出范围内唯一，持久定义和执行仍使用已绑定身份及明确的协议映射。

## 3. 执行流程

直接源码与绑定调用的当前权限及后续目标/参数、运行身份和输出授权候选统一见[权限设计](../权限/权限设计.md)第7节；上例permissions字符串仅示意能力要求，不是最终规则协议。后续Action可通过明确的受限调用路径授权特定修改，不能借实现Function或Worker的服务账号放大权限；排队、重试和结果读取按公共当前授权检查。

建议流程：按中文名称选择并绑定 ID → 按 ID 读取当前定义及目标 → 校验身份、参数及业务前置条件 → 创建持久执行记录 → 执行开始时重新解析当前依赖并保存必要执行上下文 → 执行并验证效果或保存待核对状态 → 返回结果。已绑定调用沿用原 ID 并检查当前状态，不按旧中文文本重新选取同名定义。

前置检查和实际写入之间可能有并发变化。需要强一致的条件应由实际数据所有者在事务或条件写入时再次验证，不能把入口检查当成跨服务原子保证。

同步/异步调用、任务 ID、状态、通知、超时、取消、租约及尝试标识统一见 [执行与调度](../执行与调度.md)。事件和周期按 ID 触发当前 Action；规则配置不改变 Action 自身的权限及幂等要求。

## 4. 副作用、重试与兼容性

持久任务按至少一次处理，外部写入需要接收方幂等键或结果核对。工作线程完成外部写入但未提交结果时，不能直接假定操作失败并再次创建工单。

超时不代表业务操作未发生，取消不保证撤销既有结果。跨系统默认没有原子事务；部分成功需明确补偿或向前修复，外部效果不明时保留待核对记录。补偿能力应按操作实际能力声明，不承诺通用回滚。

修改目标、业务效果、必填参数、单位、重试条件或实现引用时检查当前依赖、调用方和未完成任务，校验后替换当前定义。排队任务开始时采用最新定义并重新校验；已开始任务及其重试沿用本次执行上下文，权限与数据写入仍遵循当前校验。不兼容变更需先排空相关运行任务，具体流程见 [发布与迁移](../发布与迁移.md)。

## 5. 实现与验收

与实例和关系的数据提交边界统一见 [数据读写](../数据读写.md)：建议基础 CRUD 由 Data 动态提供，Action 表达审批、启停等业务行为；需要对象和关系原子变更时明确调用受控 Data 事务命令，多次远程调用不自动合为一个事务。

模块提供草稿维护、当前定义读取、目标/参数校验、引用检查与变更影响分析。运行器沿用 Function 的清单与扩展方式；任务处理由 Execution 负责，避免 Action 模块重复实现队列、调度与运行状态机。

定义及源码编辑契约沿用[Function的CORE-06～CORE-08](Function.md)；执行与副作用行为沿用[执行与调度的RUN-01～05](../执行与调度.md)。权限专项验收引用[权限设计的AUTH-07～AUTH-09、AUTH-14](../权限/权限设计.md)，不另定义同一组规则。本模块重点验证：

- 直接源码Action独立保存和运行；无绑定纯计算定义可补源码，已有绑定及产物模式不能切换；绑定Action保持引用与签名校验，冲突配置明确拒绝。
- 未授权或不满足目标条件的操作不能执行。
- 相同幂等键重试可定位同一个逻辑操作，业务效果按接收方协议核对。
- 外部成功但本地结果提交失败、部分成功、超时及取消都可追踪。
- 引用对象删除/停用、输入单位不符及副作用声明不一致时明确拒绝。
- 排队任务启动时使用最新定义，已开始任务及重试不切换实现，补偿行为符合本次执行记录。

待定：Action 与 Function 的最终边界、目标与前置条件协议、事务范围、幂等键作用域/保留期、接收方核对接口、补偿，以及权限专题中的调用能力/委托范围与最终策略协议。工业设备控制和额外审批能力仍属于场景范围，未自动加入基础版本。
