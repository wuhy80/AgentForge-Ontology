# Function：可调用计算与运行定义

状态：模块说明草案，尚未实现。本文统一维护函数用途、清单、接口、运行器和验收；首批语言及协议字段仍待确认。

## 1. 用途与边界

Function 提供可调用的查询、计算或外部能力。建议默认用于查询与计算；读写权限及外部副作用必须显式声明，不能因为名称是 Function 就认定只读、确定性或可安全重试。

Metadata 的 function 模块保存定义、输入输出及版本化实现引用。Execution 管理调用与任务，Worker 执行代码。具有业务效果的操作可由 [Action](Action.md) 组织并引用 Function；平台采用 Go 不限制函数实现语言。

## 2. 定义与运行清单

| 内容 | 需要说明的行为 |
| --- | --- |
| id、version、labels、description | 可发现的稳定定义及说明 |
| input、output | 类型、必填、约束、Enum 引用及计量单位 |
| runtime、entrypoint | 运行方式、语言/运行时版本、入口 |
| artifactRef、依赖版本 | 不可变代码制品与实际执行环境，能关联到运行记录 |
| timeout、resources | 超时及 CPU、内存等资源要求 |
| permissions、sideEffects | 数据访问范围、外部系统写入及可重试条件 |

输入输出复用 [Schema](Schema.md) 的属性语义和 [Enum](Enum.md) 引用。计量参数采用受控单位及明确转换规则，不能将单位不同的裸数直接传入计算。多语言调用同样需要 int64、decimal、时间、二进制的无损表示。

以下以直流电路的功率计算为例，示例字段尚未构成最终 API：

```json
{
  "id": "calculate-dc-power",
  "version": "1.0.0",
  "description": "按直流电压与电流计算功率",
  "input": {
    "voltage": {"dataType": "decimal", "quantityKind": "voltage", "unit": {"system": "UCUM", "code": "V"}},
    "current": {"dataType": "decimal", "quantityKind": "electricCurrent", "unit": {"system": "UCUM", "code": "A"}}
  },
  "output": {
    "power": {"dataType": "decimal", "quantityKind": "power", "unit": {"system": "UCUM", "code": "W"}}
  },
  "runtime": {"kind": "script", "language": "python", "version": "3.12", "entrypoint": "power:calculate"},
  "artifactRef": "calculate-dc-power/1.0.0",
  "sideEffects": "none",
  "timeoutSeconds": 5
}
```

制品引用在发布时需解析到不可变内容及依赖，不能允许同一个发布版本加载后来被覆盖的代码。示例中的运行时版本是清单演示，不代表已选定首批语言。副作用声明需要配合实际权限和隔离措施执行。

## 3. 多语言实现建议

| 方式 | 执行方式 |
| --- | --- |
| 脚本包 | Python、JavaScript 等运行器加载版本化代码及依赖 |
| 容器 | 按约定入口与协议执行 Go 等编译语言或带专有依赖的实现 |
| 外部服务 | 通过 HTTP/gRPC 调用已有计算服务 |

首期选择一种实际可用运行器，其他实现方式通过统一协议扩展。制品和依赖按版本分发与缓存；大输入、输出可使用存储引用，保证执行记录仍能定位内容及保留期限。

运行器按代码可信程度限制 CPU、内存、执行时间、文件和网络权限，业务凭据按调用身份提供，任务工作目录相互隔离。容器本身不等于完整沙盒。具体资源、租约、故障恢复和任务隔离验收见 [执行与调度](../执行与调度.md)。

## 4. 调用流程与接口边界

建议流程：读取指定发布版本 → 验证调用权限和输入类型/单位 → 固定定义及制品版本 → 提交执行 → 校验并保存输出 → 返回结果或任务 ID。

Function 与 Action 都支持同步和异步调用，共用权限、任务及重试语义。同步等待预算不以 100 ms 为统一分界；客户端超时并不自动取消计算。限时等待、结果轮询、通知、取消与错误状态统一见 [执行与调度](../执行与调度.md)，本模块不再维护另一套任务状态机。

定义模块提供注册/编辑草稿、读取指定版本、检查依赖及清单、兼容性分析能力；调用与任务查询由 Execution 的公共接口提供。新增运行器不应修改 Data 查询模块，新增计算函数不应修改通用 API 入口中的类型分支。

## 5. 版本与依赖

函数定义版本、运行时版本、制品版本与输入输出 Schema 版本分别表达。发布集固定它们的关系，已经受理的任务不因新定义发布而切换实现。

改变输入单位、必填参数、返回类型、默认值行为或副作用声明时，需要评估调用方及 Action 引用的兼容性。缓存结果是否成立取决于输入、数据版本、外部依赖及确定性，不能默认所有 Function 都可缓存。共同流程见 [发布与迁移](../发布与迁移.md)。

## 6. 验收与待定事项

下面的定义契约检查同时适用于 Action；为避免重复维护，仅在此定义编号，Action 文档补充业务效果检查。

| 编号 | 要求 | 验收方法 |
| --- | --- | --- |
| CORE-06 | Action/Function 定义关联版本、输入输出和执行要求，并声明副作用 | 定义可注册校验，调用能追溯制品和版本；新增语言可遵循运行器契约接入 |

还需验证正确输入/输出、单位不匹配、依赖缺失、运行器版本不支持、超时、资源超限及重复调用。执行公共验收使用 RUN-01～05。

待定：首批语言、代码可信度、脚本/容器优先级、依赖构建与分发、运行器协议、清单具体字段、同步预算、输出验证和制品保留方式。
