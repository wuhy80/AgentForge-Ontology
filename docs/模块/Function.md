# Function：可调用计算与运行定义

状态：完整设计与首批实现并行维护。用户于2026-11-07确认先实现Python运行器和Function/Action独立源码编辑；2026-11-08按用户追加要求接入JavaScript和Go。三语言独立编辑、纯计算、源码工具及当前态/草稿执行已有实现，分项验证统一见[项目总览](../项目总览.md#当前实现与验证2026-11-06)。本文维护源码、运行器及类型协议；任务和权限分别引用所属专题。

## 1. 用途与边界

Function 提供可调用的查询、计算或外部能力。建议默认用于查询与计算；读写权限及外部副作用必须显式声明，不能因为名称是 Function 就认定只读、确定性或可安全重试。

Metadata 的 function 模块保存一份当前定义、输入输出及实现引用，不设置业务 version。Execution 管理调用与任务，Worker 执行代码。具有业务效果的操作可由 [Action](Action.md) 组织并引用 Function；平台采用 Go 不限制函数实现语言。

组织归属及中文名称解析规则见 [组织与隔离](../组织与隔离.md)。用户按中文 name 维护和选择 Function、Schema 和 Enum，内部定义引用使用稳定 ID；输入输出按中文参数名编辑，再映射已声明的运行器参数键。运行身份、制品读取及数据访问固定在已验证的租户上下文内，下文内部清单不要求用户手填 ID。

## 2. 定义与运行清单

### 首批Python运行协议（2026-11-07已实现）

实际类型见[运行契约](../../contracts/execution.go)。Function正文中的可选`runtime`也用于[Action的直接源码模式](Action.md#直接源码与绑定调用2026-11-07)。本节记录先行Python协议：`language=python`，`source`为不超过64 KiB的UTF-8源码，`entrypoint`为普通Python函数名（默认示例`main`），`timeoutSeconds`为1～30秒；JavaScript和Go本轮扩展见下文。未配置可执行实现的既有定义继续可以登记；登记不表示可调用。当前只开放`sideEffects=none`，不支持第三方依赖安装、文件制品加载、用户指定镜像、联网访问或平台数据读写；未列出的语言及副作用声明明确拒绝。内联源码与`artifactRef`或`functionId`不能同时配置。

输入和输出各最多256个参数，支持string、text、longtext、uuid、int64、decimal、boolean及timestamp标量，不支持Enum引用、存储映射或复杂对象/数组参数。每次输入和输出分别受256 KiB总预算约束，不能将单字段longtext上限理解为本接口的请求预算。

源码作为所属定义的一部分，经草稿和发布更新；不要求修改或重新编译平台Go服务。已生效Function及直接源码Action允许更新runtime源码、入口和超时，输入输出签名、副作用及已绑定实现继续沿结构变更限制；未绑定Function或产物的既有纯计算定义可补充源码，Action直接源码与绑定Function两种模式不能互相切换。发布后新调用使用新实现，已开始调用保持本次源码快照；历史结果与当前定义不兼容时拒绝读取，具体规则见[执行与调度](../执行与调度.md)。每个定义仍只有一份当前态及最多一份草稿，不新增业务version或旧定义选择入口。

入口接收并返回字典，键使用当前定义声明的中文参数名。HTTP输入和输出仍用稳定属性ID，由Execution按本次定义快照映射，用户不填写ID。未声明键、类型不符、缺少必填值或非法空值明确失败；int64、decimal仍以字符串无损传输，代码需自行使用`int`或标准库`decimal.Decimal`计算并转换回字符串。参数中文名变更不会自动改写Python源码中的字符串引用，作者须同步检查源码；已有绑定Action时还须保持双方签名一致。以下为用户代码示例：

```python
def main(inputs):
    return {"字符数": str(len(inputs["正文"]))}
```

运行器使用部署方配置的Python 3.12镜像，启动时解析为实际本地镜像ID后执行；请求不能指定镜像、Docker参数或宿主命令。每次调用使用独立容器、非root用户、只读根文件系统和有限临时目录，关闭网络、移除Linux capabilities，限制CPU、内存、进程数及时间；不挂载宿主目录，不传入平台数据库或服务凭据，不降级到宿主Python。容器限制属于本地开发与受控代码的首批隔离措施，不据此认证恶意多租户代码沙盒或生产隔离。

2026-11-08安全加固代码另将默认执行模式设为 `sandbox`（`ONTOLOGY_EXECUTION_ISOLATION` 留空时同样适用），要求专用rootless Docker、已登记runsc及cgroup v2 CPU/内存/PID预算。就绪和实际调用均检查条件，每次创建显式选择 `--runtime=runsc`；缺少条件明确不可用，不回退runc。仅受控本地开发可显式选择 `trusted` 使用既有Docker，开发脚本和真实容器测试显式采用该模式。未知模式拒绝；检查通过只表明部署条件满足，不代表恶意代码隔离或生产安全已验收。运维准备及现网发布状态见[部署与运维](../部署与运维.md#后续安全加固代码尚未部署)。

标准输出、标准错误和异常堆栈不作为公共结果返回；只接受受限JSON输出并按声明类型再次校验。容器中的Python print不构成业务结果。代码摘要、实际镜像ID和本次定义快照由Execution保存用于核对；结果、重试和清理规则以[执行与调度](../执行与调度.md)为准。工作台分别提供当前定义运行与下文已保存草稿试运行，二者不互相替换代码。

### 独立源码编辑（2026-11-07用户确认）

Function与直接源码Action分别在自己的定义编辑页维护源码，编辑一个定义不修改另一个定义。Action仍可选择绑定已生效Function，绑定模式沿用被引用函数的实现，不产生一份可独立修改的复制源码；两种模式的约束见[Action](Action.md#直接源码与绑定调用2026-11-07)。

源码区使用本地CodeMirror Python编辑器，提供语法高亮、行号、自动缩进、括号补齐、撤销/重做及自动补全；`Ctrl+Space`可主动打开候选。补全包含Python常用语法、内建函数及当前定义声明的中文输入/输出参数，参数变化后更新候选；只有显式编辑才改变源码，参数改名不会自动改写已有字符串引用。补全基于浏览器本地语法与参数声明，不提供服务端Python环境的类型推导、第三方包分析或语言服务器。

源码、入口与超时一起保存草稿并发布，“运行当前定义”始终读取服务器当前生效定义。保存、发布或恢复结果尚未确认时，编辑器与同页表单一起禁用；浏览器重新载入服务端内容时同步更新源码。JavaScript和Go接入后的共同编辑边界见下文，不把仅完成高亮等同于运行器已就绪。

### Python调试与草稿试运行（2026-11-08已确认）

本批按用户确认补齐语法错误标记、行列定位、代码格式化、参数改名后的源码引用提醒，以及已保存草稿试运行和常用测试样例。实现和分项验证状态统一见[项目总览](../项目总览.md#当前实现与验证2026-11-06)。

语法检查与格式化使用固定`@astral-sh/ruff-wasm-web@0.17.4`，在浏览器Worker中本地解析Python源码，目标语法为Python 3.12；WASM构建产物约10.1 MB，gzip约3.76 MB，静态资源随前端构建提供，在第一次检查时按需加载，不从外部CDN取代码。工具不执行用户代码，不请求宿主Python，也不安装用户依赖。格式化采用88列、4空格缩进、LF换行并保留引号风格，保留注释和字符串语义，不重排导入或自动修复规则；源码不合法时保留原文并提示诊断。格式化是可撤销的显式编辑，需要保存草稿后才用于草稿试运行。编辑器工具的语法判断不替代容器中实际Python 3.12的执行校验；语言环境、导入模块、运行时类型及业务结果仍以Execution为准。工具加载或处理失败可重试，不伪报已通过检查，过期的检查和格式化响应不能覆盖新编辑。

本次页面编辑期间的输入、输出改名按稳定参数ID识别；编辑器提示源码中仍引用的旧中文名称及所在行，由作者确认修改，不自动全局替换字符串或改写程序逻辑。该提示辅助检查直接字符串引用，不保存跨页面的参数名称历史，不承诺覆盖动态拼接、别名、反射或所有执行路径。

“试运行草稿”只执行服务端已保存的草稿，未保存的编辑必须先保存。调用携带该草稿的`draftEtag`，服务端按稳定定义ID读取并精确匹配；不接收任意客户端定义或源码替换。试运行保持独立执行记录，受同样的输入输出、超时、容器隔离及纯计算限制，不发布草稿、不替换当前定义；此后的普通调用继续使用当前代码。绑定Action的草稿试运行使用被引用Function的当前生效实现，不隐式选择其草稿。权限和结果可读边界分别引用[权限设计](../权限/权限设计.md#草稿试运行与测试样例2026-11-08)和[执行与调度](../执行与调度.md#草稿试运行2026-11-08)。

Function与Action正文可选保存`testCases`，每项为`{id,name,input}`，`input`使用该定义输入参数的稳定ID；工作台按中文参数填写。最多10项，总JSON不超过64 KiB，名称最多80个Unicode字符且在该定义内唯一。样例允许部分输入，运行时仍执行必填、默认值、空值和声明约束检查；只接受已声明输入ID及对应标量传输类型，int64/decimal继续使用字符串。样例随定义草稿保存、随发布成为当前定义的一部分，按定义读写权限共享，不是用户私有数据，也不写入浏览器localStorage；样例输入不会自动运行或变成Python默认参数。

Execution可返回受控的源码诊断，字段为`code`、固定公共`message`、从1开始的`line`及可选`column`、`endLine`、`endColumn`。语法诊断列号按Python的Unicode码点计数，不按UTF-8字节或浏览器UTF-16索引计数；运行异常仅定位源码行。坐标须在本次源码范围内，语法和运行失败均不返回原始异常文本、堆栈、源码片段、文件路径、标准输出或标准错误。具体响应仍以[运行契约](../../contracts/execution.go)为准。

### JavaScript与Go扩展（2026-11-08已确认）

用户要求将JavaScript与Go同时加入Function和直接源码Action，包含各语言源码编辑、语法高亮、自动补全，以及当前态和已保存草稿执行。本节维护本轮已实现的源码与运行器协议；前端、真实容器、跨服务HTTP及文档验证分别记录在项目总览，不以语言下拉选项代替执行结果。实际协议以[运行契约](../../contracts/execution.go)和服务说明为准。

已确认沿用`runtime.source`、`entrypoint`、`timeoutSeconds`及唯一当前态/草稿流程；语言标识为`python`、`javascript`、`go`，不把`js`作为静默别名或退回Python。源码继续限制为64 KiB，超时为1～30秒；API须显式提供合法入口和超时，不从源码自动发现入口。入口名为1～64字符的ASCII普通函数标识，不能以双下划线开头或使用所选语言的保留名称；入口接收并返回中文参数名为键的JSON对象，HTTP与测试样例继续绑定稳定参数ID，int64和decimal必须使用字符串。新增语言不开放平台数据访问、联网、第三方依赖安装、任意镜像或外部副作用，绑定Action仍使用被引用Function的当前实现和调用权限。

JavaScript采用Node 22容器执行同步普通函数，默认入口`main`；仅提供ECMAScript内建对象及静默`console`，不开放Node模块、`require`或`process`，不接收ES模块、npm依赖或Promise结果。Go使用隔离容器内的Go 1.26.10标准工具链编译并执行单文件`package main`源码，入口签名为`func Main(inputs map[string]any) (map[string]any, error)`，默认`Main`，可使用标准库import；`main`、`init`及语言关键字不能作为入口。Go源码不调用宿主编译器，不联网解析或下载模块。两种语言与Python共用执行记录、幂等、输入输出检查、草稿ETag及结果交付复核；编译也属于受限执行，不以编译成功代替函数输出或权限验收。以下为本轮已确认的用户源码示例，实际容器执行结果单独验证：

```javascript
function main(inputs) {
  return { "字符数": String([...inputs["正文"]].length) };
}
```

```go
package main

import (
    "strconv"
    "unicode/utf8"
)

func Main(inputs map[string]any) (map[string]any, error) {
    return map[string]any{"字符数": strconv.Itoa(utf8.RuneCountInString(inputs["正文"].(string)))}, nil
}
```

输出按公共标量协议检查，不能利用JSON序列化将非有限数值、BigInt、undefined、函数或Promise静默转换成另一种业务值。Go入口返回非nil错误或任一语言抛出异常时，公共结果只包含受控错误与合法源码坐标，不返回原错误消息、堆栈、源码或编译器完整输出。

镜像只由部署方配置：`ONTOLOGY_PYTHON_IMAGE`沿用Python镜像，`ONTOLOGY_JAVASCRIPT_IMAGE`默认`node:22-alpine`，`ONTOLOGY_GO_IMAGE`默认管理员构建的`agentforge-go:1.26.10`。Go专用镜像包含可信启动器和只读预热标准库缓存，每次编译将缓存复制到本次独立临时目录，不跨调用共享可写缓存；构建和使用步骤唯一见[Execution服务](../../services/execution/README.md)。请求不自动拉取镜像。能力接口按实际可用语言报告，单一镜像不可用时明确拒绝该语言请求，不阻断已就绪语言，也不退回另一种实现。

已确认按语言设置固定预算：Python和JavaScript为1 CPU、128 MiB内存、64个进程/线程及8 MiB不可执行tmpfs；Go编译执行为1 CPU、768 MiB内存、128个进程/线程及384 MiB可执行tmpfs。Go临时目录允许执行本次编译的二进制，其根文件系统仍只读，容器仍非root、无宿主挂载和平台凭据、网络关闭。工作台模板初始超时为Python/JavaScript 5秒、Go 30秒，编译、缓存准备和用户计算共用本次配置时限；不因编译消耗时间而额外延长用户运行。资源与工具最终实测结果见项目总览，以上限制不表示生产恶意代码隔离验收。

编辑器切换语言时必须保留或明确确认替换已有源码，不能直接用另一语言模板覆盖用户代码。三种语言都提供对应语法高亮、基础语法/局部变量及中文参数键补全；这些候选来自本地语法和声明，不承诺完整类型推导或第三方包语言服务器。改名提醒继续只检查本次页面内的字面量参数引用，不自动重写程序。

Python保留上文Ruff工具；JavaScript使用本地Worker中的`prettier@3.9.10`及其Babel/estree解析器进行语法检查和保留注释的格式化，不eval用户源码。Go本地CodeMirror只提供语法辅助提示，显式“检查语法”和“格式化代码”使用Execution容器内的Go标准库`go/parser`与`go/format`，格式化与`gofmt`同源，不将编辑器语法树当作Go编译结果。工具仅解析/格式化，不执行用户函数；类型、导入是否存在、入口签名和业务输出须通过实际试运行验证。

Go工具协议为`POST /execution/source-tools`，请求`{definitionId,operation,runtime}`，`operation`为`check`或`format`，返回`{source,diagnostics}`。工具要求已存在的同租户Function或Action，从Metadata核实真实类型并要求当前`definition.edit`；新定义先保存草稿建立稳定ID，再使用Go检查和格式化。不要求invoke资格，不能以工具接口执行程序；工具不保存或发布源码，不生成执行记录，与执行共用并发槽位，使用10秒固定时限及64 KiB源码预算，不由请求的函数超时延长。公共机制及资格以[权限设计](../权限/权限设计.md#多语言源码工具2026-11-08)为唯一来源。

各语言公共诊断统一为从1开始的源码行及Unicode码点列；运行器须将Node或Go工具的内部坐标规范化后才公开。诊断只定位对应源码快照，过期检查、更换语言或新编辑后的结果不得覆盖当前代码。原始工具错误、进程输出和容器路径不作为源码工具结果返回；失败保留原文，不伪报格式化或校验已通过。

输入输出复用 [Schema](Schema.md) 的属性语义和 [Enum](Enum.md) 引用。计量参数采用受控单位及明确转换规则，不能将单位不同的裸数直接传入计算。多语言调用同样需要 int64、decimal、时间、二进制的无损表示。

Schema 计算属性的轻量公式使用受限表达式，由 Data 查询/写入计划批量执行；计算策略及依赖规则见 [Schema](Schema.md)。复杂计算可显式引用纯 Function 用于后台物化，但不能在 Data 的查询中按每行远程调用 Function，也不能在同步写事务中运行任意脚本。可物化函数的输入依赖、权限范围及确定性必须可验证，更新实现时检查并失效所有依赖结果；外部数据、当前时间及随机结果不能伪装成仅由声明字段决定的值。

## 4. 调用流程与接口边界

直接 invoke、仅供指定 Action 内部调用、原调用者/运行身份及输入输出权限的候选规则统一见[权限设计](../权限/权限设计.md)第 7 节。获准调用不自动授予函数全部数据访问能力，sideEffects 声明也不替代受限凭据和实际隔离；相关后续验收引用 AUTH-04、AUTH-07～AUTH-09、AUTH-14。

建议流程：按中文名称选择并绑定 ID → 按 ID 读取当前定义 → 验证调用权限和输入类型/单位 → 提交任务 → 实际开始时解析当前定义及依赖并重新校验 → 保存本次执行内容及制品摘要 → 运行、校验输出并保存结果。已绑定调用沿用原 ID 并检查当前状态，不按旧中文文本重新选取同名定义。

完整方案建议Function与Action支持同步和异步调用，共用权限、任务及重试语义；当前仅开放上文同步纯计算。同步等待预算不以100 ms为统一分界；首批HTTP请求取消会中止容器，后续限时等待及后台任务的取消语义须单独落实。结果核对、通知、取消与错误状态统一见[执行与调度](../执行与调度.md)，本模块不再维护另一套任务状态机。

定义模块提供注册/编辑草稿、读取当前定义、检查依赖及清单、变更影响分析能力；调用与任务查询由 Execution 的公共接口提供。新增运行器不应修改 Data 查询模块，新增计算函数不应修改通用 API 入口中的类型分支。

## 5. 当前定义、实现更新与依赖

Function、Action 及输入输出引用的 Schema/Enum 均按稳定 ID 解析当前定义，不维护版本发布集。运行时和依赖软件版本仍作为环境信息保存，制品用内容摘要定位。每次更新替换当前函数定义，检查所有 Action 引用、订阅、周期规则及参数约束。
