# Schema：双向建模、计算属性、索引与预览

状态：模块说明草案，尚未实现；标准调研日期为 2026-10-17，需求更新日期为 2026-10-18。双向建模、索引定义、预览及计算属性为已明确要求；计算策略和具体协议为候选方案，性能尚未实测。本文统一维护 Schema 的用途、建模方向、计算属性、索引、预览、类型、约束、单位、读取方式和验收。

## 1. 用途与边界

Schema 定义实体及属性，描述稳定标识、键、类型、约束和可供客户端/Agent 理解的语义。Metadata 的 schema 模块拥有定义，Data 拥有实例；每个 Schema 只有一份当前生效定义，不提供业务 version，每次新读写按当前定义校验。

Schema 归属租户、分类、分组，展示名与稳定 ID 分开，分类内统一检查五类定义重名；公共规则见 [组织与隔离](../组织与隔离.md)。数据库表名、属性协议键、展示名和内部 ID 分别保存，不能相互替代。

枚举值引用 [Enum](Enum.md)，实体关联由 [Link](Link.md) 定义；[Function](Function.md) 与 [Action](Action.md) 的输入输出复用属性语义。JSON Schema 可承担部分输入输出校验，不能单独替代关系、发布和执行模型，首期不要求完整 RDF/OWL 推理。

## 2. 建模方向与预览

Schema 必须声明 `mode`，取值为 `db_2_schema` 或 `schema_2_db`。二者共用逻辑类型、稳定 ID、索引描述和当前定义生效机制，区别在于物理结构的权威来源及是否由平台管理 DDL，不是自动互相覆盖的双向同步。

| 模式 | 权威来源与流程 | 生效边界 |
| --- | --- | --- |
| db_2_schema | 已有数据库 → 读取目录 → 选择表/字段 → 预览候选 Schema → 保存草稿 → 校验并发布映射 | 读取源结构并建立逻辑映射；不新建、修改或删除源库表及索引 |
| schema_2_db | 新建或编辑 Schema → 预览目标结构、差异与 SQL → 保存草稿及迁移计划 → 执行迁移和验证 → 替换当前定义 | 按已校验的迁移计划创建或调整平台管理的目标结构；保存草稿不执行 DDL |

### db_2_schema：从数据库反向建模

数据源由租户授权，连接凭据不写进 Schema 正文。Data 通过统一存储引擎读取允许访问的 catalog/database、数据库 schema、表、列、类型、精度、主键、唯一约束、可空、默认值、注释和索引，返回结构快照及摘要；Metadata 将快照转换为候选 Schema，用户选择归属和补充业务语义后保存草稿。

建议以 `storageBinding` 保存 dataSourceId、源库/数据库 schema、物理表和字段/索引映射；数据库 schema 与本项目 Schema 是不同概念。源库目录名、表名、列名和索引名保留原值及方言大小写语义，平台展示名可另行修改。扫描获得的物理主键不是 Schema 定义 ID；属性和索引首次导入生成内部 ID，重复导入通过已有映射对齐，不能每次重新创建对象。

目录信息不能可靠推断量类型、单位、Enum 业务含义或 Action；注释和外键只能提供补全建议。外键可生成待确认的 Link 建议，不自动创建关系定义或绕过分类内名称校验。数据库默认表达式等保留源表达及适配状态，不在应用中任意执行。不支持或未解析的类型、索引特性必须逐项显示；不能作为可正常运行的映射直接激活。

反向发现和结构预览只读目录，默认不读取业务数据。无可靠主键的表、视图、生成列和复合主键必须说明可用操作及限制，不能虚构主键后宣称可写；无法建立稳定实例标识时阻止需要该标识的操作。

重复发现用于比较源结构与当前映射，候选映射先保存在草稿，校验生效后替换当前定义。源库发生删列、类型/索引变化时显示结构漂移并暂停不安全的操作；平台不静默同步，也不反向修改源库。发现仅使用目录读取权限；后续是否允许实例写入须另行授予数据源和操作权限，不因导入成功自动获得写权限。租户数据范围按 [组织与隔离](../组织与隔离.md) 校验。

### schema_2_db：从 Schema 生效到数据库

用户先定义属性、主键、约束和索引，再选择租户授权的目标数据源。Data 根据逻辑定义、目标数据库能力及当前结构生成物理映射、差异和迁移计划，通过统一引擎编译为该数据库的 DDL；Metadata 校验通过后，沿用 [发布与迁移](../发布与迁移.md) 执行、验证及激活。

表、列和索引物理名从稳定 ID 的受控映射产生，处理方言长度限制及冲突，不直接使用展示名拼接 SQL。首次生效可建表，后续修改基于当前结构生成变更；展示改名或换组不自动更名物理对象。若目标已有未纳管的同名表，必须报告冲突，不能直接接管或覆盖。

删字段、缩小类型、增加唯一约束、调整主键或索引会显示数据验证、回填、锁表及可恢复性要求。数据库是否支持事务 DDL、在线建索引等按具体版本声明，不能把生成了 SQL 视为已经安全生效。mode 和 storageBinding 属于当前定义，已有数据的模式切换或重新绑定必须显式评估及迁移，不允许通过改一个字段自动接管源库。不兼容变更先暂停相关读写并排空运行任务，不保留可供旧调用方选择的旧 Schema。

### 预览

两种模式均提供独立预览能力，未保存草稿也可预览。预览与实际发布复用相同的类型映射、索引校验、差异分析及计划编译，不另写一套示意 SQL。

| 预览内容 | db_2_schema | schema_2_db |
| --- | --- | --- |
| 模型结构 | 展示源表到候选 Schema 的字段、类型、主键、约束、索引和映射，标明待补语义 | 展示待生效的逻辑结构及目标表、列、约束和索引映射 |
| 差异 | 展示源快照与已有映射的新增、修改、删除和漂移 | 展示草稿相对当前已发布定义及实际目标库的变化 |
| SQL 与执行影响 | 可展示适配器可读取或还原的源结构 SQL，并注明仅供查看；不生成修改源库的执行计划 | 展示目标方言的建表/变更/建索引 SQL、步骤、前置条件、验证、风险和不支持项 |
| 校验结果 | 名称/归属冲突、源类型及索引特性丢失、主键和权限限制 | 类型/索引能力、现有数据约束、物理名冲突、迁移及激活阻塞原因 |

预览返回候选结构、差异、映射、诊断及是否可进入发布；输入、能力和结构快照不足时标为未完成校验，不能返回可执行结论。结构预览不要求渲染为某一种图形，接口需提供前端可展示的结构化数据，SQL 是其中一部分。

预览不保存或激活 Schema，不执行 DDL、回填、数据写入或 Action/Function；可按租户记录预览审计及候选计划。查看源结构 SQL 不承诺逐字还原厂商原始建表语句。样例数据若作为扩展预览，必须单独请求并校验实例读取权限、租户过滤、脱敏、行数及时间预算，默认不读取。

预览关联草稿内容摘要、当前定义及依赖摘要、目标数据源及实际结构摘要、驱动能力信息。相关内容发生变化后，旧预览失效。实际生效重新检查前置条件，在受控迁移协调下执行已校验计划；阻止使用过期预览直接生效，也不执行客户端回传或手工修改的任意 SQL。外部并发 DDL 无法被平台锁覆盖时，应在维护窗口或已认证的协调机制下执行。

建议能力接口包括：Data 的 `inspect`（只读目录及结构快照）与计划编译接口，Metadata 的 `preview`（候选定义、差异及诊断）、草稿保存与发布接口。具体 HTTP 路由待定；执行 DDL 仍由 Data 的迁移入口承担。

## 3. 字段、类型、索引与校验

Schema 需要覆盖常见数据库类型，并描述主键、业务唯一键、可空性、必填、默认值、校验条件和索引。类型必须区分整数范围、数值精度、时间语义，以及 `false`、`null` 和字段缺失。适配器明确标注原生支持、转换支持或不支持，不能静默截断、丢失精度或改变语义。

建议先定义数据库无关的逻辑类型，再由适配器映射为物理类型。

| 类型组 | 建议逻辑类型 | 设计要点 |
| --- | --- | --- |
| 文本 | string、text | 长度、字符集和排序规则 |
| 整数 | int16、int32、int64 | 范围及有无符号能力差异 |
| 数值 | float32、float64、decimal | 精确值使用 decimal，定义精度与小数位 |
| 布尔 | boolean | 区分 false、null 和字段缺失 |
| 时间 | date、time、datetime、timestamp | 时区、精度和时间点语义 |
| 标识与二进制 | uuid、binary | 数据库支持程度与编码 |
| 结构化值 | json | 校验方式及可查询范围 |
| 约束值 | enum 引用 | 值的稳定标识及变更兼容性 |

每个适配器声明原生支持、转换支持或不支持，数据库版本也是能力判断的一部分。数组、空间及专有类型通过能力声明扩展。HTTP/JSON 的 int64、decimal、时间、二进制编码仍需在接口契约中确定，并验证往返无损；不能依赖客户端默认数字或日期解析保持精度。

Enum 引用、必填和可空规则分别声明；不能用显示标签替代业务值。逻辑 Schema 与物理表不必一一对应，首轮优先验证每个 Schema 的有类型实体表，按过滤/关联性能、模型数量及迁移成本决定是否采用其他布局；选型理由和统一数据库适配见 [存储引擎](../存储引擎.md)。单位/类型变化是否产生 DDL 由适配器及迁移计划决定，不能假定每次模型变更都建表。

### 索引定义

Schema 显式维护 `indexes`，至少支持普通索引、唯一索引、单字段和有序的多字段组合索引；主键通过 `primaryKey.fieldIds` 单独声明，由适配器避免重复生成主键索引。两种建模方向共用以下逻辑描述，反向导入还要保留源物理索引及能力信息。

| 字段 | 含义 |
| --- | --- |
| indexes[].id、name | Schema 内的稳定索引 ID 与展示名；物理索引名另存于映射，不使用展示名定位 |
| indexes[].unique | 是否表达业务唯一性；不能把普通加速索引当作唯一约束 |
| indexes[].fields | 有序数组，每项通过 fieldId 引用本 Schema 的稳定属性 ID，并声明 asc/desc；顺序是索引定义的一部分 |
| indexes[].method | 索引方法，例如 btree；支持情况由数据库、版本及字段类型共同决定 |
| indexes[].options | 表达式、条件、覆盖列、前缀、全文、空间等扩展选项，必须由适配器明确支持及校验，不能塞入任意 SQL |

索引字段必须存在且不能重复，索引名在当前 Schema 内唯一；被索引字段删除、类型变化或索引顺序改变时重新生成差异。普通索引与唯一约束的重复定义需检查并给出处理结果。唯一索引的 NULL、大小写、排序规则及长度限制必须声明跨库语义；新增唯一索引先校验已有数据重复，再执行实际约束，不能只靠应用查重。

共享租户表上的业务唯一约束必须包含 tenant_id；普通索引也按租户过滤及访问模式生成，逻辑索引和补充的租户列映射在预览中同时展示。租户专用表则校验映射所有权；不能为了租户约束向反向建模的既有源表静默添加列或索引。

不支持的索引特性必须显示为阻塞或待人工处理，不静默丢弃、降级成普通索引或声称保持性能。反向建模读取到专有索引时保留原始描述和未解析项；可否作为只读映射发布需明确确认能力限制，未经确认不能标记完整支持。索引的新增、变更和删除沿用发布迁移，预览需显示可能的锁、构建成本和在线能力，不能承诺不阻塞读写。

### 计算属性：策略选择

计算属性属于 properties，具有普通属性相同的稳定 ID、协议键、展示名、输出类型、精度和单位，另加 calculation 描述。其值由声明的依赖和公式产生，实例写入接口拒绝用户覆盖；虚拟值不持久化，持久化值是可重建的派生结果。原始业务字段仍是事实来源，首期不将计算属性作为主键。

建议按字段显式选择策略，不将一个 Schema 的所有计算属性统一存储，也不根据一次请求自动改变存储策略。

| calculation.strategy | 计算与保存方式 | 优先适用 | 代价与一致性 |
| --- | --- | --- | --- |
| virtual | 查询时按需计算，不保存业务结果 | 同实例的轻量四则运算、条件、字符串组合，以及仅用于页面展示的属性 | 没有派生写入和重建成本；读取频繁或大范围筛选时增加计算，结果反映本次查询的数据快照 |
| stored_sync | 依赖变化时，在同一实例写事务内计算并保存 | 同实例、确定且廉价，经常读取、筛选、排序或需要索引的公式 | 读成本低，提交后与基础字段一致；增加写入、索引和锁成本，要求所有写入口受控 |
| stored_async | 源变化持久化后合并刷新任务，后台计算并保存 | 跨 Link 的汇总、高扇出依赖、复杂算法，以及允许延迟的指标 | 隔离前台写入，但存在刷新积压和旧值窗口；需事件、状态、重算及核对机制 |

默认建议 virtual；若同实例字段是高频筛选、排序条件，或反复读取的计算成本明显较高，再显式选择 stored_sync。关联汇总优先评估 stored_async，但须明确接受数据延迟；强实时且不适合物化的关联查询可使用有预算的数据库 JOIN/聚合。stored_async 是候选扩展，首期先打通 virtual 和受控同实例 stored_sync，不默认实现任意依赖的分布式实时更新。

例如 `功率 = 电压 × 电流` 的每行计算很便宜，少量展示用 virtual 即可；若经常按功率范围筛选、排序并翻页，保存同事务计算结果并建索引通常更合适。`设备维护总费用 = SUM(关联工单费用)` 涉及工单新增、费用修改、删除和关联变更，适合后台物化或有界聚合，不能只监听设备自身的更新。

选型同时看读取涉及的行数、依赖写频率、公式成本、索引需求和平均/最大影响范围。读侧工作量约为“实际参与展示/筛选/排序的行数 × 单次公式成本”；写侧约为“依赖变更次数 × 受影响对象数 × 单次重算成本”，再加索引、事件和存储维护。只统计接口 QPS 不足以判断，异步本身也不减少总工作量，合并重复刷新和经过验证的增量算法才能减少重算。

### 公式、依赖与类型

建议 calculation 包含 strategy、expression，以及异步字段的刷新目标和读取旧值策略。expression 使用可解析且有类型的受限表达式树；字段和 Link 使用稳定 ID 引用，名称只用于编辑器展示。依赖集合由编译器从表达式提取，不能仅相信用户手填的依赖列表。

下面是一个计算属性片段，引用的电压、电流字段需已在同一 Schema 中定义，且分别声明 V、A 单位；示例协议尚未定稿。

```json
{
  "id": "9a915f48-9f49-4743-bdc3-7420db9da571",
  "name": "直流功率",
  "dataType": "decimal",
  "precision": 18,
  "scale": 3,
  "readOnly": true,
  "quantityKind": "power",
  "unit": {"system": "UCUM", "code": "W"},
  "calculation": {
    "strategy": "stored_sync",
    "expression": {
      "op": "multiply",
      "args": [
        {"fieldId": "e3c97511-af17-4e34-ae16-fc724c08f415"},
        {"fieldId": "0bd8dfd4-95f6-464e-a801-313d929df8b6"}
      ]
    }
  }
}
```

首期表达式支持经过实现验证的纯运算与白名单内置函数，不包含任意 SQL、网络请求、数据库查询脚本、随机数、隐式当前时间或有副作用调用。每次查询读取当前时间的“设备运行时长”不能仅靠源字段更新维护，须选择查询时显式时间参数或另行声明周期刷新。涉及外部服务、用户脚本或复杂算法时，可显式引用纯计算 Function 并作为后台物化任务执行，不在查询中逐行调用 Execution，也不在 Data 写事务中执行任意语言代码。Function 更新需失效依赖物化值，其源码读取了未声明外部数据时不能承诺自动更新或确定性。

生效时建立以 Schema/字段/Link ID 为节点的依赖图，检查悬空引用、循环、最大依赖深度及跨租户访问，确定计算顺序。同实例依赖只重算本次变动字段的后继，未请求的 virtual 字段不计算。stored_sync 的全部传递依赖必须可在本事务内确定，不能依赖 stored_async 旧值或外部资源后仍声明同步一致。

跨实体标量引用须校验 Link 基数，1:N/N:M 必须声明 SUM/COUNT 等聚合及去重含义，明确关系属性与实体去重，不能把任意首条关联当作标量。输入的空值、缺失、除零、溢出、decimal 舍入、空集合和错误行为都要固定，不能跨数据库静默改变。同步计算错误默认拒绝该次业务写入并回滚，异步错误保存错误状态，virtual 返回声明的字段错误或查询错误，不能伪造 0。金额等场景使用明确精度和舍入的 decimal，输出单位需通过支持的类型/物理量规则校验。

计算属性的读取权限覆盖其全部依赖及必要关联范围，隐藏字段不能通过计算结果泄漏。全局共享物化结果的业务含义及输入权限范围必须固定；若结果取决于调用者身份或动态行级权限，首期拒绝作为共享物化属性，使用按调用者授权的受控查询。

### 查询、筛选与索引

表达式在定义生效/加载时编译，按当前定义内容及后端能力缓存计划，运行时只绑定参数。可统一语义的表达式优先编译进 SQL，按需投影，避免每行解析或跨服务调用。原始字段上的索引过滤先下推，减小参与计算的候选集合。

只有输出展示所需的 virtual 字段可在数据库完成合法筛选、排序和分页后，对当前页做批量应用内计算。若查询条件、排序、聚合或分页依赖该计算字段，就必须在数据库的正确阶段计算，或使用已物化且有匹配索引的列；适配器不支持且超出执行预算时拒绝，不能先分页再按计算值过滤/排序，也不能拉全表到内存完成。

virtual 不默认可建普通列索引，表达式/函数索引及数据库生成列作为逐后端认证的优化，预览明确展示。stored_sync 可按普通持久列设计索引；stored_async 可建立普通加速索引，但筛选、排序和聚合只能表达已物化快照，响应标明刷新边界及缺失/错误项。要求当前精确筛选时，需对完整候选集合执行受控的当前计算，或等待刷新/拒绝，不能只重算已经被旧值筛出的结果，也不能悄悄排除尚未刷新的对象。

首期不允许 stored_async 参与业务唯一键、必填硬约束或强一致状态判断；stored_sync 的唯一约束仍须由数据库真实约束及租户键保证，不能把计算服务查重当作约束。

### 自动更新与异步刷新

stored_sync 必须覆盖创建、修改、批量导入、Action 写入等所有 Data 写入口。取修改后的完整依赖状态，按依赖顺序计算，基础值、派生值、索引及 outbox 在同一本地事务提交；并发更新通过锁或条件写入防止丢失计算结果。不变依赖不重算，异步任务不能再修改这些同步派生列。若存在绕过 Data 的写入，应由已验证的数据库生成列等覆盖，或明确拒绝同步一致性的承诺。

stored_async 的依赖变更覆盖字段新增/修改/清空、实体删除、Link 新增/删除/改端点、过滤条件变化及公式/Function 更新。移动一条工单关联需要刷新原设备和新设备。平台本地变更与待发事件/失效登记同事务，由 Data 的反向依赖索引定位目标；大扇出先登记有界扫描的影响范围，分页派发，不把百万个下游刷新塞入前台事务。未枚举完的范围仍视为待刷新，不能因单行状态暂未标记就宣称新鲜。

按 tenant_id、目标 Schema/实例/字段合并刷新请求，批量读取并重算当前源事实及当前公式。初期优先重算受影响目标，SUM/COUNT 增量维护仅在重复、乱序、删除、回补及并发均有明确处理时采用；不能直接把至少一次投递的每个事件当作一次加减。事件分派复用 [执行与调度](../执行与调度.md)，派生结果写回必须经过 Data 的专用接口，不能由 Worker 直写私有表。

结果写回需验证计算期间源变更标记、失效范围、当前公式摘要及尝试标识未变化，并与失效状态清理原子完成；不满足则丢弃该次结果并保留刷新请求，旧任务不能覆盖新值或误清除后续待办。跨实体源状态无法原子核对时，只承诺明确水位的最终一致，不标记为强一致。内容摘要和源变更标记仅用于内部竞争校验，不恢复业务 version 或可选择旧公式的接口。

异步结果保存值、computedAt、公式摘要、源处理水位和 pending/ready/error 等状态。允许旧值时返回这些计算状态；刷新目标超限、存在事件缺口或重算失败时按字段配置返回明确过期/错误或拒绝，不能把旧值标为当前值。computedAt 只表示计算发生时间，不能单独证明源数据已处理；源系统到变更捕获、队列再到重算的延迟全部计入新鲜度，无法证实时标记未知。以“读取时顺便同步刷新并保存”作为默认会放大请求尾延迟，首期查询不承担持久化重算，只可返回受预算控制的即时 virtual 结果或发出后台刷新请求。

### 两种建模方向、生效与预览

schema_2_db 可将 stored_sync 映射为受管理的有类型列；数据库原生生成列/表达式索引只能在三库各自验证后使用，首期不默认引入触发器及厂商物化视图。原生实现仍需覆盖依赖、精度、错误和迁移契约。

db_2_schema 的计算属性先作为逻辑扩展提供 virtual；源表已有生成列可读取其能力及表达式信息。不能为新增计算属性修改源表。需要物化时，将派生值放在 Data 管理的附属存储，以租户、Schema、源实体稳定标识、字段定位，并校验其可查询/索引能力；没有稳定主键的源无法可靠维护。外部源写入必须接入可恢复的 CDC、源 outbox 或经证明不会漏变更的同步机制，才能承诺自动刷新；普通更新时间轮询不能自动覆盖硬删除、关系移动及同时间戳写入。源写入与平台附属表不能共享本地事务时，不能选择 stored_sync。没有变更捕获时优先 virtual，定时全量核对只能提供显式延迟及成本约束下的结果。

计算属性延续单份当前定义。修改公式、依赖、类型、单位或策略前检查受影响字段/索引及已有派生数据，取消或隔离旧计算任务，旧公式摘要不匹配的结果一律拒绝。首期物化公式变更采用受影响范围维护：暂停相关操作 → 回填/校验并追平变更 → 替换当前定义及物理映射 → 恢复；失败保持可核对状态，不将旧公式结果冒充当前公式结果。virtual 的公式更新完成校验和计划失效后即可替换当前定义。完整生效流程见 [发布与迁移](../发布与迁移.md)。

预览增加依赖图、类型/单位检查、策略、SQL 或应用计算位置、存储列/索引、影响目标及重建范围、同步写放大或异步延迟说明。依赖范围过大、循环、缺失变更捕获或策略与索引不兼容时明确阻塞。试算需显式提供输入或单独授权读取少量样例，受行数和时间预算限制，不执行任意 Function、全量回填或业务写入。性能验证统一见 [性能与容量](../性能与容量.md)。

## 4. 元数据的内容和归属

调用方读取实例或查询结果后，应能确定字段代表什么、数值使用什么单位、怎样显示和校验，以及读数产生的时间、质量和来源。客户端与 Agent 无需根据字段名、表注释或预置代码猜测单位。

单位属于 Schema 中具体属性的语义。同一个 Schema 可以同时包含温度、压力、转速及无单位的状态字段。计量属性应具有明确的量类型与单位状态，普通字符串、布尔及标识属性无需强制设置单位。

信息按共享定义、测点配置、读数事实和查询结果描述四层组织，具体归属如下。

| 内容 | 建议位置 | 用途及边界 |
| --- | --- | --- |
| Schema ID、属性稳定 ID | 当前模型定义 | 重命名后仍能定位对象；语义变更需处理既有数据 |
| 属性协议键、name、labels、description、semanticId | 属性定义 | 协议键用于传输，name/labels 用于展示，semanticId 为可选外部词汇映射；引用使用稳定属性 ID |
| dataType、precision、scale、nullable、约束及 Enum 引用 | 属性定义 | 类型及输入校验；存储小数位不代表测量准确度 |
| quantityKind、measurementKind | 计量属性定义 | 物理量种类和点值/差值、绝对/相对等语义 |
| unit.system/code、单位字典引用 | 属性定义及字典 | 固定规范单位；字典保存维度和允许转换的关系，不通过业务版本选择 |
| symbol、display.fractionDigits | 展示元数据 | 本地化和显示舍入；不能作为单位唯一键或改写原值 |
| normalRange、validation；仪器量程 | 属性默认配置或测点配置 | 正常区间与硬约束分开，实际仪器量程由具体测点确定 |
| deprecated、readOnly、分类与权限引用 | 定义及治理配置 | 生命周期及访问说明；提示字段不能替代服务端权限检查 |
| 仪器量程、采样配置、连接源和校准信息 | 设备/测点配置 | 描述具体仪器及采集配置，可关联源节点和映射 ID |
| observedAt、receivedAt、quality、sourceRef | 读数或事实 | 区分事件发生与平台接收时间，保留来源和质量 |
| 原始值/单位、映射 ID 及实际换算上下文、校准及不确定度 | 来源记录、测点或读数 | 支持溯源；需要追溯的内容随事实保存，不依赖读取旧定义 |
| 返回列类型、有效单位、字段/表达式来源 | 查询结果描述 | 与本次投影、转换及聚合的实际返回值匹配；保存结果时一起保存描述 |

静态默认量程或质量协议可以由 Schema 声明，但具体设备配置和每次变化的质量、时间不能通过反复修改 Schema 保存。原始值可保存在外部时序库或归档中，以稳定引用追溯；不要求基础引擎复制全部原始时序数据。

Schema 根节点可以按 ID 引用单位字典，但具体单位必须定义在属性上。通用“测点”类型如果允许每个测点使用不同单位，应将物理量及规范单位绑定到当前测点配置，并在事实中保留解释该读数所需的实际上下文；首期优先固定属性单位，避免任意逐行覆盖。修改字典中已使用的换算规则也必须检查依赖和既有数据，不能绕过 Schema 的变更规则。

`readOnly`、默认值及展示描述的具体执行规则由平台定义。尤其不能用默认温度填补缺失观测，也不能将前端只读提示当成授权机制。

存储精度、小数位显示规则、传感器分辨率与测量不确定度分别表达。正常范围、仪器量程、硬校验和告警阈值用途不同；异常读数不能只因超出正常范围就被丢弃，告警由相应规则或测点配置维护。

## 5. 单位编码与计算规则

建议平台单位字典优先登记 UCUM 代码，并使用区分大小写的代码形式。例：`Cel` 显示为 `°C`，`kPa` 显示为 `kPa`。源系统的 UN/CEFACT 或厂商编码由适配器按代码空间映射，保存原始标识、映射 ID 及必要换算上下文。只有明确定义的等价关系才能映射，不能通过显示符号相似判断。

单位字典可关联 QUDT 的量类型、单位 URI 或其他行业语义标识。字典是 Metadata 的受控模块和可缓存数据，不必单独建立常驻微服务；热查询和读数写入不实时依赖公网标准网站。

Action/Function 输入输出参数若表示计量值，应复用同一属性描述和单位校验；调用方不能把规范单位不同的裸数直接传给计算函数。扩展 JSON Schema 时需明确自定义词汇或协议映射，不能假定通用校验器自动执行单位校验。

首期选择每个计量属性的固定规范单位；入库前将已知、允许的源单位归一化，必要时保存原始值/单位或引用。规范单位不强制采用 SI 基本单位，例如压力可统一 kPa，温度可统一 Cel。显式指定展示单位时按请求转换，但返回的数值、单位、范围和格式必须匹配。

| 情况 | 必须处理的语义 |
| --- | --- |
| 100 kPa → 0.1 MPa | 比例换算，先转换再执行对应规范单位的过滤与校验 |
| 25 Cel → 298.15 K；温差 10 °C → 10 K | 温度点包含偏移，温差没有相同偏移；不能只看单位代码 |
| 比例 0.12 → 12 % | 无量纲也可能有缩放，符号改变时数值同步转换 |
| 能量与转矩 | 即使基本量纲相同，也不能自动视为相同业务量 |
| kW 与 kWh | 功率与能量不同，转换需要时间积分等业务计算 |
| 表压与绝压 | 需要参考压力，不能只做比例换算 |
| 标准状态气体体积、dB、货币 | 分别可能依赖参考温压、参考量/对数定义、汇率与时间；不能套用通用乘除 |

“没有单位”需区分不适用、显式无量纲和未知。对外 API 可按明确契约允许省略输入单位，表示使用当前属性规范单位；单位变更前需先迁移数据并协调调用方。外部数据接入没有已知单位或映射时不能沿用这一假定。非法或未登记单位应拒绝或隔离，不能静默改标签。

换算使用经过验证的规则与明确舍入方式，先换算再校验规范值。查询过滤尽量将常量转为索引字段的规范单位，避免对每行做转换破坏索引。带偏移、舍入边界和溢出需专门验证。聚合要考虑测量语义：温度点差值产生温差，count 产生计数，量纲和单位不能盲目照抄输入列。


客户端由数值 `85.200`、显示精度 1 和符号 `°C` 显示 `85.2 °C`；计算仍使用未被显示舍入的数值。`quality` 是候选平台状态示意，接入时需明确源质量码映射，不能直接假定为 OPC UA StatusCode 原值。原始数据例如 358.350 K 可通过 `sourceRef` 查询，无需在每次结果内重复携带。

同一批采用相同定义内容和投影的结果共享一份 `fields`。跨 Schema 查询通过各列或每组结果的 Schema ID 及随结果返回的字段描述区分；字段别名、计算和展示转换后，描述必须反映实际输出语义。动态逐行单位不能伪装成同一列的固定单位，需归一化或明确逐行覆盖规则。

支持仅返回值的紧凑方式时，返回 Schema ID 及自动计算的当前描述摘要，客户端复用描述前校验摘要；摘要不用于选择旧定义，历史结果需自行保存实际字段描述。API 不承诺每次都默认展开全部元数据。缓存按 tenant_id、当前定义/字典内容摘要、权限投影、语言及展示单位等实际条件隔离并校验当前状态，不得泄露未授权字段，也不产生每行一次的 Metadata 调用。

## 8. 变更生效与实现范围

修改显示名称、描述或展示精度通常只需更新当前元数据，不重写数据。规范单位从 kPa 改为 Pa、点值改差值、物理量类型改变或换算规则纠正，必须检查历史值、索引/物化结果、阈值、默认值、过滤、运行中任务和调用方，并在迁移验证后替换当前定义。只改单位标签会造成数值误解，禁止采用。

需要由当前 Schema 读取的既有数据必须迁移到当前语义；无法转换的事实须保留自描述的实际单位、量类型和来源，或阻止该变更。迁移与维护流程见 [发布与迁移](../发布与迁移.md)，不提供旧 Schema 选择接口。展示单位变化只影响本次输出时，同步转换范围并保存与结果匹配的描述。

首期包含两种建模方向、普通/唯一及组合索引、结构/差异/SQL 预览、同实例轻量 virtual 与受控写入口的 stored_sync 计算属性、属性标签/描述、稳定标识、物理量类型、固定规范单位、受控单位字典、明确的有效范围与显示规则，以及可随查询返回的字段描述。跨 Link/复杂 Function 的 stored_async 在可靠依赖、变更捕获及刷新状态闭环后扩展。首期反向发现以授权的基础表为主，视图、专有类型和高级索引按能力显式开放。优先支持已登记的常用单位和经验证的线性/带偏移转换；不要求实现完整 UCUM 运算或全部 QUDT 本体。

读数上下文提供可扩展结构；具体时间、质量和来源字段按数据接入契约要求，缺少时标为未知，不能伪造。测点级校准、动态单位、复杂不确定度、对数单位及依赖环境的转换可后续扩展。暂不支持的转换必须明确拒绝，不能伪装为完成。

对任意查询表达式自动推导单位也不作为首期必选能力，但受支持的投影、转换及聚合必须返回正确语义；无法判断单位的计算应拒绝或返回明确的未解析状态，禁止沿用错误输入单位。

元数据归 Metadata 的 schema 模块及受控字典管理；单位转换和字段投影在 Data 的查询/适配层执行，运行参数复用相同契约。避免在通用入口累积所有类型的校验分支。

Schema 定义本身是 Metadata 的当前记录，最多附带一份待生效草稿，定义正文可保存为文档；实例字段则由 Data 为 schema_2_db 生成当前物理映射、为 db_2_schema 验证已有源映射，并交给同一存储引擎。运行时新增 Schema 不要求生成 Go ORM struct 或重新编译服务，高频过滤不得依赖加载全部实例后在应用内筛选。

| SCHEMA-07 | 异步扩展覆盖全部依赖变化、幂等合并及新鲜度 | 更新/删除/改边均定位目标；重复乱序、重算中再次写入、旧任务及失败重试不丢失待办；高扇出有界，未知水位不标新鲜 |
| SCHEMA-08 | 两种建模方向及公式替换遵守存储和当前态边界 | 无 CDC 的外部源不承诺自动刷新，源表不被增加派生列；公式变更回填后生效，旧任务拒写；预览显示依赖及重建影响 |

| SEM-02 | 单位代码包含编码体系，显示符号独立；未知、缺失、无量纲有不同语义 | Cel 能显示为 °C；区分 1 与 %；错误单位映射明确拒绝或隔离，禁止猜测 |
| SEM-03 | 查询返回与实际值、投影列匹配的字段描述 | 普通读取、字段别名、联查和转换结果均能定位单位；保存历史结果时同时保存描述，不需读取旧 Schema |
| SEM-04 | 定义、测点配置和每次读数上下文分开管理 | 设备量程变化和质量码变化不会反复修改类型定义；读数可关联时间、质量、来源与实际映射上下文 |
| SEM-05 | 单位转换验证量类型和测量语义，记录精度与失败行为 | 100 kPa 与 0.1 MPa 等价；温度点和温差使用不同转换；不能把 kW 换为 kWh 或将表压直接换绝压 |

## 10. 行业资料与方案依据

建议 Schema 属性显式保存单位及物理量语义，数据读取支持同时返回有效字段描述。行业实践共同强调机器可识别语义、展示信息和实际观测上下文的区分，但各标准的单位代码与数据结构并不统一。

| 资料 | 已核对的做法 | 对本项目的启示 |
| --- | --- | --- |
| [OPC UA Part 8：AnalogItem](https://reference.opcfoundation.org/specs/OPC-10000-8/5.3.2) | EngineeringUnits、EURange、InstrumentRange 分开表达；EURange 是正常运行范围，读数可能超出 | 单位与范围可供客户端解释读数；正常范围不能直接等同为硬校验或告警阈值 |
| [OPC UA Part 8：EUInformation](https://reference.opcfoundation.org/specs/OPC-10000-8/5.6.4) | namespaceUri、unitId、displayName、description 分开；默认映射基于 UN/CEFACT，允许其他代码体系 | 单位保存代码空间与标识，显示符号另存；接入 OPC UA 时显式映射 |
| [OPC UA Part 4：DataValue](https://reference.opcfoundation.org/specs/OPC-10000-4/7.11) | 每个值携带 statusCode、sourceTimestamp、serverTimestamp 等 | 质量及时间属于读数上下文，不能只放在共享 Schema 中 |
| [W3C WoT Thing Description 1.1 §5.3.2.1](https://www.w3.org/TR/wot-thing-description11/#dataschema) | DataSchema 包括 unit、title(s)、description(s)、默认值及访问提示；建议 unit 指向语义定义以保持唯一性 | 单位是数据描述的一部分，可为客户端和 Agent 提供一致语义 |
| [JSON Schema 2020-12 Validation §9（IETF 草案存档）](https://www.ietf.org/archive/id/draft-bhutton-json-schema-validation-01.html#section-9) | title、description、default、deprecated、readOnly/writeOnly 属于元数据注释；标准校验关键词未定义物理量单位换算 | 基础注释可以复用，单位语义需要平台扩展与明确执行规则 |
| [UCUM 规范](https://ucum.org/ucum) | 以无歧义机器通信为目标，区分单位语义与人类显示；包含特殊尺度，花括号注释不改变单位语义 | 候选采用 UCUM 机器编码；业务含义另设字段，不能依赖单位注释 |
| [QUDT Schema 3.5.2](https://qudt.org/doc/2026/09/DOC_SCHEMA-QUDT.html) | 区分 QuantityKind、Unit、QuantityValue、维度向量及转换属性；包含 conversionMultiplier/Offset、对数单位等模型 | 分开表示物理量类型、单位和数值；换算规则由受控字典维护 |

上述是标准事实；本文的 JSON、接口参数、字段名、分层和首期取舍属于本项目建议，并非这些标准的原生格式。采用语义标识不要求实现完整 RDF/OWL 系统。
