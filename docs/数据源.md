# 数据源配置

状态：2026-11-07 用户确认新增独立数据源配置菜单，支持 MySQL、PostgreSQL 等数据库；同一 Schema 的属性可来自不同数据库或表。连接协议见 [contracts/datasource.go](../contracts/datasource.go)，模型映射规则见 [Schema](模块/Schema.md#2-建模方向与预览)，分别验证的结果统一见[项目总览](项目总览.md#当前实现与验证2026-11-06)。本文维护连接配置与目录发现。

## 归属与权限

数据源属于租户，由 Data 服务持久化连接配置和加密凭据。数据源独立于业务分类，顶栏分类切换不切换租户数据源目录。平台 Metadata/Data 自身的控制表连接仍由服务端配置；新增 PostgreSQL 数据源不等于平台元数据已支持 PostgreSQL 部署。

管理员通过“数据源配置”页面维护名称、数据库类型、主机、端口、数据库、用户名、密码、TLS、租户隔离方式和启用状态；支持多个源、连接测试、目录及列结构查看。修改携带 ETag，不提供绕过并发冲突的覆盖写入。已被生效或准备中的映射引用的数据源禁止修改连接定位和隔离方式；停用后相关读取、预览及生效明确拒绝。

权限遵循[权限设计](权限/权限设计.md)：连接管理使用每次权威会话中的当前租户管理员身份；模型作者在获 `definition.edit` 授权后读取可选源及结构目录，不接收密码。租户和管理员身份不能由请求体或外部租户头指定。发现目录不等于获得模型或实例权限，运行时继续校验定义、行和列权限。

## 凭据与连接

密码只写入，响应只返回 `passwordSet`。更新省略 `password` 保留原值，显式空字符串表示清空；页面保存或离开后清除输入框内密码。密码以 AES-GCM 加密保存在 Data 控制库，密文绑定当前租户及源身份；`ONTOLOGY_DATA_SOURCE_KEY` 提供至少32字节的独立服务端密钥，需与存储一同备份并由部署机制保管。已有密文不能通过更换密钥自动恢复；缺少密钥时源操作明确拒绝，旧默认存储仍可运行。

连接使用结构化参数，不接受含任意参数的用户 DSN 或原始 SQL；MySQL 禁用多语句及参数插值，PostgreSQL 使用 pgx。TLS 可配置禁用、加密或校验主机证书。连接与目录操作有超时、数量和响应预算，错误不回显密码或完整连接串。保存配置不执行目标 DDL，普通请求和服务启动不自动迁移平台控制表。

## 数据库版本选择与校验（2026-11-07，已确认并实现）

用户已确认实施版本选择、实际版本核验和按能力放行。数据库服务器版本属于连接兼容性信息，五类业务定义仍遵循单份当前态规则。实际字段见[公共契约](../contracts/datasource.go)，公共检测及版本登记见[存储引擎](存储引擎.md#版本能力登记2026-11-07首批实现)。

### 实现范围

原实现只有 `driver`，仅连接测试返回版本文字。现在配置保存版本约束，测试返回结构化兼容诊断，所有外部物理连接通过同一适配层检查后才交给目录、查询和DDL执行。连接池重建同样核验；同一操作中新连接的产品、完整版本或关键配置与先前连接不一致时拒绝，不能因首次连通绕过检查。平台控制库在初始化时共用检测逻辑，但其用途认证独立于外部来源，不能将外部来源通过表述为该版本的平台主库认证。

版本范围覆盖当前路径所需的目录字段与SQL语义，例如PostgreSQL的 `is_generated`、`is_identity`、`indnkeyatts` 和MySQL的 `utf8mb4_0900_bin`。已登记的适配能力不授予账号权限；实际表结构、唯一键、租户隔离及账号可执行性仍由对应操作检查。

### 配置与页面

数据源表单在“数据库类型”后增加“数据库版本”：默认“自动识别”，也可选择服务端登记的明确版本系列。MySQL 按发布系列区分，PostgreSQL 按主版本区分；实际可选范围和允许补丁范围统一由[存储引擎的版本能力登记](存储引擎.md#版本能力登记2026-11-07首批实现)提供。待适配系列显示但禁用，完整补丁版本由服务端检测和展示。指定系列是实际服务器约束，不是强制套用方言的开关。

| 信息 | 实际字段 | 来源与用途 |
| --- | --- | --- |
| 版本选择方式 | `versionPolicy = auto / pinned` | 管理员选择；自动识别也必须命中已登记的适配范围 |
| 预期版本系列 | `expectedVersionLine` | 指定版本时必填；是实际服务器版本约束，不是强制套用旧方言的开关 |
| 实际产品与完整版本 | `compatibility.detectedProduct`、`serverVersion` | 服务端只读检测；不接受客户端提交为可信事实 |
| 兼容状态与能力 | `compatibility.compatibilityStatus`、`capabilityProfile`、`capabilities` | 状态为supported/unsupported/mismatch/failed；范围含目录、读取、查询、建表、加列及索引，不能替代操作权限 |
| 最近检查 | `compatibility.checkedAt`、`connected`、`code`、`message` | 记录检测时间、网络连通及公开原因；旧记录没有compatibility时显示待检测 |

列表及详情展示实际版本和兼容状态，详情另给最近检查及版本适配范围；未检测显示“待检测”。已连接但版本不匹配或不支持时不能显示成功。模型作者的可选源摘要移除完整服务器标识、主机、账号及诊断文本，保留版本系列和适配能力。

### 测试、保存与运行

1. 测试返回 `success`、`serverVersion` 和 `compatibility`，分开报告网络连通与兼容状态。连接/版本检查失败返回HTTP 200且 `success=false`，便于管理员查看实际版本及原因；身份、请求格式和ETag错误继续使用相应HTTP错误。测试不建业务表，兼容协议产品单独适配。
2. 启用状态保存时由服务端重新连接检查，不能提交客户端“测试通过”标记放行；失败不替换旧配置。停用状态允许离线保存，不保留旧检查。页面的“测试当前配置”对已有源提交完整表单及 `If-Match`，密码省略复用当前租户该来源的服务端密码，显式空串测试清空密码；这个测试不保存表单或覆盖已保存检查。
3. 已保存源的空体/JSON null测试保留原协议：停用时409拒绝；启用时将检查结果写入原 `config_json.compatibility`，以租户/来源ID及配置ETag条件更新，不改变配置ETag，检测期间配置已改变则412。保存产生的新ETag绑定本次检查和加密凭据；观察刷新不能恢复旧凭据或覆盖新配置。无需新增平台表或隐式迁移。
4. 目录发现、Schema预览/发布、实例读取、Link查询及显式离线维护均经同一连接检查。运行时以当前连接检测为准，最近保存/测试记录不作为放行凭据；签名只在服务内部参与执行，不作为客户端可信事实。
5. 产品、完整版本或关键配置改变会改变结构与查询指纹，使旧查询/Link分页游标失效。当前预览不保存可执行客户端SQL，发布重读目录并重新编译检查；不会沿用升级前预览执行。数据库升级不触发自动迁移、重建或模型重绑。尚无通用跨请求编译缓存可供失效验收。

### 现有配置与实施顺序

旧数据源缺少新增字段时按“自动识别、尚未检测”读取，不批量改写现有配置，不虚构已通过检查；使用前实际检测并匹配登记范围。本机MySQL 26.7.0、PostgreSQL 17.11的目录、映射和主表能力已有本轮真实回归。其余版本逐个认证，不按更大版本号自动继承支持。

公共适配能力、认证矩阵及尚未开放的系列只在[存储引擎](存储引擎.md#版本能力登记2026-11-07首批实现)维护；MySQL 5.7仍属于有明确需求时的独立兼容工作。版本功能验证与额外数据库版本认证分别记录，不将页面可选或单元测试通过等同于所有后端验收。

## 租户数据归属

| 方式 | 规则 |
| --- | --- |
| `column`（默认） | 数据库可共享；主表及每个关联来源表均须指定租户列，所有读取绑定当前租户，关联键在租户范围内唯一 |
| `dedicated` | 管理员声明数据库专属于当前租户，允许不配置租户列；其他租户不能登记相同规范连接定位为共享来源 |

连接定位按驱动、规范主机、端口和数据库登记并受并发锁保护。DNS 别名、代理后端和外部数据库授权无法仅由字符串目录证明，专属数据库的实际归属仍由管理员和数据库权限保证。

## 目录接口

| HTTP 接口 | 行为 |
| --- | --- |
| `GET /data/sources` | 管理员读取当前租户配置，不含密码 |
| `GET /data/sources?view=select` | 模型作者读取可选源摘要 |
| `GET /data/source-versions` | 管理员或模型作者读取服务端版本系列及supported/pending状态，不探测数据库 |
| `POST /data/sources`、`PUT /data/sources/{id}` | 创建或以 If-Match 修改配置 |
| `GET /data/sources/{id}` | 读取当前租户单个配置 |
| `POST /data/sources/test` | 测试尚未保存的连接参数 |
| `POST /data/sources/{id}/test` | 空体/null测试已保存配置；完整DataSourceInput及If-Match测试当前表单，省略密码复用服务端值 |
| `GET /data/sources/{id}/tables?namespace=...` | 只读列出允许的表 |
| `GET /data/sources/{id}/tables/{table}?namespace=...` | 返回列、类型、主键、唯一索引、可空性及结构摘要 |

MySQL 命名空间对应配置的 database，PostgreSQL 命名空间对应数据库内 schema，默认 `public`。目录不读取业务行，平台私有 `af_` 表不作为外部表开放。物理标识符经过验证和引用，值使用参数绑定。部分唯一索引、复合唯一键、生成列和不支持类型保留真实描述，不冒充单列无条件唯一关联键或可写普通列。

## 验收

| 编号 | 验收要求 |
| --- | --- |
| SOURCE-01 | 配置跨租户不可见，管理需当前管理员，模型目录校验定义授权 |
| SOURCE-02 | 密码加密，响应、日志和定义不含明文；保留/替换/清空及 ETag 冲突行为明确 |
| SOURCE-03 | MySQL、PostgreSQL 分别完成真实连接与只读目录发现，保留唯一键范围和类型精度 |
| SOURCE-04 | 共享源逐表租户过滤，专属源并发登记冲突可核对；停用与被引用定位保护有效 |
| SOURCE-05 | 自动识别与指定版本均核验实际产品/完整版本，版本选项来自服务端登记；未知产品、未知版本和版本不匹配可诊断且不能误报支持 |
| SOURCE-06 | 编辑配置及保留密码的测试、检查结果失效、旧配置读取、连接重建与版本改变后的查询/游标失效分别验证；目录、映射发布、查询及离线维护不能绕过能力检查 |

Link 可使用同一个外部来源内的关联表或端点外键，只读查询两端对象；关系表逐表隔离、物理核验及基数规则唯一见 [Link 当前实现](模块/Link.md#当前关系数据库实现2026-11-07)。Source 目录发现不意味着自动识别业务 Link，须明确配置并发布。

已生效默认模型迁入新建专用 MySQL 数据源，使用[显式离线迁移](发布与迁移.md#默认存储迁入专用源2026-11-07)保留模型及实例身份；不能仅改来源ID接管旧平台表。显式源现有实例只读范围不因迁移而改变，完整读写能力以所属模块声明为准。

跨源实例组合写入、跨源 Link、分布式事务、任意联邦条件及其他数据库适配不由连接注册自动获得，实际结构同步和查询范围见 [Schema](模块/Schema.md) 与 [Data 服务](../services/data/README.md)。
