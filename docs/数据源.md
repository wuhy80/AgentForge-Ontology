# 数据源配置

状态：2026-11-07 用户确认新增独立数据源配置菜单，支持 MySQL、PostgreSQL 等数据库；同一 Schema 的属性可来自不同数据库或表。2026-11-08已补齐数据库管理布局、真实指标和表列描述；随后按用户要求实现缩窄目录、进入预览Tab自动刷新及只读SQL控制台增量。连接协议见 [contracts/datasource.go](../contracts/datasource.go)，模型映射规则见 [Schema](模块/Schema.md#2-建模方向与预览)，分别验证的结果及待完成项统一见[项目总览](项目总览.md#当前实现与验证2026-11-06)。本文维护连接配置、目录发现及数据库管理工作台。

## 归属与权限

数据源属于租户，由 Data 服务持久化连接配置和加密凭据。数据源独立于业务分类，顶栏分类切换不切换租户数据源目录。平台 Metadata/Data 自身的控制表连接仍由服务端配置；新增 PostgreSQL 数据源不等于平台元数据已支持 PostgreSQL 部署。

管理员通过“数据源配置”页面维护名称、数据库类型、主机、端口、数据库、用户名、密码、TLS、租户隔离方式和启用状态；支持多个源、连接测试、目录及列结构查看。修改携带 ETag，不提供绕过并发冲突的覆盖写入。已被生效或准备中的映射引用的数据源禁止修改连接定位和隔离方式；停用后相关读取、预览及生效明确拒绝。

权限遵循[权限设计](权限/权限设计.md)：连接管理使用每次权威会话中的当前租户管理员身份；模型作者在获 `definition.edit` 授权后读取可选源及结构目录，不接收密码。租户和管理员身份不能由请求体或外部租户头指定。发现目录不等于获得模型或实例权限，运行时继续校验定义、行和列权限。

## 列表与数据库管理（2026-11-07）

用户已要求数据源首页直接以表格展示，每行操作提供“测试、编辑、管理”。列表展示名称、数据库类型、主机/端口、数据库、实际版本/兼容状态及启停状态；不默认打开连接编辑区。“测试”使用已保存配置，回显连接及版本检查结果；“编辑”展开连接表单，沿用密码只写、保留/清空及ETag冲突规则，关闭时清除未保存密码。

“管理”进入所选来源的独立查看界面，重新读取配置及目录，展示数据库、地址、账号、版本、TLS及隔离方式；可搜索表名，查看字段类型、主键、空值约束、生成列和索引。PostgreSQL可指定数据库内命名空间；MySQL固定使用配置的数据库。管理默认进入字段详情，不读取业务行；本轮确认进入“表数据预览”Tab时自动读取当前选中表，SQL控制台仍须点击执行，具体触发边界见下文。

本批实现有界只读物理SQL，独立于中文业务模型OntologySQL。管理员对当前租户已启用、`dedicated`专属数据源可查询真实业务表；共享来源不能绕过逐表租户列过滤，继续通过模型数据探索查询。权限边界唯一见[权限设计](权限/权限设计.md)。停用来源不开放列表测试和管理连接，可通过编辑表单测试新配置。

普通物理表查询范围为 `SELECT *` 或字段列表、单表 `FROM [namespace.]table`、`WHERE` 字段与字面量比较/LIKE/IS [NOT] NULL及AND/OR和括号、`ORDER BY` 字段列表、`LIMIT 1..100`。本轮确认增加可选请求`limit`，省略或0按100处理，其他值须为1～100；SQL内LIMIT须为1～100，省略按100处理，最终上限取两者较小值，由结果`limit`返回实际值。前端输入仍严格限制1～100。物理标识符可用反引号或双引号，字符串用单引号及双单引号转义。后端解析完整语句、核验真实表列、重新生成带参数SQL，在只读事务中执行；拒绝写入、任意函数调用、联表、子查询、CTE、注释、锁及多语句。目录排行仅按下文确认的固定模板扩展，普通语句仍拒绝系统命名空间、跨MySQL数据库及平台`af_`保留表；已有继承拓扑限制仍生效。

SQL文本最多16 KiB/2048个词元、条件括号最多8层、查询阶段10秒、结果文本累计4 MiB；超预算明确拒绝。最多返回100行，多出的行仅用于判断`hasMore`，界面明确提示。结果按列顺序返回行数组，非空值使用字符串保留int64/decimal精度，JSON null与空字符串分开展示；二进制内容拒绝并提示明确选择文本列。修改SQL、切换表、离开管理或页面隐藏清除旧结果，取消及迟到响应不能恢复旧数据；401/403清除当前管理数据。此入口不提供写入、DDL、通用数据库控制台或跨源查询。

### 数据库管理工作台（2026-11-08已确认）

用户要求继续完善`#sources`中的数据库管理，本轮已实现以下布局，分项验证及真实浏览器登录验收限制见项目总览：

- 顶部提供“返回列表”、数据库管理标题和“刷新结构”，用信息网格展示主机、端口、数据库、用户名、数据库类型、实际版本、字符集、连接数、存储占用和QPS。
- 下方采用左右分栏。左侧显示当前目录的表数量、表名搜索、每张表的字段数和主键列数，每页20条；复合主键按实际组成列计数。切换命名空间或搜索条件重新定位目录，不能把尚未加载的计数显示为0。
- 右侧展示选中表名，提供“字段详情”“表数据预览”“SQL控制台”三个Tab，默认进入字段详情。字段可搜索，展示类型、主键、可空性、默认值、注释及索引，均来自真实目录。

连接数、占用和QPS必须使用后端真实只读观测，清楚区分数据库与实例级统计范围及采样口径；不可用时显示未提供或受限原因，不能填充演示数值。QPS须来自查询数量与明确时间范围，PostgreSQL事务提交/回滚计数不能作为QPS展示。刷新结构重新读取当前配置、基础信息与目录，不触发DDL、模型重绑或迁移，也不自动执行用户SQL。

“表数据预览”沿用上述专属来源有界单表只读查询。本轮按用户新要求已改为每次进入预览Tab时自动刷新当前选中表的前100行，并移除单独预览按钮，替代上批“进入预览不查询、必须点击加载”的交互。管理初次打开仍默认字段详情，不读取业务行。共享来源的物理表预览和SQL执行禁用，继续通过业务模型的租户及行列授权查询。预览与SQL控制台沿用同一来源配置ETag、真实表列校验、超时/数量/响应预算及拒绝规则，不因Tab触发方式改变而开放写入。默认值和注释作为原始目录描述展示，不将它们执行为表达式。

已新增`GET /data/sources/{id}/overview`，响应为`{sourceId,etag,checkedAt,serverVersion,database,charset?,metrics}`，`serverVersion`来自本次新建物理连接的实际探测，不用保存的旧检查结果代替。`metrics`包含`connections`、`storageBytes`和`qps`，每项为`{available,value?,unit,scope,basis,sampleWindowMs?,reason?}`；`value`使用字符串保留数值精度，`unit`分别为`connections`、`bytes`、`queries/s`，`scope`为`instance`或`database`。不可用时不伪造数值，提供受控原因。统计权限失败只令对应指标不可用，不阻断目录展示。该接口仅向当前租户管理员开放，交付前重新检查会话、管理员身份及来源配置ETag；配置已变化时拒绝旧观察，页面提示刷新结构，不自动重放SQL。

| 指标 | MySQL口径 | PostgreSQL口径 |
| --- | --- | --- |
| 连接数 | `Threads_connected`，实例当前连接数 | `pg_stat_database.numbackends`，所配置数据库的当前连接数 |
| 存储占用 | 所配置数据库内当前账号可见普通表的`SUM(data_length + index_length)`目录估算，不含日志和临时空间，不等同于磁盘精确占用 | 所配置数据库的`pg_database_size` |
| QPS | 全局`Questions`约250ms差分采样，包含本次管理查询开销；实际窗口由`sampleWindowMs`给出，是实例指标 | 本轮明确不可用；不使用提交/回滚数量代替查询数量 |

表目录沿既有接口批量增加可选`columnCount`和`primaryKeyCount`，字段数为当前数据库账号可见的列目录数量，主键数为主键列数。缺少某表列统计或统计读取失败时省略计数；主键目录完整读取成功且该表没有主键时才能返回0。保留1000张表上限及`af_`保留表过滤，工作台在已发现目录内搜索和每页20条分页，不绕过目录预算。

列目录增加`defaultValue?: string | null`与`comment?: string`：默认值区分未返回、目录SQL NULL及目录原文，界面不能将这三种状态或空字符串合并；PostgreSQL默认表达式可能含类型转换，MySQL保留目录值文本，不跨方言改写。两类展示文本须为有效UTF-8且每项不超过64 KiB，超限或无效编码省略，不截断或阻断映射，空注释省略。默认值和注释不纳入既有结构签名，不因注释变化让已有映射失效；类型、生成列和约束等原结构规则继续生效。具体实现及实测状态见项目总览。

### SQL只读控制台（2026-11-08增量已确认）

用户确认本轮继续保持只读，新增交互及工具已实现。左侧表目录缩至上批宽度约3/5，为右侧编辑和结果区留出空间；SQL控制台跟随[工作台双主题](界面视觉升级.md#正式主题与偏好)，CodeMirror编辑器提供行号、SQL语法高亮和编辑能力，操作包含执行、一键格式化、校验语法、填入查询及清空。独立limit输入默认100，限制1～100行。高亮仅辅助编辑，不证明任意着色语法已被支持；可执行范围仍由后端封闭语法与固定模板裁决。管理初次打开仍停留字段详情，只有进入专属来源预览Tab或显式执行SQL才读取业务行。

“填入查询”包含当前表查询、表占用排行（数据+索引）和表行数排行（估算）。填入仅更新编辑器，不自动执行；排行只接受[后端固定模板](../services/data/source_sql_tools.go)，不能将目录模板扩展为任意系统表、函数或聚合访问。模板按词元完整匹配，空白、末尾分号和未加引号词元的大小写可变化，引号标识符和字面量须保持原值；仅末尾LIMIT可在1～100内调整，未匹配的修改明确拒绝。系统执行重新生成可信SQL，不直接执行客户端模板文本；仍沿请求limit、只读事务、超时/结果预算及`hasMore`约束。模板初始LIMIT为20，两类排行都保留确定性的名称并列排序。

| 模板与返回列 | MySQL范围和口径 | PostgreSQL范围和口径 |
| --- | --- | --- |
| 表占用排行：`namespace,table_name,data_bytes,index_bytes,total_bytes` | 配置数据库内可见普通表，`DATA_LENGTH`与`INDEX_LENGTH`目录估计之和，不含日志和临时空间 | 当前数据库内非系统schema、账号具备SELECT及schema USAGE的普通表；`pg_table_size`（含TOAST）与`pg_indexes_size`，总量为`pg_total_relation_size` |
| 表行数排行：`namespace,table_name,estimated_rows` | 配置数据库内可见普通表，`TABLE_ROWS`估算 | 与占用排行相同范围，`reltuples`估算；负值表示尚无估计，返回NULL |

两类模板均过滤平台`af_`保留表；PostgreSQL按`relkind=r`列普通表和叶分区，排除分区父表，范围可跨本库非系统schema，不只限于页面当前选中的schema。估计行数不等同精确`COUNT(*)`，目录占用和统计随数据库观察变化；不开放跨数据库排行、写入或任意系统目录查询。

新增工具为`POST /data/sources/{id}/sql/analyze`与`POST /data/sources/{id}/sql/format`，请求复用`SourceQuery{sql,limit?}`，成功返回`{sql,valid:true,dialect,message}`；非法语法或非法上限返回受控HTTP 422，不以`valid:false`成功响应。工具沿同一当前租户管理员、已启用专属来源及配置If-Match边界，共享来源一律拒绝。只进行词法/封闭语法检查或按词元格式化，不连接来源库、不解密来源密码、不执行查询，也不验证表存在或数据库账号的实际读取权限；即使来源暂时离线，已启用配置也可静态分析，实际执行仍重新核验。格式化只调整空白，保留全部词元的拼写，包含引号标识符、中文、精确数值和LIKE等字面量。配置、会话或管理员资格变化后，工具及查询均拒绝交付旧结果，不以语法通过授予执行资格。`SourceQuery.limit`与SQL内LIMIT按本节上文取较小值，工具和执行均拒绝非法上限。

控制台提示和实际后端能力均仅限SELECT，CREATE、INSERT、UPDATE等写入及DDL后续独立设计，不因使用“SQL控制台”名称而开放。共享来源继续拒绝物理业务行查询。编辑SQL、修改limit、切换表/Tab、刷新、清空或离开后清除过期结果，取消请求并丢弃迟到的工具及查询响应；401/403和配置412沿现有清理与刷新规则处理。实际工具协议和本轮验证统一在项目总览记录。

## 凭据与连接

密码只写入，响应只返回 `passwordSet`。更新省略 `password` 保留原值，显式空字符串表示清空；页面保存或离开后清除输入框内密码。密码以 AES-GCM 加密保存在 Data 控制库，密文绑定当前租户及源身份；`ONTOLOGY_DATA_SOURCE_KEY` 提供至少32字节的独立服务端密钥，需与存储一同备份并由部署机制保管。已有密文不能通过更换密钥自动恢复；缺少密钥时源操作明确拒绝，旧默认存储仍可运行。

连接配置使用结构化参数，不接受含任意参数的用户 DSN 或原始 SQL；管理页SQL使用单独的受限查询协议。MySQL 禁用多语句及参数插值，PostgreSQL 使用 pgx。TLS 可配置禁用、加密或校验主机证书。连接与目录操作有超时、数量和响应预算，错误不回显密码或完整连接串。保存配置不执行目标 DDL，普通请求和服务启动不自动迁移平台控制表。

2026-11-08安全加固代码增加部署方控制的 `ONTOLOGY_SOURCE_NETWORK_RULES`，JSON数组每项为 `{cidr,ports,allowInsecureTLS?}`；最多64项，每项1～32个明确端口，总文本最多32 KiB，不接受全地址CIDR。未配置时拒绝全部外部来源连接；租户管理员不能扩大此允许范围，默认平台库不受此配置控制。所有连接及重连重新解析并检查全部DNS结果，混有未允许地址则整次拒绝，实际拨号固定已检查的数字IP；拒绝未指定、多播、链路本地及带zone的地址。新来源TLS默认 `verify-full`；`disable`及不验证证书的`require`仅在对应网络规则显式设置 `allowInsecureTLS:true` 时可连接。已有配置不被自动重写；目录、实例读取和离线迁移工具同样受规则约束。

本地启动脚本仅为本机开发库显式允许 `127.0.0.1/32` 的23306、23307、25432及不安全TLS。单机迁移的知识库连接若沿用回环23307和原TLS配置，部署管理员也须显式配置对应规则；这不改变原数据源ID、密码密文或模型绑定。

## 数据库版本选择与校验（2026-11-07，已确认并实现）

用户已确认实施版本选择、实际版本核验和按能力放行。数据库服务器版本属于连接兼容性信息，五类业务定义仍遵循单份当前态规则。实际字段见[公共契约](../contracts/datasource.go)，公共检测及版本登记见[存储引擎](存储引擎.md#版本能力登记2026-11-07首批实现)。

### 实现范围

原实现只有 `driver`，仅连接测试返回版本文字。现在配置保存版本约束，测试返回结构化兼容诊断，所有外部物理连接通过同一适配层检查后才交给目录、查询和DDL执行。连接池重建同样核验；同一操作中新连接的产品、完整版本或关键配置与先前连接不一致时拒绝，不能因首次连通绕过检查。平台控制库在初始化时共用检测逻辑，但其用途认证独立于外部来源，不能将外部来源通过表述为该版本的平台主库认证。

版本范围覆盖当前路径所需的目录字段与SQL语义，例如PostgreSQL的 `is_generated`、`is_identity`、`indnkeyatts` 和MySQL的 `utf8mb4_0900_bin`。已登记的适配能力不授予账号权限；实际表结构、唯一键、租户隔离及账号可执行性仍由对应操作检查。

### 配置与页面

数据源表单在“数据库类型”后增加“数据库版本”：默认“自动识别”，也可选择服务端登记的明确版本系列。MySQL 按发布系列区分，PostgreSQL 按主版本区分；实际可选范围和允许补丁范围统一由[存储引擎的版本能力登记](存储引擎.md#版本能力登记2026-11-07首批实现)提供。待适配系列显示但禁用，完整补丁版本由服务端检测和展示。指定系列是实际服务器约束，不是强制套用方言的开关。

| 信息 | 实际字段 | 来源与用途 |
| --- | --- | --- |
| 版本选择方式 | `versionPolicy = auto / pinned` | 管理员选择；自动识别也必须命中已登记的适配范围 |
| 预期版本系列 | `expectedVersionLine` | 指定版本时必填；是实际服务器版本约束，不是强制套用旧方言的开关 |
| 实际产品与完整版本 | `compatibility.detectedProduct`、`serverVersion` | 服务端只读检测；不接受客户端提交为可信事实 |
| 兼容状态与能力 | `compatibility.compatibilityStatus`、`capabilityProfile`、`capabilities` | 状态为supported/unsupported/mismatch/failed；范围含目录、读取、查询、建表、加列及索引，不能替代操作权限 |
| 最近检查 | `compatibility.checkedAt`、`connected`、`code`、`message` | 记录检测时间、网络连通及公开原因；旧记录没有compatibility时显示待检测 |

列表及详情展示实际版本和兼容状态，详情另给最近检查及版本适配范围；未检测显示“待检测”。已连接但版本不匹配或不支持时不能显示成功。模型作者的可选源摘要移除完整服务器标识、主机、账号及诊断文本，保留版本系列和适配能力。

### 测试、保存与运行

1. 测试返回 `success`、`serverVersion` 和 `compatibility`，分开报告网络连通与兼容状态。连接/版本检查失败返回HTTP 200且 `success=false`，便于管理员查看实际版本及原因；身份、请求格式和ETag错误继续使用相应HTTP错误。测试不建业务表，兼容协议产品单独适配。
2. 启用状态保存时由服务端重新连接检查，不能提交客户端“测试通过”标记放行；失败不替换旧配置。停用状态允许离线保存，不保留旧检查。页面的“测试当前配置”对已有源提交完整表单及 `If-Match`，密码省略复用当前租户该来源的服务端密码，显式空串测试清空密码；这个测试不保存表单或覆盖已保存检查。
3. 已保存源的空体/JSON null测试保留原协议：停用时409拒绝；启用时将检查结果写入原 `config_json.compatibility`，以租户/来源ID及配置ETag条件更新，不改变配置ETag，检测期间配置已改变则412。保存产生的新ETag绑定本次检查和加密凭据；观察刷新不能恢复旧凭据或覆盖新配置。无需新增平台表或隐式迁移。
4. 目录发现、Schema预览/发布、实例读取、Link查询及显式离线维护均经同一连接检查。运行时以当前连接检测为准，最近保存/测试记录不作为放行凭据；签名只在服务内部参与执行，不作为客户端可信事实。
5. 产品、完整版本或关键配置改变会改变结构与查询指纹，使旧查询/Link分页游标失效。当前预览不保存可执行客户端SQL，发布重读目录并重新编译检查；不会沿用升级前预览执行。数据库升级不触发自动迁移、重建或模型重绑。尚无通用跨请求编译缓存可供失效验收。

### 现有配置与实施顺序

旧数据源缺少新增字段时按“自动识别、尚未检测”读取，不批量改写现有配置，不虚构已通过检查；使用前实际检测并匹配登记范围。本机MySQL 26.7.0、PostgreSQL 17.11的目录、映射和主表能力已有本轮真实回归。其余版本逐个认证，不按更大版本号自动继承支持。

公共适配能力、认证矩阵及尚未开放的系列只在[存储引擎](存储引擎.md#版本能力登记2026-11-07首批实现)维护；MySQL 5.7仍属于有明确需求时的独立兼容工作。版本功能验证与额外数据库版本认证分别记录，不将页面可选或单元测试通过等同于所有后端验收。

## 租户数据归属

| 方式 | 规则 |
| --- | --- |
| `column`（默认） | 数据库可共享；主表及每个关联来源表均须指定租户列，所有读取绑定当前租户，关联键在租户范围内唯一 |
| `dedicated` | 管理员声明数据库专属于当前租户，允许不配置租户列；其他租户不能登记相同规范连接定位为共享来源 |

连接定位按驱动、规范主机、端口和数据库登记并受并发锁保护。DNS 别名、代理后端和外部数据库授权无法仅由字符串目录证明，专属数据库的实际归属仍由管理员和数据库权限保证。

## 目录接口

| HTTP 接口 | 行为 |
| --- | --- |
| `GET /data/sources` | 管理员读取当前租户配置，不含密码 |
| `GET /data/sources?view=select` | 模型作者读取可选源摘要 |
| `GET /data/source-versions` | 管理员或模型作者读取服务端版本系列及supported/pending状态，不探测数据库 |
| `POST /data/sources`、`PUT /data/sources/{id}` | 创建或以 If-Match 修改配置 |
| `GET /data/sources/{id}` | 读取当前租户单个配置 |
| `GET /data/sources/{id}/overview` | 本轮新增的管理员真实基础信息与指标观测，按上述指标范围与可用状态返回；交付前复核会话、管理员及配置ETag |
| `POST /data/sources/test` | 测试尚未保存的连接参数 |
| `POST /data/sources/{id}/test` | 空体/null测试已保存配置；完整DataSourceInput及If-Match测试当前表单，省略密码复用服务端值 |
| `GET /data/sources/{id}/tables?namespace=...` | 只读列出允许的表 |
| `GET /data/sources/{id}/tables/{table}?namespace=...` | 返回列、类型、主键、唯一索引、可空性及结构摘要 |
| `POST /data/sources/{id}/query` | 管理员携带配置If-Match及`{sql,limit?}`，对当前租户专属来源执行有界只读查询；本轮增量limit和固定排行模板见上文，返回columns/rows/hasMore/limit/elapsedMs |
| `POST /data/sources/{id}/sql/analyze`、`POST /data/sources/{id}/sql/format` | 只读SQL工具，沿相同管理员/专属来源/If-Match边界；不连接来源库、不执行查询，成功返回sql/valid:true/dialect/message |

MySQL 命名空间对应配置的 database，PostgreSQL 命名空间对应数据库内 schema，默认 `public`。目录不读取业务行，平台私有 `af_` 表不作为外部表开放。物理标识符经过验证和引用，值使用参数绑定。部分唯一索引、复合唯一键、生成列和不支持类型保留真实描述，不冒充单列无条件唯一关联键或可写普通列。

## 验收

| 编号 | 验收要求 |
| --- | --- |
| SOURCE-01 | 配置跨租户不可见，管理需当前管理员，模型目录校验定义授权 |

| SOURCE-03 | MySQL、PostgreSQL 分别完成真实连接与只读目录发现，保留唯一键范围和类型精度 |
| SOURCE-04 | 共享源逐表租户过滤，专属源并发登记冲突可核对；停用与被引用定位保护有效 |
| SOURCE-05 | 自动识别与指定版本均核验实际产品/完整版本，版本选项来自服务端登记；未知产品、未知版本和版本不匹配可诊断且不能误报支持 |
| SOURCE-06 | 编辑配置及保留密码的测试、检查结果失效、旧配置读取、连接重建与版本改变后的查询/游标失效分别验证；目录、映射发布、查询及离线维护不能绕过能力检查 |
| SOURCE-07 | 表格操作测试已保存连接，编辑保留并发/凭据语义，管理重新读取基础信息及表列/索引；宽窄屏可用 |
| SOURCE-08 | 专属来源只读SQL验证管理员、租户、ETag、停用与共享来源边界，普通SQL拒绝任意函数/写入/多语句及系统表；固定目录排行另按SOURCE-10核对，精确值、NULL/空串、数量/超时/响应预算和迟到清理明确 |
| SOURCE-09 | 管理页顶部真实基础信息/指标、左右分栏、表搜索及每页20条、字段/主键统计、字段默认值/注释/索引及三个Tab可核对；指标缺失明确原因，QPS不以TPS替代，默认字段页不读取业务行，每次进入专属来源预览Tab自动刷新、共享来源拒绝，刷新/切换/迟到/拒绝及宽窄屏分别验证 |

Link 可使用同一个外部来源内的关联表或端点外键，只读查询两端对象；关系表逐表隔离、物理核验及基数规则唯一见 [Link 当前实现](模块/Link.md#当前关系数据库实现2026-11-07)。Source 目录发现不意味着自动识别业务 Link，须明确配置并发布。

已生效默认模型迁入新建专用 MySQL 数据源，使用[显式离线迁移](发布与迁移.md#默认存储迁入专用源2026-11-07)保留模型及实例身份；不能仅改来源ID接管旧平台表。显式源现有实例只读范围不因迁移而改变，完整读写能力以所属模块声明为准。

跨源实例组合写入、跨源 Link、分布式事务、任意联邦条件及其他数据库适配不由连接注册自动获得，实际结构同步和查询范围见 [Schema](模块/Schema.md) 与 [Data 服务](../services/data/README.md)。
