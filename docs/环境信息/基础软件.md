## D 盘目录

| 路径 | 用途 |
| --- | --- |
| `D:\Programs\Docker\Docker` | Docker Desktop 程序和命令行工具 |
| `D:\DockerData\main` | `docker-desktop` WSL2 系统盘 |
| `D:\DockerData\legacy-data` | `docker-desktop-data` 数据盘；镜像、容器、数据库卷的实际字节在该盘内 |
| `D:\WSL\swap.vhdx` | 配置给 WSL2 的 Swap 文件，下次完整重启 WSL 后生效 |
| `D:\DockerUpgrade\20261018-180407` | Docker 升级记录、旧数据盘和配置备份 |
| `D:\AgentForgeData\credentials` | 数据库密码和 InfluxDB Token，仅本机保存 |
| `D:\AgentForgeData\access` | 本机端口转发脚本及运行日志 |
| `D:\AgentForgeData\backups` | 数据库备份存放目录，需另外执行备份才会产生文件 |
| `D:\AgentForgeData\records` | 安装过程中的实际版本、镜像摘要和验证记录 |
| `D:\AgentForgeData\downloads` | MySQL 已校验的离线镜像归档和下载组装文件 |

`C:\Program Files\Docker\cli-plugins` 是指向 D 盘程序目录的目录联接，实际插件文件在 D 盘。少量用户配置和日志仍保存在 C 盘。Ubuntu-22.04 和另一个 Ubuntu 发行版仍位于 C 盘，本次数据库部署不会迁移或重启这些发行版。

## 资源配置

`%USERPROFILE%\.wslconfig` 已配置内存上限 16GB、12 个逻辑处理器、Swap 4GB，以及 `autoMemoryReclaim=gradual`。这些是全部 WSL2 发行版共享的上限。

2026-10-18 部署数据库前实测仍为约 32GB / 24 个逻辑处理器 / 8GB Swap，说明上限尚未在当前运行的 WSL 虚拟机生效。为保留原有 PostgreSQL、Redis 和开发进程，本次未执行 `wsl --shutdown`。关闭相关工作后完整重启 WSL 或重启 Windows，设置才会生效。

## 检查命令

新开 PowerShell 后执行：

```powershell
wsl --version
wsl --list --verbose
docker version
docker desktop kubernetes status
kubectl --context docker-desktop get nodes
kubectl --context docker-desktop get pods -A
```

Docker Desktop 启动前，数据库与 Kubernetes 都不可访问。Kubernetes 使用单机本地卷；`Retain` 策略只能保留 Kubernetes PV，不能替代完整集群重置、Docker 数据清理或物理盘损坏时的备份恢复。
