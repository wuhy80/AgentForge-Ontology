# 本机数据库

安装日期：2026-10-18。使用 Docker Desktop 内置 Kubernetes，context 为 `docker-desktop`，namespace 为 `agentforge-infra`。三个服务均为单副本开发环境，启用认证和持久化，不提供跨主机高可用。

## 版本与连接

按安装当日官方稳定发布选择，固定完整版本标签，后续升级需明确执行，不随 `latest` 自动变化。

| 软件 | 安装镜像 | Windows 本机地址 | 库 / 用户 |
| --- | --- | --- | --- |
| MySQL | `mysql:26.7.0` | `127.0.0.1:13306` | 数据库 `agentforge`；应用用户 `agentforge` |
| Redis | `redis:8.10.2` | `127.0.0.1:16379` | 用户 `default`；默认 DB 0 |
| InfluxDB 3 Core | `influxdb:3.12.1-core` | `http://127.0.0.1:18181` | 数据库 `agentforge`；Bearer Token 认证 |

MySQL 26.7.0 是安装当日 Docker 官方镜像提供的最新 GA 服务器版本。Oracle 另有专用容器的 26.7.1 安全修订号，不是 Docker 官方 `mysql` 镜像的同名标签；该专用镜像下载超时，本机最终使用 Docker 官方 `mysql:26.7.0`，不将其标记为 26.7.1。26.10 仍属于 Early Access，本次不使用。当前安装的是最新稳定 Innovation 分支；如未来需要 LTS，应单独规划版本和数据迁移。

InfluxDB 使用 **3 Core**，提供 SQL / InfluxQL 查询和 HTTP 写入 API，内部 HTTP 端口为 `8181`。它不提供 InfluxDB 2.x 的内置 Web 管理界面、Flux、organization / bucket 工作模式；已有 2.x 客户端需要单独确认兼容性。

集群内使用以下地址，无需经过 Windows 端口转发：

| 软件 | Kubernetes DNS / 端口 |
| --- | --- |
| MySQL | `mysql.agentforge-infra.svc.cluster.local:3306` |
| Redis | `redis.agentforge-infra.svc.cluster.local:6379` |
| InfluxDB | `http://influxdb.agentforge-infra.svc.cluster.local:8181` |

Windows 地址只监听 `127.0.0.1`。原 Ubuntu 中已有 Redis 占用 `6379`，本环境使用 `16379` 避免冲突。

## 凭据

密码使用随机数生成，仅保存在本机 `D:\AgentForgeData\credentials\infrastructure.json`，目录权限仅授予当前用户、SYSTEM 和 Administrators。InfluxDB 原始离线管理员 Token 文件为同目录的 `influxdb-admin-token.json`。Kubernetes 中对应 `mysql-auth`、`redis-auth`、`influxdb-auth` 三个 Secret。

在本机 PowerShell 中加载凭据：

```powershell
$credentials = Get-Content -Raw 'D:\AgentForgeData\credentials\infrastructure.json' | ConvertFrom-Json
# 按客户端需要读取对应字段；不要提交到 Git 或粘贴到公开日志。
# MySQL: $credentials.mysql.username / password / rootPassword / database
# Redis: $credentials.redis.username / password
# InfluxDB: $credentials.influxdb.adminToken / database
```

MySQL 应用用户仅管理 `agentforge` 库；root 仅允许容器内 localhost 连接，用于维护。Redis 当前用户拥有完整 Redis 权限。InfluxDB 当前保存的是管理员 Token，适用于本机环境管理；业务接入时按需要另建受限 Token。

## 数据与资源

| 服务 | PVC | 申请容量 | CPU request / limit | 内存 request / limit |
| --- | --- | --- | --- | --- |
| MySQL | `mysql-data` | 20Gi | 250m / 2 | 768Mi / 2Gi |
| Redis | `redis-data` | 2Gi | 100m / 1 | 128Mi / 512Mi |
| InfluxDB | `influxdb-data` | 20Gi | 250m / 2 | 512Mi / 2Gi |

StorageClass 为 `agentforge-local-retain`，使用 `rancher.io/local-path`，回收策略为 `Retain`。实际数据保存在 kind 节点的 Docker 卷中，落在 D 盘的 Docker WSL2 数据盘，具体路径见[基础软件](基础软件.md)。不是直接将 Windows 文件夹挂载给数据库。

local-path 的 PVC 申请容量不等于预先分配磁盘，也不提供严格的容量配额，需要监控 D 盘和 WSL2 虚拟盘可用空间。删除 Pod 后会重用 PVC；删除 PVC 后 PV 会变为 Released，需要手动恢复绑定。重置 Kubernetes、删除 kind 节点、清理 Docker 卷或删除 Docker 数据盘均可能丢失数据，`Retain` 不能替代备份。

MySQL 使用 `utf8mb4` / `utf8mb4_0900_ai_ci`，InnoDB buffer pool 512MiB，连接上限 100。Redis 启用 AOF（每秒 fsync）和 RDB，`maxmemory=256mb`、`noeviction`，超过限制时写入会报错，不自动淘汰已有键。InfluxDB 使用本地文件对象存储，查询执行内存池 256MB。

## 启动、停止与重建

Docker Desktop 和 Kubernetes 启动后，三个 StatefulSet 会恢复服务。Windows 计划任务 `AgentForge-DatabaseAccess` 在当前用户登录时运行 `D:\AgentForgeData\access\Start-LocalAccess.ps1`，保持三个本机端口转发，Pod 重建导致连接退出后会重连。Docker 尚未就绪时会继续重试。

```powershell
kubectl --context docker-desktop -n agentforge-infra get pods,pvc,services
Get-ScheduledTask -TaskName AgentForge-DatabaseAccess
Start-ScheduledTask -TaskName AgentForge-DatabaseAccess
```

端口转发日志位于 `D:\AgentForgeData\access\*.log`。Docker 停止时三个地址不可用；Pod 重建期间连接会短暂失败，转发程序检测到退出后约 5 秒重试，客户端需要支持重连。Docker Desktop 当前未配置登录时自动启动，需要先手动打开 Docker Desktop。

从仓库恢复部署（保留原凭据目录）：

部署文件：[Kubernetes 清单](../../deploy/kubernetes/infrastructure/infrastructure.yaml)、[凭据初始化](../../deploy/kubernetes/infrastructure/Initialize-Secrets.ps1)、[端口转发](../../deploy/kubernetes/infrastructure/Start-LocalAccess.ps1)。

```powershell
& .\deploy\kubernetes\infrastructure\Initialize-Secrets.ps1
kubectl --context docker-desktop apply -f .\deploy\kubernetes\infrastructure\infrastructure.yaml
kubectl --context docker-desktop -n agentforge-infra rollout status statefulset/mysql
kubectl --context docker-desktop -n agentforge-infra rollout status statefulset/redis
kubectl --context docker-desktop -n agentforge-infra rollout status statefulset/influxdb
```

使用全新 InfluxDB 数据卷时，还需创建数据库（原数据卷已有该库时跳过）：

```powershell
kubectl --context docker-desktop -n agentforge-infra exec influxdb-0 -- influxdb3 create database agentforge
```

初始化脚本重用本机凭据，不自动轮换已有数据库密码。**已有 MySQL 数据目录下，修改 Secret 不会修改数据库账户密码**，需要通过 SQL 完成密码轮换，再同步凭据和 Secret。恢复部署前应确认 context、原 PVC 和本机凭据仍正确。

临时停止服务并保留数据：

```powershell
kubectl --context docker-desktop -n agentforge-infra scale statefulset mysql redis influxdb --replicas=0
# 恢复
kubectl --context docker-desktop -n agentforge-infra scale statefulset mysql redis influxdb --replicas=1
```

## 备份

备份目录预留在 `D:\AgentForgeData\backups`，安装不等于已建立定时备份。MySQL 可用容器内 `mysqldump` 导出后通过 `kubectl cp` 复制到 D 盘，避免 Windows PowerShell 重定向改变编码；Redis 可执行 `BGSAVE` 后复制 `dump.rdb`；InfluxDB Core 应在停止写入并正常停止进程后备份整个数据目录及 Token 文件。复制正在写入的目录不能视为一致性备份。

凭据和数据需要一起备份，并放到另一块磁盘或其他主机；C、D、E 是同一块物理盘。数据库升级前先做可恢复的备份，不能将更高版本的数据目录直接交给旧版本使用。
