## 本地启动与停止

需要 Go 1.22+、PowerShell、运行中的 Docker Desktop 及 Docker Compose。在仓库根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-dev.ps1
$token = powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev-token.ps1
```

上述命令仅为当前子进程指定脚本执行策略，不更改系统设置。脚本创建两个隔离的 MySQL 开发库、OPA 和本地 Go 服务，密钥保存在被忽略的 `.cache/dev/secrets.json`。平台迁移先显式执行，成功后才启动服务；直接运行服务入口不会自动建平台表。重复启动复用本项目已经运行的进程，不重复生成凭据。

| 地址 | 用途 |
| --- | --- |
| `http://127.0.0.1:18080` | Metadata；`/healthz`、`/readyz` 为探针 |
| `http://127.0.0.1:18081` | Data；`/data/capabilities` 返回当前能力 |
| `http://127.0.0.1:28181` | 本地开发 OPA，加载 `deploy/opa/ontology.rego` 和 `data.example.json` |
| `127.0.0.1:23306`、`127.0.0.1:23307` | 分别为 Metadata、Data 的独立开发 MySQL |

默认开发主体是 `demo-tenant / developer`，权限由示例 OPA 数据明确授予。该签名凭据是首批本地身份接入协议，不是 JWT/OIDC；外部认证目录接入仍待后续实现。OPA 的管理接口仅作为环回开发工具，当前 Compose 和示例授权不能作为生产部署。

停止应用进程或连同开发依赖一起停止：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop-dev.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop-dev.ps1 -Dependencies
```

停止脚本只处理记录的本项目二进制进程，保留数据库卷。无法读取进程路径时会明确失败并保留 PID 记录，应使用启动服务时相同的用户及权限运行；启动脚本也会核验记录的进程与新启动的二进制，避免仅因端口有响应就误报成功。日志在 `.cache/dev/*.stderr.log`。凭据文件与数据库卷应一起保留；已有卷不会因改变环境变量就自动更改数据库密码。

## 创建、预览、生效及查询

以下示例对应本轮已实现协议，面向开发者。服务端分配定义与属性 ID，业务选择使用中文名称，不需要手工填写 UUID。

```powershell
$headers = @{ Authorization = "Bearer $token" }
$contentType = 'application/json; charset=utf-8'
$category = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:18080/metadata/categories' -Headers $headers -ContentType $contentType -Body (@{name='生产管理'} | ConvertTo-Json)
$group = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:18080/metadata/groups' -Headers $headers -ContentType $contentType -Body (@{name='设备模型'; categoryId=$category.id} | ConvertTo-Json)

$definition = @{
    categoryId=$category.id; groupId=$group.id; kind='schema'; name='设备'
    schema=@{
        mode='schema_2_db'; storageLayout='single'
        properties=@(
            @{name='设备编码'; dataType='string'; required=$true},
            @{name='设备名称'; dataType='string'; required=$true}
        )
    }
}
$draft = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:18080/metadata/definitions' -Headers $headers -ContentType $contentType -Body ($definition | ConvertTo-Json -Depth 12)
$definitionUrl = "http://127.0.0.1:18080/metadata/definitions/$($draft.definition.id)"
$preview = Invoke-RestMethod -Method Post -Uri "$definitionUrl/preview" -Headers $headers
$publishHeaders = @{ Authorization="Bearer $token"; 'If-Match'=('"' + $draft.etag + '"') }
$publication = Invoke-RestMethod -Method Post -Uri "$definitionUrl/publish" -Headers $publishHeaders

$values = @{}
foreach ($property in $draft.definition.schema.properties) {
    if ($property.name -eq '设备编码') { $values[$property.id] = 'PUMP-001' }
    if ($property.name -eq '设备名称') { $values[$property.id] = '输送泵' }
}
$instanceUrl = "http://127.0.0.1:18081/data/schemas/$($draft.definition.id)/instances"
$instance = Invoke-RestMethod -Method Post -Uri $instanceUrl -Headers $headers -ContentType $contentType -Body (@{values=$values; idempotencyKey=[guid]::NewGuid().ToString()} | ConvertTo-Json -Depth 12)

$query = @{
    from=@{category='生产管理'; schema='设备'}
    select=@('设备编码','设备名称')
    where=@{op='startsWith'; field='设备编码'; value='PUMP-'}
    orderBy=@(@{field='设备编码'; direction='asc'})
    page=@{limit=50}
}
$result = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:18081/data/query' -Headers $headers -ContentType $contentType -Body ($query | ConvertTo-Json -Depth 12)
$result
```

分类与定义示例只需创建一次；重复执行时应按真实名称唯一性处理冲突。PATCH/删除需要实例当前 `ETag` 对应的带引号 `If-Match`，不能用定义 ETag 替代。新请求读取当前定义；发布失败时按同一草稿 ETag 重试原发布，不能通过普通 CRUD 绕过暂停状态。详细路由与错误码见所属服务 README。

## 构建与验证

```powershell
# 独立模块测试及 go vet；未提供数据库的集成用例明确跳过。
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\check.ps1

# 使用本项目的两个 MySQL 开发库和真实 OPA 做集成验证。
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-dev.ps1 -DependenciesOnly
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\check.ps1 -Integration
```

集成测试创建随机租户/Schema，不清空平台表和已有业务数据；测试 OPA 授权记录在用例结束时删除。动态测试实体表和测试租户记录可能保留在开发数据库，用于核对，不应把验证脚本指向生产库。

各服务可单独构建和显式迁移，例如：

```powershell
$env:GOWORK='off'
Set-Location services/metadata
go build ./cmd/server
# 先按下表配置环境，再执行一次显式平台迁移。
go run ./cmd/server -migrate
go run ./cmd/server
```

| 环境变量 | 责任 |
| --- | --- |
| `ONTOLOGY_MYSQL_DSN` | 当前服务自己的 MySQL 库和账号，需 `parseTime=true`；不得交叉写另一服务私有表 |
| `ONTOLOGY_AUTH_SECRET` | 两服务一致的身份签名密钥，至少 32 字节 |
| `ONTOLOGY_SERVICE_TOKEN` | 两服务间凭据，至少 32 字节且与身份密钥不同；只开放受控内部发布/当前定义读取 |
| `ONTOLOGY_CURSOR_SECRET` | Data 游标签名密钥，至少 32 字节，独立于其他密钥 |
| `ONTOLOGY_OPA_URL` | OPA 根地址；未配置、错误或无法确认决策时拒绝受影响操作 |
| `ONTOLOGY_OPA_TOKEN` | 可选 OPA 服务调用凭据 |
| `ONTOLOGY_DATA_URL` | Metadata 调用 Data 的地址 |
| `ONTOLOGY_METADATA_URL` | Data 读取权威当前定义的地址 |
| `ONTOLOGY_LISTEN` | 当前服务监听地址；默认仅环回 `18080` / `18081` |
