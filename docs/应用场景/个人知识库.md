# 个人知识库建模建议

状态：用户于2026-11-07确认按本方案构建，已完成首批六个对象模型、六个关系定义与 `Ontology/` 16篇内容试点。Git正文来源、单向同步和通用内容模型按本轮确认落实；关系实例、专用阅读器和后续业务语义仍待开发。源知识库保持只读。本文件只维护场景映射和实际试点，平台能力与公共规则仍以所属模块为准。

## 1. 实际内容与建模目标

源库当前以 Git 中的 Markdown 为内容真相源，由 ZCode/DSH 编辑，Obsidian 是存量文件格式。建议首期保留这套维护方式，将系统作为结构化数据、关系和查询的入口，采用 Git → 系统单向同步；在编辑职责和冲突协议确定前，不同时开放两端正文编辑。

此次统计采用源库发布脚本的九个内容目录，排除其明确排除的路径、协作指令文件及隐藏内容，不包含 `_site` 构建副本、模板、缓存或已迁出的私密库。统计是源文件结构调查，未执行发布脚本的脱敏与发布处理，不等于这些原文件已获公开发布许可。

904 篇包含可解析的 YAML frontmatter；常见字段有 `tags`、`created`、`updated`、`status`、`aliases`、`source` 和 `type`。frontmatter 中有 571 个不同的非空标签值，文件名存在 15 组同名情况。去除围栏代码块后的词法扫描发现 612 篇含 WikiLink 或嵌入，共约 5,249 次，其中约 1,337 次为嵌入；此项不是链接解析或有效性验收。

内容差异影响模型划分：

- 大模型资料包含 4 篇 `model-card`，已有厂商、价格、上下文长度、输入模态及嵌套评测指标，适合进一步结构化。142 篇 `ai-daily` 和 30 篇 `weekly-news` 可先作为不同类型的笔记，无须各建一套 Schema。
- 书籍卡片已有 ISBN、作者、出版社、评分等字段，但来源评分与个人评分应分开。作者、来源存在单值和列表两种形式。
- 双语精读包含对照段落、词汇注释和来源；现有脚本已能抽取词汇。个人掌握度当前保存在站点浏览器 localStorage，不能从笔记推断。
- 书签页通常一篇包含多个 URL，应区分笔记页面和外部资源条目。

## 2. 分类、分组与对象

建议在当前租户下新增一个“个人知识库”分类，通过工作台顶栏选择；分类内按“内容资产”“知识组织”“引用溯源”等分组维护模型。原库的“技术笔记”“大模型”等目录以及 Kubernetes、Ontology 等主题属于实例数据，不按每个文件夹重复创建分类或 Schema。

分类/分组、命名和跨分类引用统一遵循[组织与隔离](../组织与隔离.md)。分类组织模型定义；每篇笔记是“笔记”Schema 的实例，标签是“标签”Schema 的实例。分类内五类定义中文名称仍须统一唯一，实例标签不占定义名称登记。

首批候选模型如下。字段为语义清单，尚不是可直接提交的完整定义协议。

| 分组 | Schema | 主要数据 |
| --- | --- | --- |
| 内容资产 | 知识库 | 稳定库标识、名称、来源仓库标识、同步范围；部署端维护本机路径 |
| 内容资产 | 笔记 | 标题、来源相对路径、原始 Markdown、原始 YAML、来源类型/状态、来源业务日期、内容摘要哈希、同步时间、来源可用状态 |
| 内容资产 | 附件 | 名称、类型、大小、内容哈希、来源定位、可用状态；二进制不塞进普通属性 |
| 知识组织 | 标签 | 原始标签值、展示名；`技术/数据库` 的层次可后续确认，首期保留完整值 |
| 引用溯源 | 外部资源 | 原始 URL、规范化定位、标题、说明、资源类型；URL 规范化保留原值，不随意删查询参数 |
| 引用溯源 | 引用记录 | 原始写法、普通/嵌入类型、别名、标题/块/页码/显示尺寸定位、出现位置、来源内容哈希、解析状态 |

笔记标题允许重名。来源业务日期、Git 变更时间和系统同步时间分别保存；仅有日期的字段保留日期语义，不能伪造当天零点为真实事件时刻。原始 `status` 不直接强制归一：“精读”“初稿”“已归档”等可能属于不同业务维度，也与平台定义草稿/生效状态无关。

YAML 原文用来保真和追溯；需要筛选的多值来源、别名和标签应逐项规范化，不能用逗号拼接字符串代替集合。首期可由导入器保留别名解析索引，尚未建模的附加字段保留在原始 YAML 中，不宣称它们可直接参与结构化查询。标签会持续增长，适合业务对象；笔记类型、引用类型等受控集合才是 Enum 候选，绑定能力实现前不承诺平台强校验。

候选 Link 包括“笔记归属知识库”“笔记标记标签”“笔记产生引用”“引用指向笔记”“引用指向资源”“引用指向附件”。一个引用记录归属一篇来源笔记，目标按类型最多关联一个对象；解析失败或歧义时保留原始目标和状态，不伪造目标实体。反向引用从同一事实派生，遵循[Link](../模块/Link.md)，不重复存两份边。

WikiLink 只证明文档引用。`[[Kubernetes]]` 不自动代表“依赖 Kubernetes”；“依赖”“实现”“对比”等领域事实需显式抽取并保留来源及确认状态。全文分块、向量及搜索索引是可重建派生数据，不作为知识实体的稳定身份。

## 3. 增量同步与保真

笔记使用独立稳定 ID；同步映射记录库 ID、当前相对路径和实体 ID。文件名或路径哈希不能作为永久身份。首期可在导入侧保存映射而不改源笔记；若以后引入源文件 ID 或 sidecar，再单独确定维护职责。

新增、修改、删除和重命名分别处理。相同文件重复导入不重复建实例；内容哈希识别变化，修改使用并发凭证，系统中存在独立修改时返回冲突。路径变化只在可靠 Git 重命名证据或人工映射确认后沿用身份；证据不足时保留待核对项，不凭标题或相似度自动合并。只有完整且成功的清单扫描才能判断缺失，扫描失败不能触发删除。来源删除首期标记不可用，不自动级联删除笔记、附件和引用。

链接解析保留原始目标，支持路径、别名、标题、块和附件参数；路径和别名的匹配优先级须通过源库实际样例确认，同名或多候选目标返回歧义，不能取枚举到的第一个文件。别名多值和相对路径语义不能丢失；导入器读取链接但不改写原文。

原始 Markdown 保留 Callout、表格、公式、Mermaid、脚注、块 ID 和嵌入。Dataview、DataviewJS、Templater 作为文本保存，不在导入或预览中执行。后续正文阅读器另行处理渲染兼容、HTML 清理、脚本禁用及附件访问授权；不把保存原文等同于已支持全部插件渲染。

导入范围沿显式白名单和排除清单配置，只处理被纳入范围的内容及获准附件。源库现有公开导出范围与系统租户授权是两套边界；文件在公开技术库内不代表可自动对外公开。访问、后台同步身份及派生搜索结果遵循[权限设计](../权限/权限设计.md)，不读取或扩入已迁出的私密库与插件缓存。

现有 `build-vault-meta.mjs`、`build-d1-index.mjs` 和 `build-vocab.mjs` 可参考其元数据/词汇提取逻辑。但 D1 导入的重建表、路径唯一身份、正文截断及标签字符串不能直接沿用。新导入流程引用[数据读写](../数据读写.md)与[执行与调度](../执行与调度.md)的所属设计，不另建绕过 Data 校验和权限的写表通道。

## 4. 逐步增加业务语义

通用内容闭环之后，按有价值的查询增加独立模型，不预先把所有名词建成对象：

| 场景 | 后续候选模型 | 示例问题 |
| --- | --- | --- |
| 模型选型 | 大模型、评测指标、评测结果、计价记录 | 哪些模型可本地部署？在相同评测口径下表现和价格如何？ |
| 技术知识 | 技术概念、工具、概念关系及来源证据 | 哪些笔记讨论权限？哪些内容显式比较不同权限方案？ |
| 阅读学习 | 图书、课程、章节、个人阅读记录 | 哪些书与数学有关？我最近读到哪一章？ |
| 双语学习 | 词条、词义/出现记录、对照段落、个人学习记录 | 某个词在哪些文章出现？我有哪些待复习词？ |

模型评测结果需携带指标定义/口径、工具设置、来源和观察日期，不把不同测试的同名分数直接排序为同一榜单；价格需保留币种、计价单位、适用条件和观察时间。缺失值不按零填充。外部模型发布标识和评测指标修订是业务数据，不引入可选择旧版平台定义的机制。

个人评分、阅读进度和词汇掌握度绑定用户，由用户记录或显式迁入，不能提升为所有用户共享的图书/词条属性。现有站点 localStorage 数据没有自动迁移，需另定用户确认和导入格式。AI 抽取的概念/关系保留来源笔记、位置、内容哈希及确认状态，来源变化后可标记待复核。

## 5. 当前可做与建议开发顺序

当前实际能力以[项目总览](../项目总览.md#当前实现与验证2026-11-06)、[Data 服务](../../services/data/README.md)和[Schema](../模块/Schema.md)为准：已可维护模型、发布 MySQL 单表、单条写入和单 Schema 筛选/排序/分页。本轮新增外部工具基于这些单条 API 做受控导入和更新；平台尚无 Link 事实读写、通用批量导入/调度、全文搜索、向量检索、聚合、OntologySQL 或 Action/Function 执行。

`text` 仍限制为65,535 UTF-8字节；调查范围内有14篇完整Markdown超过该上限，最大约996 KB。本轮沿所属模块新增独立 `longtext` 类型，上限4 MiB，映射 MySQL LONGTEXT；Data请求体上限为8 MiB，包含JSON转义和其他字段，超限明确拒绝，不截断。原 `text` 契约不变；Metadata与身份管理请求仍为1 MiB。正文及YAML采用longtext，字段结构先确定后发布，发布后仍只允许展示变更。

本轮确认先做第一步，后续继续按所属能力推进：

1. **内容试点**：先选择 `Ontology/` 的 16 篇，确认字段和同步映射，开发只读扫描预览、错误报告、单向幂等导入及长正文支持；用全库长文样本做容量检查。没有完整 Link 能力时，只验证笔记/资源对象和引用待解析清单，不称为关系闭环。
2. **关系与查询**：补齐所属模块的 Link 实例保存/反向读取、增量重命名处理和正文阅读入口，实现标签检索、反向链接、来源追踪及失效链接检查；再按实际需求加全文检索，查询后仍执行当前授权。
3. **业务扩展**：先用 4 张模型卡片验证模型、评测及计价模型，再扩展书籍与双语词汇；语义检索和问答后续依据查询需求决定。

试点应能核对：原文无截断；重复导入不增副本；改名保留身份或进入明确待确认状态；歧义/失效链接不误绑定；扫描失败不误删；来源删除可追溯；多值和日期语义保留；未授权内容不出现在正文、引用反查和搜索结果。只验收实际开放入口，引用反查和搜索的权限验收随其实现开展。

## 6. 本轮实现与实测（2026-11-07）

可复用蓝图与离线/在线工具见[个人知识库工具](../../tools/knowledge_base/README.md)。本机开发租户中已建立“个人知识库”分类，含内容资产、知识组织、引用溯源三个分组，六个Schema与六个Link定义均已生效；未创建额外测试账号或枚举。

通过工作台账号会话及公开API导入1个知识库、16篇笔记、31个标签、66个外部资源、328条引用记录，附件实例为0。引用解析为292条目标已定位、15条明确范围外、21条未解析；已定位只表示目标对象唯一，标题/块锚点未做存在性认证。范围外不读取文件，未解析不伪造目标UUID。636项候选关联保存在扫描清单，Link事实写入数为0；标签/来源的可查询记录是普通引用对象，没有宣称已实现关系导航或外键约束。

首轮逐对象回读所有导入字段及完整正文/YAML通过；重复执行新增、更新和失效数均为0，442个已有对象全部复用，再次回读一致。真实Microsoft Edge通过正常登录、分类选择、模型浏览、查询16篇笔记和打开原文详情，未出现浏览器运行错误。截图与同步状态仅保存在忽略目录。

真实MySQL完成4 MiB UTF-8 longtext往返与实际物理表核验，临时测试表已清理；Go六模块测试及vet、前端105项测试和构建通过。扫描、恢复和并发保护的离线测试覆盖源路径边界、错误扫描、原文与多值日期保留、歧义、疑似改名停止、ETag冲突、丢失创建响应及发布中断恢复；文档链接与验收索引另行检查。不代表完整关系功能、全库导入、三库兼容、性能或生产部署验收。

当前限制：单scope状态不跨范围协调，尚无自动Git重命名或人工映射界面；同步需显式执行，无后台监视或调度。同步冲突会保留状态并停止，缺失来源只标记不可用；没有专用正文阅读器、全文/向量索引、语义抽取或问答。书籍、模型评测和英语学习模型仍按第4节作为后续范围。
