# 定义生效与数据库迁移

状态：统一采用单份当前定义，不提供业务 version。本文维护 Schema、Enum、Link、Action、Function 的修改生效、数据库迁移、运行一致性和验收；尚无业务实现。

## 1. 所有定义统一采用当前态

每个对象只有一个稳定 ID、一份当前生效定义，最多保留一份可编辑草稿。草稿用于预览及变更校验，不参与业务读取和执行；生效成功后替换当前定义并清理草稿。首次创建尚未生效的对象不能被业务引用。

五类定义及其引用均不携带 `version`，引用形式为 `{ "id": "<稳定 ID>" }`。新请求、新查询及新开始的执行按当前生效定义处理。不提供语义版本号、历史定义选择、指定旧定义调用、定义分支、多份生效定义或跨类型版本发布集。`latest` 也无需作为字段或别名保存。

| 对象 | 修改生效前检查 |
| --- | --- |
| Schema | 字段、约束、索引、单位、实例数据、物理映射及所有引用方 |
| Enum | 当前取值、字段/参数/默认值引用及已存业务编码；被使用的取值不可直接删除 |
| Link | 两端 Schema、关系事实、基数、重复及删除规则 |
| Action | 目标、输入输出、权限、效果、实现引用及运行中的调用 |
| Function | 输入输出、实现制品、权限、副作用及运行中的调用 |

依赖按 ID 解析，更新被引用对象时同步检查当前引用方、订阅及周期规则，不能因 ID 未变就跳过校验。不兼容变更需先调整依赖和数据；无法逐步兼容时，暂停受影响范围后协调生效，首期不建立通用的多对象发布集机制。租户、分类、分组及命名规则见 [组织与隔离](组织与隔离.md)。

## 2. 保存、预览与生效

建议流程：`编辑/保存草稿 → 预览及影响检查 → 必要的数据/结构迁移 → 校验 → 替换当前定义 → 清理草稿并恢复访问`。不影响存储的变更可合并校验和生效步骤；保存草稿不自动影响当前业务。

Metadata 拥有五类当前定义、草稿、依赖及生效状态；Data 拥有实例、关系、数据源、物理映射和实际迁移。定义、操作记录和迁移目标均归属一个 tenant_id，禁止跨租户引用。

`schema_2_db` 根据当前定义、草稿及实际目标结构编译迁移计划，创建或调整受管理表和索引，验证成功后生效。`db_2_schema` 校验源结构并替换当前逻辑映射，不执行修改源库的 DDL；发现结构漂移先暂停不再安全的操作，不静默覆盖当前映射。详细边界见 [Schema](模块/Schema.md)。

预览关联草稿内容摘要、当前定义及依赖摘要、目标数据源、实际结构摘要、驱动能力信息。任何相关内容改变，旧预览及计划失效；正式生效重新校验。SQL 预览和执行复用同一计划编译，不接受客户端回传的任意 SQL。摘要只用于校验内容是否变化，不提供按摘要选择历史定义的接口。

Metadata 的定义替换、名称登记、依赖更新及所属 outbox 在本地事务完成；并发编辑可用 ETag/If-Match 或等价条件更新拒绝覆盖。ETag 是自动生成的并发校验凭证，不是用户维护的定义版本，不保留可选择的历史 ETag。

生效协调必须阻止依赖在“检查完成”与“替换当前定义”之间被并发修改；读取请求在开始时取得一致的当前定义及依赖内容，在该次操作内复用。不能边执行边重新取最新定义，拼成从未生效过的组合。具体锁及跨服务校验协议在实现时确定。

## 3. 数据库迁移与失败恢复

| 类型 | 对象 | 记录内容 |
| --- | --- | --- |
| 平台数据库迁移 | 元数据、任务、调度等服务自身的数据表 | 软件迁移编号、校验和、执行状态及失败进度 |
| 模型数据/结构变更 | Schema、Enum、Link 变更引起的实例、关系、索引及物理结构 | 操作 ID、变更前后摘要、计划、数据验证、进度及恢复措施 |

软件、API、数据库引擎和运行时的版本仍按其工程规则管理；它们与业务定义 version 分开。迁移记录的操作 ID 用于恢复一次操作，不是定义版本，也不成为实例或定义引用字段。

Data 执行模型迁移，各服务执行自己的平台迁移，共用 [存储引擎](存储引擎.md) 的目录、方言及执行设施。迁移可由命令或 Job 执行，服务启动及普通查询不调用 AutoMigrate 修改结构。

多副本迁移需持久化互斥和旧执行者隔离。涉及 DDL 的跨服务步骤不假定原子事务，MySQL、PostgreSQL、达梦分别验证事务 DDL、锁及在线能力。大规模回填分批执行并保存进度；不能仅靠外层事务假装可以撤销全部变化。

首期对删字段、缩小类型、变更单位、删除使用中的 Enum 编码、收紧 Link 基数等不兼容变更，采用受影响范围的维护流程：暂停新读写及执行 → 等待运行中操作排空或显式停止 → 迁移并验证 → 替换当前定义及映射 → 清理缓存 → 恢复访问。排队任务恢复后重新读取并校验当前定义。不中断业务的兼容扩展只在适配器及缓存一致性已验证时开放。

失败时不将候选定义标为当前。若数据库尚未改变，可继续使用原当前定义；若结构已部分改变且无法证明原定义仍安全，保持受影响范围暂停，按记录恢复或向前修复，不能自动恢复流量。操作状态可包括 preparing、applying、succeeded、failed、needs_repair，具体协议待实现。

修改描述和展示名直接更新元数据；修改单位、类型或业务编码需要迁移已有数据，不能用最新定义给旧数值换含义。历史事实若无法迁移，必须保留其实际单位、量类型、原始值等自描述上下文，或拒绝原地变更并新建不同 ID 的业务概念。审计日志及备份用于追踪和恢复，不提供任意切回历史定义的运行入口。

## 4. 请求、任务与缓存

新请求读取当前生效定义；排队任务在首次实际开始执行时解析最新 Action/Function 及依赖并重新校验输入、权限和目标。目标已删除、停用或输入不再合法时明确失败，不自动回退旧定义。

执行开始后，在同一任务记录中保存实际采用的输入输出约束、单位、目标及实现制品摘要等必要内容，运行和重试沿用该任务上下文，不中途切换代码或参数规则。该记录仅服务于本次执行、核对和审计，不可作为旧定义向其他任务开放。权限撤销及租户检查仍然即时执行。无法按原上下文安全重试时停止并核对，不偷偷换成当前实现；详细规则见 [执行与调度](执行与调度.md)。

所有业务读写仍须满足当前数据约束，任务上下文不是绕过 Data 当前校验的通道。与运行任务不兼容的结构或定义变更必须先排空任务，不能一边删除字段，一边承诺旧任务继续使用它。

定义及查询计划缓存按 tenant_id、对象 ID、当前内容摘要、权限和映射等实际条件隔离。每次使用需校验权威的当前状态/摘要；失效事件用于加速，不能仅靠事件或 TTL 容忍生效后继续读旧定义。权威状态不可确认时受影响操作失败或重试；在没有完成这一机制前可先关闭相关缓存。跨服务生效期间使用持久化暂停状态和入口检查阻止旧实例继续接收请求。

历史查询结果及任务结果应保存与实际值匹配的字段描述、单位、必要执行内容及来源，读取历史记录不通过当前 Schema 猜测原含义。不承诺恢复任意过去时间的完整定义。

## 5. 验收

| 编号 | 要求 | 验收方法 |
| --- | --- | --- |
| PUB-01 | 统一维护一份当前定义，平台迁移与模型变更分别记录 | 五类接口及引用无业务 version；仅可读取当前定义及编辑草稿，操作 ID 不可用作旧定义调用 |
| PUB-02 | 预览、依赖检查及迁移成功后才生效 | 草稿不影响业务；过期预览、跨租户及并发依赖变更被拒绝；两个 Schema 模式遵守 DDL 边界 |
| PUB-03 | 迁移并发安全、失败可恢复，旧执行者不能提交 | 两副本争抢、回填中断及部分 DDL 失败可核对；结构不一致期间保持暂停 |
| PUB-04 | 新操作用当前定义，已开始任务保持执行一致性 | 生效后两副本读取相同当前定义；排队任务取最新，运行任务不换代码；破坏性变更排空任务，失效缓存不能继续服务 |

## 6. 待定事项

需明确目标数据库版本、ETag 及依赖并发校验、跨服务暂停/恢复协议、迁移互斥、缓存权威校验成本、任务上下文保留期和备份恢复方式。五类对象的单份当前定义原则已确定，具体工程协议尚待验证；不承诺所有变更在线无停机。
