# 定义生效与数据库迁移

状态：统一采用单份当前定义，不提供业务 version。本文维护完整生效设计；首批已实现首次发布与展示变更的持久协调，结构性迁移及运行任务协调仍待后续实现。实际能力见[项目总览](项目总览.md#当前实现与验证2026-11-06)。

## 当前实现协议（2026-11-06）

首批 Metadata 以持久租户 guard 串行化定义编辑/发布；Data 以持久 Schema 入口状态和同事务锁隔离普通读写。发布依次执行：固定草稿及操作 ID → Data 在已有事务完成后暂停该 Schema → 校验并准备受管理结构 → Metadata 在本地事务中替换当前定义、名称、依赖并写 outbox → Data 从 Metadata 核对权威当前摘要 → 激活入口 → 清理 Metadata guard。网络调用不包在 Metadata 长数据库事务中，不假定两服务共享原子事务。

相同在途操作重试恢复原操作 ID；激活失败保留暂停并重试激活，不重新产生定义事件。历史上出现过相同内容不能替代当前发布意图，例如改名 A→B→A 必须实际重新协调生效，不能查到历史成功记录就返回成功。发布操作记录不是可供选择的业务定义版本。

首批只允许首次生效和存储签名不变的展示修改；结构、字段类型、约束、Enum 编码等变化明确拒绝。已知不支持的布局、属性和行宽等在暂停前拒绝；DDL 已部分发生或结果不明时保持暂停，按实际结构核对恢复，不能假报回滚。平台迁移通过服务 `-migrate` 显式执行，失败/中断进入待修复记录，由存储模块的显式核验恢复接口处理，不在服务启动或普通请求中自动重跑。

草稿和 active 是本轮开放的定义状态；停用、定义删除及名称释放尚未开放。完整生命周期、反向源身份/漂移、备份恢复和运行任务排空继续按后续设计推进。首批细节见[开发指南](开发指南.md)及所属服务说明；以下章节中的完整目标不等于本轮均已交付。

2026-11-07补齐Function及直接源码Action内联Python实现的发布与更新：runtime作为所属当前定义的一部分保存，同样复用草稿、ETag、依赖检查和持久发布协调；源码/入口/超时可更新，未绑定函数或产物的既有纯计算定义可补充源码。输入输出签名、副作用和已有实现引用仍受结构限制，绑定Action不能改为直接源码，发布Function时复核当前绑定Action的签名。新调用使用新源码，已开始调用保留本次快照，不执行数据副作用；当前定义变化后旧结果整体拒读。首批不排异步队列，也未实现通用运行任务排空或跨服务原子撤权，协议分别见[Function](模块/Function.md)、[Action](模块/Action.md)、[执行与调度](执行与调度.md)及[权限设计](权限/权限设计.md)。

## 1. 所有定义统一采用当前态

每个对象只有一个稳定 ID、一份当前生效定义，最多保留一份可编辑草稿。草稿用于预览及变更校验，不参与业务读取和执行；生效成功后替换当前定义并清理草稿。首次创建尚未生效的对象不能被业务引用。

五类定义及其引用均不携带 `version`，引用形式为 `{ "id": "<稳定 ID>" }`。新请求、新查询及新开始的执行按当前生效定义处理。不提供语义版本号、历史定义选择、指定旧定义调用、定义分支、多份生效定义或跨类型版本发布集。`latest` 也无需作为字段或别名保存。

| 对象 | 修改生效前检查 |
| --- | --- |
| Schema | 字段、约束、索引、单位、实例数据、分表规则/目录、物理映射及所有引用方；采用继承候选时还检查基类、全部后代的有效定义及具体类型匹配 |
| Enum | 当前取值、字段/参数/默认值引用及已存业务编码；被使用的取值不可直接删除 |
| Link | 两端 Schema、自动正反向视图、关系事实、基数、重复及删除规则；采用关系语义候选时还检查组合归属、拓扑范围、子类型端点、排序权威来源及上下文/属性/有效时间 |
| Action | 目标、输入输出、权限、效果、实现引用及运行中的调用 |
| Function | 输入输出、实现制品、权限、副作用及运行中的调用 |

依赖按 ID 解析，更新被引用对象时同步检查当前引用方、订阅及周期规则，不能因 ID 未变就跳过校验。不兼容变更需先调整依赖和数据；无法逐步兼容时，暂停受影响范围后协调生效，首期不建立通用的多对象发布集机制。租户、分类、分组及命名规则见 [组织与隔离](组织与隔离.md)。

细粒度权限为新增候选，统一见[权限设计](权限/权限设计.md)：策略绑定的字段、类型、Link、Action/Function 及组织作用域也属于变更依赖，删除/类型变化和移组不能跳过影响检查。策略当前态、内部授权标记、成员变更、撤权串行边界和缓存校验由权限专题维护，不引入五类定义的业务 version，后续验证引用 AUTH-09～AUTH-10。

## 2. 保存、预览与生效

建议流程：`编辑/保存草稿 → 预览及影响检查 → 必要的数据/结构迁移 → 校验 → 替换当前定义 → 清理草稿并恢复访问`。不影响存储的变更可合并校验和生效步骤；保存草稿不自动影响当前业务。

Metadata 拥有五类当前定义、草稿、依赖及生效状态；Data 拥有实例、关系、数据源、物理映射和实际迁移。定义、操作记录和迁移目标均归属一个 tenant_id，禁止跨租户引用。

`schema_2_db` 根据当前定义、草稿及实际目标结构编译迁移计划，创建或调整受管理表和索引，验证成功后生效。`db_2_schema` 校验源结构并替换当前逻辑映射，不执行修改源库的 DDL；发现结构漂移先暂停不再安全的操作，不静默覆盖当前映射。详细边界见 [Schema](模块/Schema.md)。

预览关联草稿内容摘要、当前定义及依赖摘要、目标数据源、实际结构摘要、驱动能力信息。任何相关内容改变，旧预览及计划失效；正式生效重新校验。SQL 预览和执行复用同一计划编译，不接受客户端回传的任意 SQL。摘要只用于校验内容是否变化，不提供按摘要选择历史定义的接口。

外部来源的实际产品、版本和关键配置检查统一见[数据源版本管理](数据源.md#数据库版本选择与校验2026-11-07已确认并实现)。当前发布重新打开受检查连接、读取目录并编译，不能凭升级前预览直接执行；版本变化不自动触发平台迁移或重绑。

Metadata 的定义替换、名称登记、依赖更新及所属 outbox 在本地事务完成；并发编辑可用 ETag/If-Match 或等价条件更新拒绝覆盖。ETag 是自动生成的并发校验凭证，不是用户维护的定义版本，不保留可选择的历史 ETag。

Link 生效同时向两端提供当前方向视图，草稿只预览，停用/删除及端点变化一并处理两个方向的依赖、发现索引和缓存。它们共用一个当前 Link ID，不单独发布反向定义，也不为生成视图复制或回填倒置端点的业务边；基数或端点变化引起的实际数据迁移仍须验证。完整行为见 [Link](模块/Link.md)。

针对新增的关系语义候选，普通关联改为组合或收紧为树/DAG 前，须扫描整个声明范围的已有边，检查独占归属、父数量及环，准备相应归属登记/并发约束并验证后才生效；不能仅改类型标签或自动删除冲突关系。删除策略、共同约束范围、端点子类型匹配变化也须纳入预览及影响检查。

启用或改变有序成员、直接前后链、上下文范围、对称/派生规则、关系属性及有效时间时，预览现有关系的排序补全、重复/区间重叠、属性转换和约束变化；歧义顺序不能按设备 ID 或创建时间自动当作真实业务顺序。需要重建事实或索引时先在受影响范围协调迁移并校验，唯一权威顺序和派生导航一起切换，旧游标/缓存失效。普通成员拖动、安装有效时间等是实例事实变化，不替换 Link 定义、不引入业务 version，仍按相应事务及审计契约处理。

针对新增的 Schema 继承候选，新增/替换基类、改抽象类型或修改基类字段/公式/索引，须展开全部后代有效定义，检查具体实体表、分表、存量数据、Link 端点及运行参数。纯类型匹配变化也可能使已有关系失效。需维护迁移时按受影响范围暂停、排空、回填、验证并协调替换当前定义/映射/方向发现后恢复；Metadata 和 Data 的多步操作不假定分布式原子事务。任何后代未完成就保持该范围暂停，失败可恢复，不用业务 version 保留新旧有效结构并行运行。完整类型规则见 [Schema](模块/Schema.md)。

生效协调必须阻止依赖在“检查完成”与“替换当前定义”之间被并发修改；读取请求在开始时取得一致的当前定义及依赖内容，在该次操作内复用。不能边执行边重新取最新定义，拼成从未生效过的组合。具体锁及跨服务校验协议在实现时确定。

## 3. 数据库迁移与失败恢复

| 类型 | 对象 | 记录内容 |
| --- | --- | --- |
| 平台数据库迁移 | 元数据、任务、调度等服务自身的数据表 | 软件迁移编号、校验和、执行状态及失败进度 |
| 模型数据/结构变更 | Schema、Enum、Link 变更引起的实例、关系、索引及物理结构 | 操作 ID、变更前后摘要、计划、数据验证、进度及恢复措施 |

软件、API、数据库引擎和运行时的版本仍按其工程规则管理；它们与业务定义 version 分开。迁移记录的操作 ID 用于恢复一次操作，不是定义版本，也不成为实例或定义引用字段。

Data 执行模型迁移，各服务执行自己的平台迁移，共用 [存储引擎](存储引擎.md) 的目录、方言及执行设施。迁移可由命令或 Job 执行，服务启动及普通查询不调用 AutoMigrate 修改结构。

多副本迁移需持久化互斥和旧执行者隔离。涉及 DDL 的跨服务步骤不假定原子事务，MySQL、PostgreSQL、达梦分别验证事务 DDL、锁及在线能力。大规模回填分批执行并保存进度；不能仅靠外层事务假装可以撤销全部变化。

首期对删字段、缩小类型、变更单位、删除使用中的 Enum 编码、收紧 Link 基数等不兼容变更，采用受影响范围的维护流程：暂停新读写及执行 → 等待运行中操作排空或显式停止 → 迁移并验证 → 替换当前定义及映射 → 清理缓存 → 恢复访问。排队任务恢复后重新读取并校验当前定义。不中断业务的兼容扩展只在适配器及缓存一致性已验证时开放。

失败时不将候选定义标为当前。若数据库尚未改变，可继续使用原当前定义；若结构已部分改变且无法证明原定义仍安全，保持受影响范围暂停，按记录恢复或向前修复，不能自动恢复流量。操作状态可包括 preparing、applying、succeeded、failed、needs_repair，具体协议待实现。

修改描述和中文业务名称更新元数据，不因改名修改内部 ID 或物理表列名。Schema/属性/Link 主名称及方向名变更须校验对应范围的名称冲突，并同步更新名称登记、发现索引及名称缓存；已保存的定义、公式与查询保留原 ID 绑定并更新展示。重新提交的未绑定文本按当前名称解析，不自动保留旧名别名；删除后同名新建不得接管旧引用。命名规则统一见 [组织与隔离](组织与隔离.md)。修改单位、类型或业务编码需要迁移已有数据，不能用最新定义给旧数值换含义。历史事实若无法迁移，必须保留其实际单位、量类型、原始值等自描述上下文，或拒绝原地变更并新建不同 ID 的业务概念。审计日志及备份用于追踪和恢复，不提供任意切回历史定义的运行入口。

计算属性的公式、依赖、Function 实现或计算策略变化时，将物化值、索引、当前依赖图及后台任务一起纳入影响检查。物化字段首期先暂停相关操作、回填并验证后替换当前定义，旧公式任务不得提交，新公式结果不能混入旧公式值。virtual 变更校验后失效旧计划即可。内部内容摘要仅用于防止过期结果，业务仍按稳定 ID 读取单份当前定义；结果按当前公式计算与源数据是否已刷新分别判断。完整规则见 [Schema](模块/Schema.md)。

分表布局、取值来源/快照语义、规则或已有范围/值集合归属变化时，检查实例搬迁、全局定位/唯一性、成员索引、Link 约束和计算依赖；增加 hash 桶数不能直接切换路由。受影响范围排空后迁移，Data 的唯一当前路由与 Metadata 定义通过持久生效协调共同切换，跨服务步骤不假定事务原子性；完成前保持暂停，旧执行者不能写原成员。关联源普通属性更新默认不搬迁旧实例；如要求随父对象共置，须显式维护搬迁。按已生效规则提前或按需建成员也须经受控入口验证后登记，反向源成员只读发现和校验。详细规则及 SCHEMA-09～SCHEMA-14 见 [Schema](模块/Schema.md)。

### 默认存储迁入专用源（2026-11-07）

当前已实现[显式离线维护命令](../tools/storage_relocation/README.md)，仅支持同租户、同分类的默认 MySQL `schema_2_db / single` 模型迁入同一显式专用 MySQL 数据源。一次1至16个模型，每模型全部属性映射到一个新主表；模型、属性、索引和实例ID、逻辑类型与约束保持不变，不改变建模方向。拒绝现有草稿、未完成发布、已绑定相关Link、已有目标表接管及过期来源摘要；普通表单/发布仍拒绝随意重绑。

固定清单包含每模型独立操作ID、原当前定义/摘要、候选定义/摘要和数据源ETag；服务启动与普通请求不执行该命令。维护前备份并停止本地Metadata/Data及其他写入方，命令持有两控制库的租户维护锁。Data一次关闭整批gate并排空旧事务，再编译目标表、索引和所有权标记，复制当前租户的稳定实例ID及全部业务列，校验NULL、空串、精确数值、时间和完整正文；不复制平台tenant_id/etag系统列，不修改或删除原表。每表预算10,000行/64MiB，整批128MiB；持久步骤绑定完整排序清单，拒绝以子集恢复或覆盖不一致的目标数据。

目标核验完成后保持prepared；Metadata在单个本地事务更新整批当前定义，新增succeeded发布记录及`definition.storage_relocated` outbox，事件payload为完整的单模型迁移清单项，包含原/新定义及来源摘要。同一操作重入须匹配原证据，不修改历史发布；最后核对Metadata和目标数据，再一次将整批gate恢复ready。跨服务步骤不是分布式原子事务；失败后保留暂停并用同一固定清单恢复，不自动回滚或恢复流量。该实现仅认证本地单实例维护，不覆盖生产多副本隔离、备份恢复或任意类型的模型迁移。

迁移后的旧游标因模型摘要/来源变化失效。显式源实例读写范围仍以[Schema](模块/Schema.md)和[数据源](数据源.md)为准，目前实例写入不开放；迁移不自动取得写入能力。相关未绑定Link在全部对象迁移完成后，通过正常草稿/发布配置同源外键或关联表。

## 4. 请求、任务与缓存

新请求读取当前生效定义；排队任务在首次实际开始执行时解析最新 Action/Function 及依赖并重新校验输入、权限和目标。目标已删除、停用或输入不再合法时明确失败，不自动回退旧定义。

执行开始后，在同一任务记录中保存实际采用的输入输出约束、单位、目标及实现制品摘要等必要内容，运行和重试沿用该任务上下文，不中途切换代码或参数规则。该记录仅服务于本次执行、核对和审计，不可作为旧定义向其他任务开放。权限撤销及租户检查仍然即时执行。无法按原上下文安全重试时停止并核对，不偷偷换成当前实现；详细规则见 [执行与调度](执行与调度.md)。

所有业务读写仍须满足当前数据约束，任务上下文不是绕过 Data 当前校验的通道。与运行任务不兼容的结构或定义变更必须先排空任务，不能一边删除字段，一边承诺旧任务继续使用它。

定义及查询计划缓存按 tenant_id、对象 ID、当前内容摘要、权限和映射等实际条件隔离。每次使用需校验权威的当前状态/摘要；失效事件用于加速，不能仅靠事件或 TTL 容忍生效后继续读旧定义。权威状态不可确认时受影响操作失败或重试；在没有完成这一机制前可先关闭相关缓存。跨服务生效期间使用持久化暂停状态和入口检查阻止旧实例继续接收请求。

名称到 ID 的缓存还须包含解析范围与规范名称键，并在使用时校验当前名称登记及权限。已绑定查询始终检查原 ID 的当前定义，不将“原 ID 不存在”降级成按文本查找同名对象；名称来源仅用于编辑和说明，不能覆盖实际绑定。

历史查询结果及任务结果应保存与实际值匹配的字段描述、单位、必要执行内容及来源，读取历史记录不通过当前 Schema 猜测原含义。不承诺恢复任意过去时间的完整定义。

## 5. 验收

| 编号 | 要求 | 验收方法 |
| --- | --- | --- |
| PUB-01 | 统一维护一份当前定义，平台迁移与模型变更分别记录 | 五类接口及引用无业务 version；仅可读取当前定义及编辑草稿，操作 ID 不可用作旧定义调用 |
| PUB-02 | 预览、依赖检查及迁移成功后才生效 | 草稿不影响业务；过期预览、跨租户及并发依赖变更被拒绝；两个 Schema 模式遵守 DDL 边界 |
| PUB-03 | 迁移并发安全、失败可恢复，旧执行者不能提交 | 两副本争抢、回填中断及部分 DDL 失败可核对；结构不一致期间保持暂停 |
| PUB-04 | 新操作用当前定义，已开始任务保持执行一致性 | 生效后两副本读取相同当前定义；排队任务取最新，运行任务不换代码；破坏性变更排空任务，失效缓存不能继续服务 |

## 6. 待定事项

需明确目标数据库版本、ETag 及依赖并发校验、跨服务暂停/恢复协议、迁移互斥、缓存权威校验成本、任务上下文保留期和备份恢复方式。五类对象的单份当前定义原则已确定，具体工程协议尚待验证；不承诺所有变更在线无停机。
