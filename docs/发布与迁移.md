# 定义生效与数据库迁移

状态：统一采用单份当前定义，不提供业务 version。本文维护完整生效设计；已有首次发布与展示变更的持久协调，2026-11-08已补默认平台 Schema 安全追加迁移。破坏性结构迁移及通用运行任务排空继续后续，分项实际能力与验证见[项目总览](项目总览.md#当前实现与验证2026-11-06)。

## 当前实现协议（2026-11-06）

首批 Metadata 以持久租户 guard 串行化定义编辑/发布；Data 以持久 Schema 入口状态和同事务锁隔离普通读写。发布依次执行：固定草稿及操作 ID → Data 在已有事务完成后暂停该 Schema → 校验并准备受管理结构 → Metadata 在本地事务中替换当前定义、名称、依赖并写 outbox → Data 从 Metadata 核对权威当前摘要 → 激活入口 → 清理 Metadata guard。网络调用不包在 Metadata 长数据库事务中，不假定两服务共享原子事务。

相同在途操作重试恢复原操作 ID；激活失败保留暂停并重试激活，不重新产生定义事件。历史上出现过相同内容不能替代当前发布意图，例如改名 A→B→A 必须实际重新协调生效，不能查到历史成功记录就返回成功。发布操作记录不是可供选择的业务定义版本。

首次生效和存储签名不变的展示修改沿既有流程执行；默认平台 Schema 的安全追加按下节扩展，Enum 的增值、标签及废弃规则见[Enum](模块/Enum.md#当前实现协议2026-11-08)。其余字段类型、既有约束及破坏性变更仍明确拒绝。已知不支持的布局、属性和行宽等在暂停前拒绝；DDL 已部分发生或结果不明时保持暂停，按实际结构核对恢复，不能假报回滚。平台迁移通过服务 `-migrate` 显式执行，失败/中断进入待修复记录，由存储模块的显式核验恢复接口处理，不在服务启动或普通请求中自动重跑。

草稿和 active 是本轮开放的定义状态；停用、定义删除及名称释放尚未开放。完整生命周期、反向源身份/漂移、备份恢复和运行任务排空继续按后续设计推进。首批细节见[开发指南](开发指南.md)及所属服务说明；以下章节中的完整目标不等于本轮均已交付。

2026-11-07补齐Function及直接源码Action内联Python实现的发布与更新：runtime作为所属当前定义的一部分保存，同样复用草稿、ETag、依赖检查和持久发布协调；源码/入口/超时可更新，未绑定函数或产物的既有纯计算定义可补充源码。输入输出签名、副作用和已有实现引用仍受结构限制，绑定Action不能改为直接源码，发布Function时复核当前绑定Action的签名。新调用使用新源码，已开始调用保留本次快照，不执行数据副作用；当前定义变化后旧结果整体拒读。首批不排异步队列，也未实现通用运行任务排空或跨服务原子撤权，协议分别见[Function](模块/Function.md)、[Action](模块/Action.md)、[执行与调度](执行与调度.md)及[权限设计](权限/权限设计.md)。

2026-11-08用户确认将JavaScript与Go加入同一源码实现协议：语言、源码、入口和超时随所属定义保存草稿并发布，不新增业务version或平行生效实现。编辑语言只改变草稿；普通调用在发布成功前继续使用当前代码，已保存草稿只能通过明确的草稿试运行执行。绑定Action仍引用Function当前实现，不能隐式复制或切换为直接源码；语言对应的容器与源码工具能力见[Function](模块/Function.md#javascript与go扩展2026-11-08已确认)，本轮验证状态见项目总览。

## 默认平台Schema安全追加（2026-11-08）

本批沿既有 Metadata 租户 guard 与 Data Schema gate 实现安全追加迁移，支持范围唯一见[Schema](模块/Schema.md#默认存储安全追加迁移2026-11-08用户已确认)。Data 新增平台迁移 `010_data_schema_migrations`，创建 `af_data_schema_migrations`；更新部署须显式执行 Data `-migrate`，普通启动、请求和预览不创建平台控制表。

迁移记录绑定租户、原当前定义、目标摘要和唯一操作 ID。预检使用同一追加校验及计划编译逻辑；执行在持久关闭 gate、排空已入场事务后按实际目录应用新增列、固定值回填和新增索引，核验后才交给 Metadata 提交新当前态并激活。MySQL DDL 不支持跨步骤业务回滚：部分 ALTER、网络中断或结果不明必须保留暂停，使用原操作及原草稿 ETag 重试核对实际进度，不创建新操作覆盖半完成结构。

新增属性改变既有对象的可见状态，回填事务同时轮换已有行 ETag，使迁移前 `If-Match` 失效；仅新增索引不改变对象值。对象 ID、旧属性 ID、旧业务编码和幂等证据保留。旧游标因当前模型摘要变化失效，旧成功回执须按当前定义及权限重新核对，不能返回缺失新增属性的旧对象形状或盲目重复执行写入。

服务端解析出的 Enum 选项与其摘要属于逻辑依赖，不写入持久定义或物理存储签名；已有属性更换 Enum 绑定仍属未开放变更。备份须包含新增迁移记录、Data gate、回执和 outbox。开发环境的隔离测试、单后端恢复和现网部署分别记录，不将本节描述为生产恢复、三库迁移或零停机认证。

首批仍使用普通DDL与整表回填，需评估维护窗口和数据量；超过请求预算可保持暂停，按原发布请求恢复。未实现分块回填、在线大表迁移或生产容量保证。回填和一次性标记同事务，恢复不重复轮换已完成回填的行ETag；仅追加索引也不触发行ETag变化。

## 1. 所有定义统一采用当前态

每个对象只有一个稳定 ID、一份当前生效定义，最多保留一份可编辑草稿。草稿用于预览及变更校验，不参与普通业务读取和调用；Function/Action仅可通过[明确的草稿试运行](执行与调度.md#草稿试运行2026-11-08)执行已保存草稿，不替换当前代码。生效成功后替换当前定义并清理草稿，原草稿运行结果按所属协议拒绝交付。首次创建尚未生效的对象不能被其他业务定义引用。

五类定义及其引用均不携带 `version`，引用形式为 `{ "id": "<稳定 ID>" }`。新请求、新查询及新开始的执行按当前生效定义处理。不提供语义版本号、历史定义选择、指定旧定义调用、定义分支、多份生效定义或跨类型版本发布集。`latest` 也无需作为字段或别名保存。

| 对象 | 修改生效前检查 |
| --- | --- |
| Schema | 字段、约束、索引、单位、实例数据、分表规则/目录、物理映射及所有引用方；采用继承候选时还检查基类、全部后代的有效定义及具体类型匹配 |
| Enum | 当前取值、字段/参数/默认值引用及已存业务编码；被使用的取值不可直接删除 |
| Link | 两端 Schema、自动正反向视图、关系事实、基数、重复及删除规则；采用关系语义候选时还检查组合归属、拓扑范围、子类型端点、排序权威来源及上下文/属性/有效时间 |
| Action | 目标、输入输出、权限、效果、实现引用及运行中的调用 |
| Function | 输入输出、实现制品、权限、副作用及运行中的调用 |

依赖按 ID 解析，更新被引用对象时同步检查当前引用方、订阅及周期规则，不能因 ID 未变就跳过校验。不兼容变更需先调整依赖和数据；无法逐步兼容时，暂停受影响范围后协调生效，首期不建立通用的多对象发布集机制。租户、分类、分组及命名规则见 [组织与隔离](组织与隔离.md)。

细粒度权限为新增候选，统一见[权限设计](权限/权限设计.md)：策略绑定的字段、类型、Link、Action/Function 及组织作用域也属于变更依赖，删除/类型变化和移组不能跳过影响检查。策略当前态、内部授权标记、成员变更、撤权串行边界和缓存校验由权限专题维护，不引入五类定义的业务 version，后续验证引用 AUTH-09～AUTH-10。

### 直接定义依赖查看（2026-11-16，已实现）

首批依赖影响查看使用 `GET /metadata/definitions/{id}/dependencies?view=current|draft`，省略view时为current；只接受一个view参数，其他查询参数明确拒绝。能力响应声明 `dependencyImpact=direct-definitions`。公开DTO见[dependency_impact.go](../contracts/dependency_impact.go)，服务入口及网关路径见[Metadata](../services/metadata/README.md)。

返回 `scope=direct-definition-references`、所选定义摘要 `definition`、向外引用 `dependencies` 和引用方 `dependents`。摘要包含稳定ID、类型、名称、分类/分组ID、current/draft视图及该视图ETag，不返回源码、物理映射、属性正文或业务数据。向外引用指向当前生效目标；引用方同时检查当前定义和已保存草稿，分别列出，不将草稿引用登记为当前生效依赖。包含同租户合法跨分类引用，不按工作台当前分类截断。

| 原因码 | 已实现的直接引用 |
| --- | --- |
| enum | Schema属性、Action/Function输入输出的enumId |
| link-source / link-target | Link两端Schema；自关联合并为一项并保留两个原因 |
| action-target | Action关联的Schema |
| data-write | Action/Function声明的业务写入Schema |
| record-read | Action 声明读取当前记录的 Schema |
| implementation | Action绑定的Function |

所选current视图要求该定义definition.read，draft要求definition.edit；向外目标要求当前definition.read，引用方按current/read、draft/edit逐项检查。首次无权查看的关联项直接省略，没有隐藏计数、占位符或游标。所选视图无权或不存在统一404；授权服务异常不降级为空列表。交付前再次核验所选视图及全部可见关联项，撤权时整份拒绝，不交付已收集结果。复核授权后批量核对已纳入报告的当前或草稿摘要，发现视图消失或内容变化时返回 409 `dependency_context_changed`。新增引用仍可能出现在读取快照之后。公共权限规则由[权限设计](权限/权限设计.md)维护；服务凭据和MCP外部凭据不开放此入口，OntoApp业务表单别名也不代理此管理接口。

实现以租户内REPEATABLE READ只读事务获得当前/草稿的一致快照，先校验数量与JSON长度，通过预算后再传输正文；不获取发布写锁、不调用Data、不迁移或读业务表。扫描上限1000个定义、当前与草稿JSON累计8MiB、单份JSON1MiB、4096条去重的视图到目标边；每个方向最多200项可见结果。超出任一预算返回422 dependency_budget，整份拒绝且不分页、不截断。当前没有按分类缩小扫描范围的参数；大目录需后续完善索引后扩容。

报告只覆盖直接定义引用，不递归展开，不包含业务数据、权限策略、个人保存查询、运行任务和外部应用。它是查看时的快照，响应中的ETag不构成删除许可或引用锁。零条可见引用不能证明无依赖，也不能据此停用、恢复或删除；后续生命周期写操作仍须在权威串行边界检查全部引用与实际数据，沿上述单份当前定义原则实施。
#### 已支持的停用与恢复预览

无副作用且未声明写入的 Action 和 Function 支持 `GET /metadata/definitions/{id}/disable-preview` 和 `GET /metadata/definitions/{id}/restore-preview`。能力声明为 `callableLifecyclePreview=true`。调用要求 `definition.read`、`definition.publish` 和当前视图的强 `If-Match`。通过时返回定义 ID、目标状态和当前 ETag 响应头。工作台在服务声明此能力时先请求预览，成功后显示确认按钮，阻断时直接展示服务端原因。预览在只读事务中检查发布状态、草稿、定义引用及恢复依赖。若存在引用，只返回通用阻断原因，不透露引用方名称、ID 或数量。正式操作在租户写入串行边界再次执行校验，预览后新增草稿或引用仍可阻断。Action 草稿绑定 Function 时使用相同的租户锁，停用后新建或更新草稿均不能再绑定该 Function。

正式停用、恢复或删除应分别定义阻断条件。以下检查由持有实际状态的服务执行，具体接口和并发控制待实现。

| 业务实例和关系 | Data 已支持[托管单表对象和关系存量检查](../services/data/README.md#托管实例与关系存量检查)。正反向映射对象可检查主表存量。映射 Link 和间接引用仍待实现。停用保留数据；删除要求确认相关范围无存量。无法确认来源状态时中止删除。 |

预览时间与正式操作之间可以新增引用或任务。正式操作应重新读取权威状态，并以各服务的准入控制约束检查到状态变更之间的新操作。预览权限限制仅用于展示，不能从正式操作的阻断检查中排除不可见引用。

工作台五类定义编辑页均提供“查看定义依赖”，按需读取；已有当前态的草稿可切换两个视图，显示引用原因和跨分类标记。未保存修改或待确认发布时不显示旧报告；刷新、保存内容变化、切换视图或离页会清理旧结果并取消在途请求。这里的草稿指服务端已保存内容，不分析未提交编辑器内容。

### 无副作用调用定义的停用与恢复

Metadata 能力 `callableLifecycle=pure-only` 开放当前已生效、无副作用的 Action 和 Function。在工作台定义详情确认操作，或向 `POST /metadata/definitions/{id}/disable`、`POST /metadata/definitions/{id}/restore` 提交当前内容的 `If-Match`。两项操作要求 `definition.read` 和 `definition.publish`。

停用请求在租户发布锁内检查已保存草稿、当前引用及草稿 Action 对 Function 的引用。受引用时返回通用冲突，不返回不可见的定义详情。恢复在同一边界重新验证外部定义引用。成功后保留名称、ID、原有授权配置和内容摘要，状态在 `active` 与 `disabled` 间切换，并记录 Metadata outbox 事件。向已经处于目标状态的定义重复提交同一内容摘要不会重写状态或重复记录事件。

停用预览和正式操作还检查当前及草稿权限策略中的定向 `action.invoke` 或 `function.invoke` 引用。存在引用时返回 `409 definition_policy_in_use`，响应只提示联系权限管理员。通配授权和定义管理权限不影响停用。正式操作在同一事务内读取并锁定权限策略，串行化策略保存、发布和停用。

停用定义保留在管理详情和定义列表，调用目录及 Execution 当前态调用不开放；停用期间拒绝草稿保存、发布、新调用及历史结果交付。已开始的纯计算可能继续完成，结果交付仍检查当前定义状态。摘要用于确认内容，未记录状态转换历史版本。Schema、Link、带数据写入的调用定义及删除仍待后续。

### Enum 停用与恢复

已发布 Enum 可使用相同的停用／恢复预览及正式接口，权限仍为 `definition.read` 和 `definition.publish`。停用前检查本身是否有未发布草稿、模型或调用定义的当前／草稿枚举引用，以及 Data 中保存查询参数的直接引用。正式操作在租户发布锁内重新检查，影响报告超过预算或 Data 无法确认时拒绝，响应不包含引用方身份。

停用保留稳定 ID、名称、编码与摘要。停用期间管理详情仍可读取，运行时枚举解析和新引用要求生效状态。现有实例行和调用参数通过其所属定义间接引用 Enum，因此仍有引用的模型或调用定义会阻止停用。Enum 无独立实例存储或专用业务授权资源。Data 保存查询复查跨服务进行，独立的元数据和保存查询事务之间仍存在并发窗口。恢复后重新允许按稳定 ID 引用。

### 托管 Link 停用与恢复

仅开放默认平台托管关系。Metadata 复用定义生命周期的预览、权限和并发凭证，Data 在正式停用时独占关系存储门，等待使用该门的事务结束后检查实际边和租户保存查询引用。定向关系策略的当前态或草稿引用会阻止停用。结果仅说明阻断类别。

成功停用时，Data 先暂停关系存储门，Metadata 再持久保存停用状态。保存查询写入与停用使用同一关系存储门，关系查询和写入在取得门后复核 Metadata 当前状态。恢复复核两端定义及存储，再重新启用。保留关联定义 ID、原物理表及授权配置。外部映射关系未开放本操作。

跨服务请求中断后可用同一凭证重试原操作核对。如果 Data 已暂停而 Metadata 仍显示生效，保持不可运行，权限管理员可按阻断原因处理后重试停用，或显式调用恢复入口重新启用存储。

### 托管 Schema 停用与恢复

Enum、托管单表 Schema 和平台托管 Link 的停用预览及正式停用遇到保存查询扫描超限时，返回 HTTP 422 `saved_query_impact_budget`。此次操作无法确认是否可停用，超限时保留原状态。

Data 在只读事务中执行托管定义的生命周期预览，响应禁止缓存。托管单表 Schema 和平台托管 Link 的停用、恢复都复核实际物理结构，发现结构变化时返回 `mapping_unavailable`。默认平台 `schema_2_db` 单表使用相同的预览、权限和并发凭证。停用前检查当前及草稿定义引用、当前及草稿的定向实例策略和对象取值引用、保存查询引用以及对象存量。正式操作通过 Data 存储门等待在途事务。保存查询的 Schema 和 Link 引用也在写入事务中锁定相应存储门。

停用保留定义 ID、名称及物理表。Data 先暂停存储门，Metadata 再记录停用状态。恢复复核 Schema 的引用和物理表，在门内访问仍复读 Metadata 生效状态。跨服务中断沿用托管 Link 的重试及恢复方式。映射来源及非单表 Schema 继续后续。

### 记录生命周期变更（2026-11-25 首批实现）

记录生命周期（阶段与流转）随 Schema 当前定义发布，属于运行配置而不是物理结构，因此不触发 DDL 或安全追加迁移；校验与协议见 [Schema](模块/Schema.md#记录生命周期2026-11-25-首批实现)。发布只替换定义，不迁移已有记录：Data 按记录保存当前阶段和历史，记录阶段已从新定义移除时报告该阶段未知并拒绝继续流转，必须由业务显式处理，不能按新定义自动猜测目标阶段。

### 受控删除（LC-03）

Metadata 已实现从未发布且无发布记录的草稿删除。具备删除策略检查组件时，能力接口返回 `unpublishedDraftDelete=true`，客户端可据此展示草稿删除入口。`GET /metadata/definitions/{id}/delete-preview` 和 `DELETE /metadata/definitions/{id}` 均要求 `definition.edit`、`definition.publish` 和草稿的强 `If-Match`。通过时返回 204。正式操作复查当前及草稿定义引用和策略引用，并在租户写入事务中清空草稿内容、保留稳定 ID 与名称占用、记录删除事件。同一摘要重试不会重复记录。标准管理网关已允许这两条精确路由并转发 If-Match。隔离 Nginx 已验证正确方法和路径、OntoApp 别名拒绝及日志隐私。工作台的 Schema、Enum、Action、Function 编辑页已接入，删除前请求预览并由用户确认，成功后返回并刷新目录。关系编辑器沿用同一删除流程。

已停用且没有草稿的 Enum 可通过同一路由预览和删除，使用当前定义的强 If-Match。删除时复查未完成发布、定义引用、策略和保存查询，保留稳定 ID、名称占用和删除审计。Metadata 通过 `disabledEnumDelete` 声明此能力，工作台在已停用的 Enum 编辑页提供预览和确认入口。

已停用且无草稿的托管单表 Schema 和平台托管 Link 也可通过同一路由删除。Metadata 在正式删除时重新调用 Data 预检，要求存储门已关闭且物理结构、存量和保存查询检查通过。存在独立保留的记录（包括评论回复已读记录）时返回 `definition_retained_records`，响应只提供阻断类别。删除事务清除定义的出向依赖并记录审计。工作台按 disabledManagedStorageDelete 能力显示删除入口，隔离 Edge 搭配模拟 HTTP 验证两类定义的双主题和 1440px、390px 交互。隔离 MySQL 搭配模拟 Data HTTP 验证 Schema 预检失败时保持停用，复查通过后可删除。

已停用且无草稿的无副作用 Action 和 Function 可使用同一接口。Metadata 配置 ONTOLOGY_EXECUTION_URL，预览与删除均复查未完成的直接调用和作为绑定实现的调用。有未完成执行时返回 definition_execution_in_use，执行检查不可用时拒绝删除。隔离 MySQL 搭配模拟 Execution 验证预览后复查、失效响应、重试及删除后拒绝恢复。设置 ONTOLOGY_TEST_EXECUTION_DSN 可运行模型演进套件中的真实 Metadata/Execution 检查。实测绑定实现的调用记录在预览之后写入时，正式删除返回 409，调用进入终态后重试成功。该用例直接创建持久调用记录，Metadata 在已配置执行地址和服务凭据时通过 disabledCallableDelete 公布能力。工作台复用删除预览和确认，Edge 使用模拟 HTTP 验证双主题与桌面、窄屏。同一套件通过公开调用接口配合可暂停的测试运行器，验证运行中停用会阻断删除和结果交付，运行进入终态后可删除。同步调用在写入前暂停，删除完成后再写入时，Execution 复查当前定义，将调用记为授权变化失败且不会启动运行器。异步接纳竞态仍待验收。

以下为其余停用定义删除及完整验收的候选方案。

删除预览允许选择从未发布的草稿，或者已经停用且没有草稿的定义。当前生效定义必须先停用。预览和确认均要求管理权限及强 If-Match，摘要针对待删除的视图。正式请求在 Metadata 租户写入锁内重新读取状态、摘要和发布操作，不能沿用预览结论。只要发布、迁移、待执行或未确认提交的业务操作仍涉及该定义，就阻断删除。

Metadata 检查租户内当前和草稿定义的直接引用，并在策略写入锁内检查当前与草稿策略，包括定向定义管理授权、业务访问授权及行条件中的对象取值。Data 检查全部所有者的保存查询、对象与关系存量，以及可能独立保留的业务附件和评论。无法在预算内确认、依赖服务不可用或外部来源无法判空时返回阻断原因。对外只返回阻断类别，不返回引用方 ID、名称、数量或物理表名。

正式删除采用保留稳定 ID 的逻辑删除。删除标记和审计事件在同一 Metadata 事务写入，事件记录操作者、租户、定义 ID、类型和被确认的摘要。删除后管理列表、当前和草稿读取、执行及恢复入口都拒绝使用该 ID。同一操作重试不得新增审计事件。托管数据表和存储门保留，删除前保持存储门停用。物理清理须另行定义所有权、审计保留期和故障恢复，映射源表不由本操作删除。

验收覆盖活动定义、有草稿的停用定义、引用与存量阻断、预览后新增引用、旧 ETag、跨租户、重复请求和审计事务回滚。先交付无需跨服务物理清理的逻辑删除，再覆盖各类型的业务及外部依赖。

## 2. 保存、预览与生效

建议流程：`编辑/保存草稿 → 预览及影响检查 → 必要的数据/结构迁移 → 校验 → 替换当前定义 → 清理草稿并恢复访问`。不影响存储的变更可合并校验和生效步骤；保存草稿不自动影响当前业务。

Metadata 拥有五类当前定义、草稿、依赖及生效状态；Data 拥有实例、关系、数据源、物理映射和实际迁移。定义、操作记录和迁移目标均归属一个 tenant_id，禁止跨租户引用。

`schema_2_db` 根据当前定义、草稿及实际目标结构编译迁移计划，创建或调整受管理表和索引，验证成功后生效。`db_2_schema` 校验源结构并替换当前逻辑映射，不执行修改源库的 DDL；发现结构漂移先暂停不再安全的操作，不静默覆盖当前映射。详细边界见 [Schema](模块/Schema.md)。

预览关联草稿内容摘要、当前定义及依赖摘要、目标数据源、实际结构摘要、驱动能力信息。任何相关内容改变，旧预览及计划失效；正式生效重新校验。SQL 预览和执行复用同一计划编译，不接受客户端回传的任意 SQL。摘要只用于校验内容是否变化，不提供按摘要选择历史定义的接口。

外部来源的实际产品、版本和关键配置检查统一见[数据源版本管理](数据源.md#数据库版本选择与校验2026-11-07已确认并实现)。当前发布重新打开受检查连接、读取目录并编译，不能凭升级前预览直接执行；版本变化不自动触发平台迁移或重绑。

Metadata 的定义替换、名称登记、依赖更新及所属 outbox 在本地事务完成；并发编辑可用 ETag/If-Match 或等价条件更新拒绝覆盖。ETag 是自动生成的并发校验凭证，不是用户维护的定义版本，不保留可选择的历史 ETag。

Link 生效同时向两端提供当前方向视图，草稿只预览，停用/删除及端点变化一并处理两个方向的依赖、发现索引和缓存。它们共用一个当前 Link ID，不单独发布反向定义，也不为生成视图复制或回填倒置端点的业务边；基数或端点变化引起的实际数据迁移仍须验证。完整行为见 [Link](模块/Link.md)。

针对新增的关系语义候选，普通关联改为组合或收紧为树/DAG 前，须扫描整个声明范围的已有边，检查独占归属、父数量及环，准备相应归属登记/并发约束并验证后才生效；不能仅改类型标签或自动删除冲突关系。删除策略、共同约束范围、端点子类型匹配变化也须纳入预览及影响检查。

启用或改变有序成员、直接前后链、上下文范围、对称/派生规则、关系属性及有效时间时，预览现有关系的排序补全、重复/区间重叠、属性转换和约束变化；歧义顺序不能按设备 ID 或创建时间自动当作真实业务顺序。需要重建事实或索引时先在受影响范围协调迁移并校验，唯一权威顺序和派生导航一起切换，旧游标/缓存失效。普通成员拖动、安装有效时间等是实例事实变化，不替换 Link 定义、不引入业务 version，仍按相应事务及审计契约处理。

针对新增的 Schema 继承候选，新增/替换基类、改抽象类型或修改基类字段/公式/索引，须展开全部后代有效定义，检查具体实体表、分表、存量数据、Link 端点及运行参数。纯类型匹配变化也可能使已有关系失效。需维护迁移时按受影响范围暂停、排空、回填、验证并协调替换当前定义/映射/方向发现后恢复；Metadata 和 Data 的多步操作不假定分布式原子事务。任何后代未完成就保持该范围暂停，失败可恢复，不用业务 version 保留新旧有效结构并行运行。完整类型规则见 [Schema](模块/Schema.md)。

生效协调必须阻止依赖在“检查完成”与“替换当前定义”之间被并发修改；读取请求在开始时取得一致的当前定义及依赖内容，在该次操作内复用。不能边执行边重新取最新定义，拼成从未生效过的组合。具体锁及跨服务校验协议在实现时确定。

## 3. 数据库迁移与失败恢复

| 类型 | 对象 | 记录内容 |
| --- | --- | --- |
| 平台数据库迁移 | 元数据、任务、调度等服务自身的数据表 | 软件迁移编号、校验和、执行状态及失败进度 |
| 模型数据/结构变更 | Schema、Enum、Link 变更引起的实例、关系、索引及物理结构 | 操作 ID、变更前后摘要、计划、数据验证、进度及恢复措施 |

软件、API、数据库引擎和运行时的版本仍按其工程规则管理；它们与业务定义 version 分开。迁移记录的操作 ID 用于恢复一次操作，不是定义版本，也不成为实例或定义引用字段。

Data 执行模型迁移，各服务执行自己的平台迁移，共用 [存储引擎](存储引擎.md) 的目录、方言及执行设施。迁移可由命令或 Job 执行，服务启动及普通查询不调用 AutoMigrate 修改结构。

多副本迁移需持久化互斥和旧执行者隔离。涉及 DDL 的跨服务步骤不假定原子事务，MySQL、PostgreSQL、达梦分别验证事务 DDL、锁及在线能力。大规模回填分批执行并保存进度；不能仅靠外层事务假装可以撤销全部变化。

首期对删字段、缩小类型、变更单位、删除使用中的 Enum 编码、收紧 Link 基数等不兼容变更，采用受影响范围的维护流程：暂停新读写及执行 → 等待运行中操作排空或显式停止 → 迁移并验证 → 替换当前定义及映射 → 清理缓存 → 恢复访问。排队任务恢复后重新读取并校验当前定义。不中断业务的兼容扩展只在适配器及缓存一致性已验证时开放。

失败时不将候选定义标为当前。若数据库尚未改变，可继续使用原当前定义；若结构已部分改变且无法证明原定义仍安全，保持受影响范围暂停，按记录恢复或向前修复，不能自动恢复流量。操作状态可包括 preparing、applying、succeeded、failed、needs_repair，具体协议待实现。

修改描述和中文业务名称更新元数据，不因改名修改内部 ID 或物理表列名。Schema/属性/Link 主名称及方向名变更须校验对应范围的名称冲突，并同步更新名称登记、发现索引及名称缓存；已保存的定义、公式与查询保留原 ID 绑定并更新展示。重新提交的未绑定文本按当前名称解析，不自动保留旧名别名；删除后同名新建不得接管旧引用。命名规则统一见 [组织与隔离](组织与隔离.md)。修改单位、类型或业务编码需要迁移已有数据，不能用最新定义给旧数值换含义。历史事实若无法迁移，必须保留其实际单位、量类型、原始值等自描述上下文，或拒绝原地变更并新建不同 ID 的业务概念。审计日志及备份用于追踪和恢复，不提供任意切回历史定义的运行入口。

计算属性的公式、依赖、Function 实现或计算策略变化时，将物化值、索引、当前依赖图及后台任务一起纳入影响检查。物化字段首期先暂停相关操作、回填并验证后替换当前定义，旧公式任务不得提交，新公式结果不能混入旧公式值。virtual 变更校验后失效旧计划即可。内部内容摘要仅用于防止过期结果，业务仍按稳定 ID 读取单份当前定义；结果按当前公式计算与源数据是否已刷新分别判断。完整规则见 [Schema](模块/Schema.md)。

分表布局、取值来源/快照语义、规则或已有范围/值集合归属变化时，检查实例搬迁、全局定位/唯一性、成员索引、Link 约束和计算依赖；增加 hash 桶数不能直接切换路由。受影响范围排空后迁移，Data 的唯一当前路由与 Metadata 定义通过持久生效协调共同切换，跨服务步骤不假定事务原子性；完成前保持暂停，旧执行者不能写原成员。关联源普通属性更新默认不搬迁旧实例；如要求随父对象共置，须显式维护搬迁。按已生效规则提前或按需建成员也须经受控入口验证后登记，反向源成员只读发现和校验。详细规则及 SCHEMA-09～SCHEMA-14 见 [Schema](模块/Schema.md)。

### 默认存储迁入专用源（2026-11-07）

当前已实现[显式离线维护命令](../tools/storage_relocation/README.md)，仅支持同租户、同分类的默认 MySQL `schema_2_db / single` 模型迁入同一显式专用 MySQL 数据源。一次1至16个模型，每模型全部属性映射到一个新主表；模型、属性、索引和实例ID、逻辑类型与约束保持不变，不改变建模方向。拒绝现有草稿、未完成发布、已绑定相关Link、已有目标表接管及过期来源摘要；普通表单/发布仍拒绝随意重绑。

固定清单包含每模型独立操作ID、原当前定义/摘要、候选定义/摘要和数据源ETag；服务启动与普通请求不执行该命令。维护前备份并停止本地Metadata/Data及其他写入方，命令持有两控制库的租户维护锁。Data一次关闭整批gate并排空旧事务，再编译目标表、索引和所有权标记，复制当前租户的稳定实例ID及全部业务列，校验NULL、空串、精确数值、时间和完整正文；不复制平台tenant_id/etag系统列，不修改或删除原表。每表预算10,000行/64MiB，整批128MiB；持久步骤绑定完整排序清单，拒绝以子集恢复或覆盖不一致的目标数据。

目标核验完成后保持prepared；Metadata在单个本地事务更新整批当前定义，新增succeeded发布记录及`definition.storage_relocated` outbox，事件payload为完整的单模型迁移清单项，包含原/新定义及来源摘要。同一操作重入须匹配原证据，不修改历史发布；最后核对Metadata和目标数据，再一次将整批gate恢复ready。跨服务步骤不是分布式原子事务；失败后保留暂停并用同一固定清单恢复，不自动回滚或恢复流量。该实现仅认证本地单实例维护，不覆盖生产多副本隔离、备份恢复或任意类型的模型迁移。

迁移后的旧游标因模型摘要/来源变化失效。显式源实例读写范围仍以[Schema](模块/Schema.md)和[数据源](数据源.md)为准，目前实例写入不开放；迁移不自动取得写入能力。相关未绑定Link在全部对象迁移完成后，通过正常草稿/发布配置同源外键或关联表。

## 4. 请求、任务与缓存

新请求读取当前生效定义；排队任务在首次实际开始执行时解析最新 Action/Function 及依赖并重新校验输入、权限和目标。目标已删除、停用或输入不再合法时明确失败，不自动回退旧定义。

执行开始后，在同一任务记录中保存实际采用的输入输出约束、单位、目标及实现制品摘要等必要内容，运行和重试沿用该任务上下文，不中途切换代码或参数规则。该记录仅服务于本次执行、核对和审计，不可作为旧定义向其他任务开放。权限撤销及租户检查仍然即时执行。无法按原上下文安全重试时停止并核对，不偷偷换成当前实现；详细规则见 [执行与调度](执行与调度.md)。

所有业务读写仍须满足当前数据约束，任务上下文不是绕过 Data 当前校验的通道。与运行任务不兼容的结构或定义变更必须先排空任务，不能一边删除字段，一边承诺旧任务继续使用它。

定义及查询计划缓存按 tenant_id、对象 ID、当前内容摘要、权限和映射等实际条件隔离。每次使用需校验权威的当前状态/摘要；失效事件用于加速，不能仅靠事件或 TTL 容忍生效后继续读旧定义。权威状态不可确认时受影响操作失败或重试；在没有完成这一机制前可先关闭相关缓存。跨服务生效期间使用持久化暂停状态和入口检查阻止旧实例继续接收请求。

名称到 ID 的缓存还须包含解析范围与规范名称键，并在使用时校验当前名称登记及权限。已绑定查询始终检查原 ID 的当前定义，不将“原 ID 不存在”降级成按文本查找同名对象；名称来源仅用于编辑和说明，不能覆盖实际绑定。

历史查询结果及任务结果应保存与实际值匹配的字段描述、单位、必要执行内容及来源，读取历史记录不通过当前 Schema 猜测原含义。不承诺恢复任意过去时间的完整定义。

## 5. 验收

| 编号 | 要求 | 验收方法 |
| --- | --- | --- |
| PUB-01 | 统一维护一份当前定义，平台迁移与模型变更分别记录 | 五类接口及引用无业务 version；仅可读取当前定义及编辑草稿，操作 ID 不可用作旧定义调用 |
| PUB-02 | 预览、依赖检查及迁移成功后才生效 | 草稿不影响业务；过期预览、跨租户及并发依赖变更被拒绝；两个 Schema 模式遵守 DDL 边界 |
| PUB-03 | 迁移并发安全、失败可恢复，旧执行者不能提交 | 两副本争抢、回填中断及部分 DDL 失败可核对；结构不一致期间保持暂停 |
| PUB-04 | 新操作用当前定义，已开始任务保持执行一致性 | 生效后两副本读取相同当前定义；排队任务取最新，运行任务不换代码；破坏性变更排空任务，失效缓存不能继续服务 |

## 6. 待定事项

需明确目标数据库版本、ETag 及依赖并发校验、跨服务暂停/恢复协议、迁移互斥、缓存权威校验成本、任务上下文保留期和备份恢复方式。五类对象的单份当前定义原则已确定，具体工程协议尚待验证；不承诺所有变更在线无停机。
